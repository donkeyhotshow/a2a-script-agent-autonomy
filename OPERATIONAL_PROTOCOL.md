# OPERATIONAL_PROTOCOL - Правила и требования к работе над проектом

Этот документ определяет обязательный протокол взаимодействия и выполнения задач для всех AI-агентов в данном репозитории.

## 1. Основные принципы (Core Principles)

1.  **От простого к сложному (Sequential Progress)**: Запрещено переходить к сложным интеграционным задачам без подтверждения работоспособности базовых компонентов.
2.  **Dev-File First**: Каждое действие должно начинаться с анализа `DEV_STATE.md` и заканчиваться его обновлением.
3.  **Доказательная база (Evidence-Based)**: Отчет о завершении шага должен содержать логи, результаты тестов или выводы команд.
4.  **Строгое соблюдение AGENTS.md**: Все технические правила (Action-Key Shape, Stateless, NodeNext imports) являются законом.

---

## 2. Протокол ведения Dev-файлов (`DEV_STATE.md`)

Файлы `DEV_STATE.md` (в корне и в каждом модуле) — это "внешняя память" проекта.

### Правила работы:
- **Перед задачей**: Проверь актуальность `DEV_STATE.md`. Если он устарел — сначала актуализируй его.
- **Во время задачи**: Если найдены новые инсайты или проблемы — зафиксируй их в секции `Известные проблемы`.
- **После задачи**:
    - Удали выполненные пункты.
    - Обнови дату в заголовке.
    - Добавь следующий логический шаг в `Next Steps`.
- **Чистота**: "Убираем ненужное всегда". Не превращай файл в свалку логов. Только структура, статусы и критические факты.

## 3. Этапы выполнения (Simple to Complex)

Любая работа по "доведению до продакшена" должна следовать этой иерархии:

### Фаза 1: Проверка фундамента (Environment)
- [ ] Проверка портов (`11435`, `11434`, `3000`, `5173`).
- [ ] Проверка доступности Ollama и моделей.
- [ ] Проверка переменных окружения (ENCRYPTION_KEY, AI_HUB_URL).
- **Результат**: Все `curl /health` возвращают `ok`.

### Фаза 2: Валидация компонентов (Liveness & Unit)
- [ ] Запуск unit-тестов модуля (`npm run test`).
- [ ] Проверка линтинга (`npm run lint`).
- **Результат**: 0 ошибок в базовом коде.

### Фаза 3: Интеграционная логика (Simulations)
- [ ] Запуск `npm run sim:lint`.
- [ ] Запуск `npm run sim:validate` для целевых сценариев.
- **Результат**: Логика протокола (Action-Key, Transforms) подтверждена "золотыми" тестами.

### Фаза 4: Сквозной сценарий (E2E)
- [ ] Запуск всей системы через `start-all.bat` / `start-all.sh`.
- [ ] Проверка создания сессии через Client API.
- [ ] Проверка получения ответа от LLM в Web UI.
- **Результат**: Проект работает "в сборе".

### Фаза 5: Production Readiness
- [ ] Проверка логирования и обработки ошибок.
- [ ] Удаление dev-заглушек (`SKIP_AUTH=1` и т.д.).
- [ ] Финальный прогон тестов.

## 4. Правила взаимодействия (Agent Interaction)

- **Confirmation**: Перед началом Фазы N, агент обязан подтвердить, что Фаза N-1 пройдена и стабильна.
- **No Drifting**: Если пользователь просит "сделать продакшен", агент должен ответить: *"Я начинаю с Фазы 1 (Проверка фундамента), согласно OPERATIONAL_PROTOCOL"*.
- **Task Pruning**: Мелкие задачи решаются сразу. Крупные — декомпозируются в `DEV_STATE.md`.
- **Atomic Commits**: Изменения файлов должны быть атомарными и соответствовать текущему шагу.

---

## 5. Обязательные проверки (Checklist)

Агент должен прогонять этот чек-лист перед каждым ответом пользователю:
1. Использую ли я Action-Key Shape в JSON? (см. AGENTS.md)
2. Обновил ли я `DEV_STATE.md`?
3. Мое текущее действие — это "простое" или я пытаюсь перепрыгнуть через этапы?
4. Соответствуют ли мои импорты правилу `.js` (NodeNext)?
