### 📄 Архитектура когнитивной системы управления задачами

#### 1. Уровни обработки данных (Data Layers)

Система работает на принципе «матрешки», где каждый следующий слой уточняет предыдущий:

* **Слой ДНК (Base Knowledge):** Статические JSON-нейроны (бывшие `.l4`), описывающие стандарты Laravel 11.
* **Слой Контекста (Session Delta):** Текущие изменения, специфичные для проекта (кастомные пути, настройки).
* **Слой Графа (Knowledge Graph):** Динамическая карта сущностей (`Entity`) и связей (`Relation`), извлеченных из `new_task` и файлов.

#### 2. Жизненный цикл обработки (The Neural Loop)

| Этап | Компонент | Процесс |
| --- | --- | --- |
| **Восприятие** 👁️ | **Detector** | Разбивает входящий текст на блоки (код, конфиг, интент). |
| **Анализ** 🧠 | **Semantic Plexer** | Активирует нейроны по триггерам. Если связь неизвестна — помечает её как `unknown`. |
| **Планирование** 📝 | **Task Engine** | Превращает активированные нейроны в очередь `tasks` с учетом `depends_on`. |
| **Обучение** 🌱 | **Question Generator** | Генерирует вопросы (8 типов) для заполнения лакун в графе знаний. |

#### 3. Механизм приоритетов и зависимостей

Вместо ручного ввода, сервер вычисляет **Weight** (вес) каждой задачи в массиве `tasks`:

* **Блокирующие связи:** Если задача `B` требует данных из задачи `A`, `A` получает высший приоритет.
* **Семантическая важность:** Задачи по изменению архитектуры (Models) важнее косметических правок (Views).

#### 4. Векторное развитие (Plexer ML)

Будущая миграция предполагает замену Regex-паттернов на **Embeddings** (векторные представления). Это позволит системе понимать смысл (например, связь между `Auth` и `Guard`), даже если эти слова не прописаны в триггерах нейрона.
