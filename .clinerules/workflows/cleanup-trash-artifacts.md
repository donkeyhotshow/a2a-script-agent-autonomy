# Workflow: Уборка мусорных артефактов

## Цель

Очистка проекта от устаревших, неиспользуемых и мусорных файлов для поддержания чистоты кодовой базы.

## Определение мусорных артефактов

### Типы мусора

1. **Дубликаты**
   - Файлы с одинаковым содержимым в разных местах
   - Резервные копии (*.bak, *.old, *.backup)
   - Временные файлы редакторов (*~, .swp, *.swo)

2. **Устаревшие файлы**
   - Неиспользуемые зависимости в package.json
   - Старые версии файлов в archive/
   - Неактуальные документации
   - Deprecated API и компоненты

3. **Сгенерированные файлы**
   - node_modules/ (может быть пересоздан)
   - build/ директории
   - dist/ директории
   - .cache/ папки

4. **Тестовый мусор**
   - Скриншоты из тестов
   - Логи тестов
   - Временные файлы тестирования

5. **Мета-данные**
   - Пустые файлы
   - Файлы с нулевым размером
   - Битые символические ссылки

## Чеклист задач

- [ ] Сканировать проект на наличие дубликатов
- [ ] Определить устаревшие файлы и папки
- [ ] Проверить неиспользуемые зависимости
- [ ] Очистить сгенерированные директории
- [ ] Удалить тестовый мусор
- [ ] Удалить пустые файлы и папки
- [ ] Обновить .gitignore при необходимости
- [ ] Зафиксировать удаления в git

## Процедура очистки

### Шаг 1: Анализ

```bash
# Найти дубликаты
find . -type f -exec md5sum {} \; | sort | uniq -d

# Найти большие файлы
find . -type f -size +10M

# Найти пустые файлы
find . -type f -empty

# Найти временные файлы
find . -name "*.tmp" -o -name "*.log" -o -name "*~"
```

### Шаг 2: Проверка использования

- Проверить импорты в коде
- Проверить ссылки в документации
- Убедиться что файл не используется

### Шаг 3: Удаление

- Использовать `git rm` для отслеживаемых файлов
- Использовать `rm` для неотслеживаемых
- Добавить в .gitignore чтобы предотвратить повторное добавление

### Шаг 4: Верификация

- Запустить тесты
- Проверить сборку
- Убедиться что ничего не сломалось

## Безопасность

- **Никогда не удалять**:
  - .git директорию
  - Активные ветки
  - Текущую рабочую директорию с несохранёнными изменениями
  
- **С осторожностью**:
  - node_modules - можно очистить, но переустановить
  - Базы данных
  - Конфиденциальные данные

## Периодичность

- Легкая очистка: еженедельно
- Глубокая очистка: ежемесячно
- Полная ревизия: при выпуске новых версий
