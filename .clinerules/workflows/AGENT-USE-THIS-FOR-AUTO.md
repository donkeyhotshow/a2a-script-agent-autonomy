# Инструкция для агента по использованию системы документации

## Для кого этот документ?

Этот документ предназначен для агентов, которые будут использовать систему документации в `.clinerules/` для работы с
документацией проекта.

## Что делает эта система?

Система помогает:

- Анализировать существующую документацию
- Обновлять устаревшие документы
- Создавать новую документацию
- Контролировать качество и актуальность

## Как использовать систему?

### 1. Запуск анализа документации

```bash
# Запустить анализ всех документов
node .clinerules/scripts/workflow-engine.js --start --priority medium

# Для срочных задач
node .clinerules/scripts/workflow-engine.js --start --priority high

# Для фоновой обработки
node .clinerules/scripts/workflow-engine.js --start --priority low
```

### 2. Мониторинг процесса

```bash
# Проверить текущий статус
node .clinerules/scripts/workflow-engine.js --status

# Сгенерировать отчет
node .clinerules/scripts/workflow-engine.js --report --format json
```

### 3. Работа с отдельными документами

```bash
# Создать новую документацию
node .clinerules/scripts/cli.js create docs/new-feature.md "Содержимое документа"

# Запустить ревью документа
node .clinerules/scripts/cli.js start 123456

# Завершить ревью
node .clinerules/scripts/cli.js complete 123456 "Проверка завершена"
```

### 4. Что делать если система спрашивает?

Система может задавать вопросы через QTU (Question to User). На них нужно ответить, выбрав один из предложенных
вариантов или введя свой ответ.

Примеры вопросов:

- "Выберите режим обработки: последовательный, пакетный, гибридный"
- "Установите порог качества: 70%, 80%, 90%, 95%"
- "Как поступать при ошибках: остановить, пропустить, повторить"

### 5. Что проверять после завершения?

После завершения работы системы:

1. **Проверьте результаты** в папке `docs/`
2. **Сравните с исходными** документами
3. **Исправьте неточности** если они есть
4. **Подтвердите изменения** если все в порядке

### 6. Что делать при ошибках?

Если система сообщает об ошибках:

1. **Остановите процесс**: `node .clinerules/scripts/workflow-engine.js --stop --reason "error"`
2. **Проверьте логи**: `node .clinerules/scripts/workflow-engine.js --status`
3. **Исправьте проблему** вручную
4. **Запустите заново**: `node .clinerules/scripts/workflow-engine.js --start --priority medium`

### 7. Важные моменты

- **Не создавайте файлы в корне проекта** - используйте `.clinerules/` для временных файлов
- **Проверяйте результаты** - система может делать ошибки
- **Отвечайте на вопросы** - если система спрашивает, нужно ответить
- **Следите за статусом** - проверяйте прогресс каждые 10-15 минут
- **Не прерывайте процесс** без необходимости - это может повредить состояние системы

### 8. Типичные сценарии использования

#### Сценарий 1: Обновление устаревшей документации

1. Запустить анализ: `--start --priority medium`
2. Дождаться завершения discovery фазы
3. Ответить на вопросы системы о приоритетах
4. Контролировать процесс обработки
5. Проверить результаты и внести правки

#### Сценарий 2: Создание новой документации

1. Создать документ: `cli.js create docs/new.md "Content"`
2. Запустить ревью: `cli.js start 123456`
3. Завершить ревью: `cli.js complete 123456 "Done"`
4. Проверить качество документа

#### Сценарий 3: Анализ существующей документации

1. Запустить анализ: `--start --priority low`
2. Получить отчет: `--report --format json`
3. Проанализировать состояние документации
4. Принять решение о дальнейших действиях

## Полезные команды

```bash
# Помощь по командам
node .clinerules/scripts/workflow-engine.js --help

# Проверка состояния системы
node .clinerules/scripts/workflow-engine.js --status

# Генерация подробного отчета
node .clinerules/scripts/workflow-engine.js --report --format markdown

# Остановка системы
node .clinerules/scripts/workflow-engine.js --stop --reason "reason"
```

## Что НЕ нужно делать

- ❌ Не изменяйте файлы в `.clinerules/scripts/` без необходимости
- ❌ Не удаляйте JSON файлы состояния
- ❌ Не прерывайте процесс без веской причины
- ❌ Не игнорируйте вопросы системы
- ❌ Не создавайте документы в корне проекта
