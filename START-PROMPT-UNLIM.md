# IDE-агент и субагент (A2A по API)

## Термин: субагент

**Субагент** здесь — не отдельная нейросеть в другом окне. Это **запущенный стек этого репозитория** (Client API → a2a-server → интеграция с LLM), к которому ходят **только по HTTP**.

- **Главный агент** — ты в **IDE** (Kilo / Cursor agent): план, терминал, правки кода, рассуждение.
- **Субагент** — «чёрный ящик» с точки зрения IDE: ты ему даёшь **сессию + сообщение** через `curl`, получаешь **execute/result/context** (и поллишь async), не кликая веб-UI.

Так понятнее, чем «оркестратор-скрипт»: **оркестрация — в IDE**, **исполнение диалога/задачи — у субагента по API**.

## Назначение промпта

Использовать субагента **в бою**: реальные сценарии (сессия → `/next` → ожидание ответа) и **параллельно** ловить баги — зависания `promiseId`, JSON, **action-key shape**, health **3000 / 11434 / 11435**, странности Gray Room.

Баг → repro (запрос + ответ) → правка **кода или системных промптов** (`a2a-server/prompts/`, `a2a-server/prompts/transforms/`) → снова вызов субагента через API.

## Чего не делать

- Не путать **субагента** с **серверным** оркестратором LLM внутри `a2a-server` (Gray Room и т.д.) — тот внутри стека; **субагент** — весь стек снаружи для IDE.
- Не подменять субагента бесконечными «методологическими» подзадачами и жизнью только в `tasks/`.
