# Plan: Distribute Tests to Their Own Packages

## Overview

The current test suite is centralized in the root `tests/` directory, but since this is a monorepo with multiple packages, and the main code is in `packages/server/src/`, the tests should be moved to `packages/server/tests/` to keep them with their corresponding package.

## Analysis

- All test files in `tests/` import from `src/`, which corresponds to `packages/server/src/`.
- The packages already have empty `tests/` directories, indicating they are prepared for package-specific tests.
- Some packages like `config`, `actions`, etc., already have their own test files directly in their package directories.
- The root `tests/` contains unit, integration, e2e, and other tests that are primarily testing the server package functionality.

## Steps

1. **Move the tests directory**: Move the entire `tests/` directory from the root to `packages/server/tests/`.
2. **Update Vitest configuration**: Modify `vitest.config.ts` to point to the new test location.
   - Change `include: ['tests/**/*.test.ts']` to `include: ['packages/server/tests/**/*.test.ts']`
   - Change `setupFiles: ['tests/setup.ts']` to `setupFiles: ['packages/server/tests/setup.ts']`
   - Update `coverage.include` if needed, but it already points to `src/**/*.ts` which is correct.
3. **Update package.json scripts**:
   - Change `"lint": "eslint \"src/**/*.ts\" \"tests/**/*.ts\""` to `"lint": "eslint \"packages/server/src/**/*.ts\" \"packages/server/tests/**/*.ts\""`
   - Note: The current lint script references `src/**/*.ts` which doesn't exist in root; this may need correction anyway.
4. **Update any hardcoded references**: Search for any other references to `tests/` path in the codebase and update them.
5. **Verify the move**: Run the test suite to ensure all tests pass with the new location.
6. **Run linting**: Ensure linting works with the updated paths.
7. **Commit changes**: If everything works, commit the reorganization.

## Expected Benefits

- Better organization in the monorepo structure.
- Tests are co-located with the code they test (server package).
- Cleaner root directory.
- Easier maintenance and package-specific testing in the future.

## Risks

- Import paths in tests use relative paths like `../../src/`, which should still work since the relative position remains the same (tests/ to src/ in server package).
- If any absolute paths or configurations reference the old location, they may break.
- Coverage configuration may need adjustment if it relies on relative paths.

## Verification

After implementation, run:

- `npm test` to ensure all tests execute.
- `npm run lint` to check for any linting issues.
- `npm run test:coverage` to verify coverage still works.
