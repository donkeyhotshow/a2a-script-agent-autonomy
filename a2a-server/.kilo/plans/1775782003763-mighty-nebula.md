# Plan: Distribute Tests by Packages

## Objective

Reorganize the test structure to distribute tests across their respective packages instead of having them centralized in `packages/server/tests/` or scattered in `src/` directories. This will improve maintainability, modularity, and allow each package to have its own test suite.

## Current State Analysis

- Main tests are in `packages/server/tests/tests/` (unit, integration, e2e, actions, gray-room, etc.)
- Some packages have tests in their `src/` directories (config, actions, gray-room, features)
- Vitest config only runs tests from `packages/server/tests/**/*.test.ts`
- Lint config only lints `packages/server/src/` and `packages/server/tests/`

## Proposed Changes

### 1. Create Tests Directories

Ensure each package has a `tests/` directory:

- `packages/config/tests/`
- `packages/actions/tests/`
- `packages/gray-room/tests/`
- `packages/llm/tests/`
- `packages/core/tests/` (if needed)
- `packages/protocol/tests/` (if needed)
- `packages/transform/tests/` (if needed)
- `packages/utils/tests/` (if needed)
- `packages/memory/tests/` (if needed)
- `packages/p2p/tests/` (if needed)
- `packages/daemon/tests/` (if needed)
- `packages/request/tests/` (if needed)
- `packages/services/tests/` (if needed)
- `packages/agents/tests/` (if needed)

### 2. Move Existing Tests

#### From packages/_/src/\*\*/_.test.ts to packages/\*/tests/

- `packages/config/env-mapper.test.ts` → `packages/config/tests/env-mapper.test.ts`
- `packages/config/loader.test.ts` → `packages/config/tests/loader.test.ts`
- `packages/actions/src/handlers/file-operations/security.test.ts` → `packages/actions/tests/security.test.ts`
- `packages/gray-room/src/manager.test.ts` → `packages/gray-room/tests/manager.test.ts`
- `packages/features/src/gray-room/manager.test.ts` → `packages/features/tests/gray-room-manager.test.ts`
- `packages/features/src/actions/handlers/file-operations/security.test.ts` → `packages/features/tests/actions-security.test.ts`

#### From packages/server/tests/tests/ to respective packages

Move action-related tests to `packages/actions/tests/`:

- `action-processor.test.ts`
- `actions/handlers.test.ts`
- `e2e/action-e2e.test.ts`
- `integration/action-iteration.test.ts`
- `integration/invoke-http-parity.test.ts` (if action-related)

Move gray-room tests to `packages/gray-room/tests/`:

- `gray-room-trigger.test.ts`
- `gray-room-finalize-merge.test.ts`
- `gray-room-slot.test.ts`

Move LLM-related tests to `packages/llm/tests/`:

- `unit/llm-hub-poll.test.ts`
- `unit/llm-model-resolver.test.ts`
- `unit/materialize-result-for-llm.test.ts`

Move transform-related tests to `packages/transform/tests/`:

- `transform-runtime.test.ts`

Move daemon-related tests to `packages/daemon/tests/`:

- Any daemon-specific tests

Move core functionality tests to appropriate packages or keep server-specific ones in `packages/server/tests/`

### 3. Update Vitest Configuration

Modify `vitest.config.ts` to include tests from all packages:

```typescript
include: ["packages/*/tests/**/*.test.ts"],
```

### 4. Update Lint Configuration

Modify package.json scripts to lint all packages:

```json
"lint": "eslint \"packages/*/src/**/*.ts\" \"packages/*/tests/**/*.ts\"",
"lint:fix": "eslint \"packages/*/src/**/*.ts\" \"packages/*/tests/**/*.ts\" --fix",
```

### 5. Update Import Paths

After moving files, update relative import paths in test files to match new locations.

### 6. Update Coverage Configuration

Adjust vitest coverage to include all package sources:

```typescript
coverage: {
  include: ["packages/*/src/**/*.ts"],
  exclude: ["packages/*/src/**/*.d.ts"],
},
```

### 7. Handle Shared/Mock Files

Move shared test utilities and mocks from `packages/server/tests/` to appropriate locations or create a shared test package.

## Implementation Steps

1. Create `tests/` directories in all packages
2. Move test files from `src/` directories to `tests/` directories
3. Move package-specific tests from `server/tests/` to respective package `tests/` directories
4. Update vitest and lint configurations
5. Fix import paths in moved test files
6. Run tests to ensure everything works
7. Update any CI/CD configurations if needed

## Benefits

- Each package can be tested independently
- Better organization and maintainability
- Easier to run tests for specific packages
- Consistent structure across all packages
- Improved modularity

## Potential Challenges

- Import path updates may be extensive
- Some tests may depend on server-specific setup
- Mock files and shared utilities need to be handled
- Integration tests spanning multiple packages need consideration
