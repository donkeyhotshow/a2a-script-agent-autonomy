## 1. Обзор

Внедрение системы A2A Script Agent кардинально меняет подход к решению рутинных задач разработки. Этот документ описывает последствия и изменения, которые происходят при использовании данной системы.

---

## 2. Изменения в рабочих процессах

### 2.1. Импорты и алиасы путей

**До:**
- Ручное создание алиасов в `tsconfig.json` / `vite.config.js` как "костыль" для сломанных импортов
- Отчаянные попытки исправить импорты вручную при рефакторинге
- Создание временных алиасов для быстрого "починить и забыть"

**После:**
- Система автоматически находит и исправляет сломанные импорты через action `fix-vue-imports`
- Алиасы нужны только для семантической организации (например, `@/components`), а не как workaround
- Относительные импорты автоматически корректируются при перемещении файлов

**Пример:**
```typescript
// До: приходилось создавать алиас
// tsconfig.json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./resources/js/*"],  // Создан только чтобы "починить" импорты
      "~/*": ["./resources/*"]       // Ещё один костыль
    }
  }
}

// После: алиасы опциональны, система сама находит правильные пути
import MyComponent from './components/MyComponent.vue'  // Автоматически исправлено
```

### 2.2. Рефакторинг файлововой структуры

**До:**
- Страх перемещать файлы из-за сломанных импортов
- Массовый поиск и замена в IDE (часто с ошибками)
- Временные файлы-заглушки для сохранения работоспособности

**После:**
- Безопасное перемещение файлов — система автоматически обновит все импорты
- Детерминированное поведение без участия AI
- Возможность отката через git (изменения предсказуемы)

### 2.3. Миграция между проектами

**До:**
- Копирование кода с последующим ручным исправлением путей
- Создание временных скриптов для миграции (одноразовых)
- Долгий процесс адаптации под новую структуру

**После:**
- Копирование кода + запуск action для автоматического исправления
- Переиспользование actions между проектами
- Единый подход к миграции

## 3. Устаревшие практики

### 3.1. Что больше не нужно делать вручную

| Практика | Почему устарела | Альтернатива |
|----------|-----------------|--------------|
| Создание алиасов для "починки" импортов | Система автоматически находит правильные пути | Использовать `fix-vue-imports` action |
| Ручной поиск сломанных импортов | Автоматическое обнаружение через AST-анализ | Sub-action `vue-import-detect` |
| Массовая замена в IDE | Часто ломает корректные импорты | Точечное исправление с проверкой существования файлов |
| Создание временных скриптов миграции | Одноразовые скрипты теряются, не переиспользуются | Actions хранятся в репозитории, версонируются |
| Комментарии `// FIXME: import` | Накапливаются и забываются | Немедленное исправление через action |

### 3.2. Алиасы — когда они действительно нужны

Алиасы остаются полезными для:

1. **Семантическая организация** — `@/components`, `@/utils`, `@/features`
2. **Избежание глубоких вложенностей** — вместо `../../../utils/helpers`
3. **Конвенции команды** — единый стиль импортов

Алиасы НЕ нужны для:
- "Починки" сломанных импортов после рефакторинга
- Временных workaround'ов
- Сокрытия проблем со структурой проекта

## 4. Новые возможности

### 4.1. No-AI режим

Система actions работает без AI:
- **Мгновенное выполнение** — нет задержек на API вызовы
- **Офлайн-работа** — не требует интернет-соединения
- **Предсказуемость** — детерминированный результат
- **Бесплатность** — нет затрат на AI API

### 4.2. Итеративный протокол

```
Client                          Server
  │                               │
  │  new_task                     │
  │ ─────────────────────────────>│
  │                               │ Анализ задачи
  │  action_proposal + step 1     │
  │ <─────────────────────────────│
  │                               │
  │  [Выполнение кода на клиенте] │
  │                               │
  │  continue + result            │
  │ ─────────────────────────────>│
  │                               │ Следующий шаг
  │  step 2                       │
  │ <─────────────────────────────│
  │                               │
  │  ... (повторить для всех шагов)
  │                               │
  │  completed                    │
  │ <─────────────────────────────│
```

### 4.3. Расширяемость

Создание нового action:
1. Создать `.md` файл в `a2a-server/src/actions/definitions/`
2. Описать sub-actions с TypeScript кодом
3. Система автоматически подхватит новый action

## 5. Симуляции

### 5.1. Исправление сломанных импортов

**Сценарий:** После рефакторинга переместили файл `UserProfile.vue` из `./components/users/` в `./features/profile/components/`

```
Итерация 1: Обнаружение
┌─────────────────────────────────────────────────────────────────────┐
│ Пользователь: "Переместили UserProfile.vue, нужно починить импорты" │
└─────────────────────────────────────────────────────────────────────┘
                                ↓
┌─────────────────────────────────────────────────────────────────────┐
│ Клиент → Сервер: new_task { task: "Исправить сломанные импорты" } │
└─────────────────────────────────────────────────────────────────────┘
                                ↓
┌─────────────────────────────────────────────────────────────────────┐
│ Сервер: Поиск подходящего action → find "fix-vue-imports"          │
│ matchScore: 0.95                                                   │
└─────────────────────────────────────────────────────────────────────┘
                                ↓
┌─────────────────────────────────────────────────────────────────────┐
│ Сервер → Клиент: action_proposal + step "vue-import-detect"       │
└─────────────────────────────────────────────────────────────────────┘

---

**Итерация 1 (продолжение): Выполнение на клиенте**

Клиент выполняет SubAction `vue-import-detect`:

```typescript
// vue-import-detect выполняется на клиенте
const broken_imports = [
  { file: "./pages/UserEdit.vue", line: 3, specifier: "../components/users/UserProfile" },
  { file: "./api/UserService.ts", line: 8, specifier: "../../components/users/UserProfile" },
  { file: "./composables/useUser.ts", line: 2, specifier: "@/components/users/UserProfile" }
]
```

---

**Итерация 2: Разрешение путей**

```
Клиент → Сервер: continue { broken_imports: [...] }
```
                                ↓
```
Сервер: Переход к step "vue-import-resolve"
```
                                ↓
```
Сервер → Клиент: step "vue-import-resolve"
```

---

**Итерация 2 (продолжение): Выполнение на клиенте**

Клиент разрешает правильные пути:

```typescript
// vue-import-resolve выполняется на клиенте
const patches = [
  { file: "./pages/UserEdit.vue", line: 3, from: "../components/users/UserProfile", to: "../features/profile/components/UserProfile" },
  { file: "./api/UserService.ts", line: 8, from: "../../components/users/UserProfile", to: "../../features/profile/components/UserProfile" },
  { file: "./composables/useUser.ts", line: 2, from: "@/components/users/UserProfile", to: "@/features/profile/components/UserProfile" }
]
```

---

**Итерация 3: Применение исправлений**

```
Клиент → Сервер: continue { patches: [...] }
```
                                ↓
```
Сервер: Переход к step "vue-import-apply"
```
                                ↓
```
Сервер → Клиент: step "vue-import-apply"
```

---

**Итерация 3 (продолжение): Выполнение на клиенте**

Клиент применяет патчи:

```typescript
// vue-import-apply выполняется на клиенте
const fixed_files = [
  "./pages/UserEdit.vue",
  "./api/UserService.ts",
  "./composables/useUser.ts"
]
```

---

**Итерация 4: Завершение**

```
Клиент → Сервер: continue { fixed_files: [...] }
```
                                ↓
```
Сервер: Переход к step "vue-import-cleanup" (опционально)
```
                                ↓
```
Сервер → Клиент: completed
```

---

**Результат:**
- Все импорты автоматически исправлены
- Пользователь может проверить изменения через `git diff`
- Алиасы больше не нужны как workaround

### 5.2. Рефакторинг структуры проекта

**Сценарий:** Переименование директории `components/utils` → `components/helpers`

Система: Разрешает ./components/utils/* → ./components/helpers/*

**Результат:**
- 47 файлов автоматически обновлено
- Ни один корректный импорт не сломан
- Время выполнения: < 1 секунды

## 6. Рекомендации по миграции

### 6.1. Очистка существующих алиасов

1. Запустить `fix-vue-imports` action
2. Проверить исправленные импорты
3. Удалить "костыльные" алиасы из конфигурации
4. Оставить только семантические алиасы (`@/components`, `@/utils`)

### 6.2. Интеграция в CI/CD

```yaml
# .github/workflows/fix-imports.yml
name: Fix Broken Imports
on: [push]
jobs:
  fix-imports:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Run fix-vue-imports
        run: |
          npm run a2a:action -- --action fix-vue-imports --rootDir .
      - name: Commit fixes
        run: |
          git config --global user.name "A2A Bot"
          git config --global user.email "bot@a2a.dev"
          git add -A
          git diff --quiet && git diff --staged --quiet || git commit -m "fix: auto-fix broken imports"
          git push
```

### 6.3. Командные конвенции

1. **Не создавать алиасы для workaround** — использовать actions
2. **Запускать action после рефакторинга** — привычка проверять импорты
3. **Хранить actions в репозитории** — версионирование и переиспользование
4. **Документировать actions** — описывать в README проекта используемые actions

## Заключение

Система A2A Script Agent устраняет необходимость в "костыльных" решениях для работы с импортами. Алиасы остаются полезным инструментом для семантической организации кода, но перестают быть способом "починки" сломанных импортов.

Ключевые преимущества:
- Автоматическое исправление импортов без AI
- Детерминированное и предсказуемое поведение
- Переиспользование actions между проектами
- Интеграция в CI/CD для автоматической поддержки кодовой базы
