# Вариант 4: Генерация кода

## Описание варианта

Система самостоятельно генерирует код на основе задачи пользователя. Это наиболее амбициозный вариант, требующий интеграции с LLM на сервере и механизмов безопасного применения изменений.

## Роль клиента

Клиентская часть выполняет:

1. **Формирование задачи** — описание того, что нужно сделать
2. **Предоставление контекста** — указание файлов для анализа
3. **Получение изменений** — diff/patch сгенерированного кода
4. **Применение изменений** — запись в файлы (с подтверждением)
5. **Откат** — возможность отменить применённые изменения

### Пример workflow клиента

```
Пользователь: "Добавить метод для отправки email уведомлений"
    ↓
Клиент: Сбор контекста (User model, NotificationService)
    ↓
Клиент: Отправка задачи на сервер
    ↓
Сервер: Генерация кода через LLM
    ↓
Сервер: Валидация синтаксиса
    ↓
Клиент: Получение diff для просмотра
    ↓
Пользователь: Подтверждение применения
    ↓
Клиент: Применение изменений
```

## Роль сервера

Сервер выполняет генерацию:

1. **Понимание задачи** — анализ запроса пользователя
2. **Сбор контекста** — поиск релевантного кода через RAG
3. **Генерация** — вызов LLM API для создания кода
4. **Валидация** — проверка синтаксиса и стиля
5. **Формирование diff** — структурированные изменения

### Архитектура генерации

```
┌─────────────────────────────────────────────────────────┐
│                    Запрос пользователя                   │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                   Анализ задачи (LLM)                    │
│  - Извлечение требований                                 │
│  - Определение затрагиваемых файлов                      │
│  - Выбор стратегии генерации                             │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                   Сбор контекста (RAG)                   │
│  - Семантический поиск релевантного кода                 │
│  - Извлечение связанных сущностей из графа               │
│  - Формирование промпта с контекстом                     │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                   Генерация кода (LLM)                   │
│  - Вызов API (Claude/GPT/локальная модель)               │
│  - Streaming ответа                                      │
│  - Парсинг сгенерированного кода                         │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                   Валидация и применение                 │
│  - Синтаксическая проверка                               │
│  - Линтинг                                               │
│  - Формирование diff                                     │
│  - Применение изменений                                   │
└─────────────────────────────────────────────────────────┘
```

## Преимущества

| Преимущество | Описание |
|--------------|----------|
| **Автоматизация** | Минимум ручной работы |
| **Скорость** | Быстрое создание boilerplate |
| **Консистентность** | Код следует стилю проекта |
| **Обучение** | Примеры правильного кода |
| **Итеративность** | Можно уточнять результат |

## Недостатки

| Недостаток | Описание |
|------------|----------|
| **Стоимость** | Расходы на LLM API |
| **Качество** | Код может требовать доработки |
| **Безопасность** | Код отправляется на внешние API |
| **Сложность** | Требует тщательной настройки |
| **Ответственность** | Кто отвечает за баги в сгенерированном коде? |

| Тип | Описание | Сложность |
|-----|----------|-----------|
| **Boilerplate** | CRUD, модели, контроллеры | Низкая |
| **Методы** | Добавление методов в класс | Средняя |
| **Рефакторинг** | Переименование, извлечение | Средняя |

## Пример использования

### API запрос

```bash

{
  "project_path": "/path/to/project",
  "action": "generate",
  "task": {
    "description": "Add method to send email notifications to user",
    "target_file": "app/Models/User.php",
```

## Безопасность

### Меры предосторожности

1. **Превью изменений** — всегда показывать diff перед применением
2. **Резервные копии** — сохранять оригиналы файлов
3. **Git интеграция** — автоматический коммит с описанием
4. **Откат** — возможность отменить последнее изменение
5. **Валидация** — проверка синтаксиса перед записью

### Ограничения

```typescript
const GENERATION_LIMITS = {
  maxFileSize: 100 * 1024,      // 100KB max file
  maxChanges: 10,               // max files per request
  excludedPatterns: [
    '.env*',
    '*secret*',
    '*key*',
    'config/database.php',
  ],
  requireConfirmation: true,    // always require user approval
};
```

## Метрики успеха

1. **Точность генерации** — процент работающего кода
2. **Принятие изменений** — процент применённых изменений
3. **Время генерации** — скорость получения результата
4. **Стоимость** — расходы на LLM API
5. **Удовлетворённость** — оценка качества пользователями
