# ADR-003: State Machine (PhaseMachine)

## Дата
2026-02-25

## Авторы
- Команда разработки

## Статус
Предложено

## Контекст

Система A2A Script Agent использует конечный автомат (Finite State Machine) для управления потоком обработки запросов. PhaseMachine определяет последовательность фаз обработки задачи и правила переходов между ними.

### Требования к State Machine

- **Детерминированность:** Переходы между фазами должны быть предсказуемыми
- **Обработка ошибок:** Каждая фаза должна обрабатывать возможные ошибки
- **Логирование:** Все переходы должны логироваться
- **Восстановление:** Возможность восстановления после сбоев

## Решение

### Диаграмма состояний

```
                    +---------+
                    |  idle   |
                    +----+----+
                         |
                         | request received
                         v
              +------------------+
              |    discovery     |
              +--------+---------+
                       |
                       | data collected
                       v
              +------------------+
              |   recognition    |
              +--------+---------+
                       |
                       | entities identified
                       v
              +------------------+
              |    analysis       |
              +--------+---------+
                       |
                       | analysis complete
                       v
              +------------------+
              |     action        |
              +--------+---------+
                       |
                       | action executed
                       v
              +------------------+
              |    validation     |
              +--------+---------+
                       |
                       | validation passed
                       v
              +------------------+
              |    completed      |
              +------------------+
                       |
                       | reset
                       v
                    (idle)
```

### Описание фаз

| Фаза | Описание | Входные данные | Выходные данные |
|------|---------|----------------|-----------------|
| `idle` | Ожидание нового запроса | - | - |
| `discovery` | Сбор данных о задаче | request, context | discovered_data |
| `recognition` | Распознавание сущностей | discovered_data | entities |
| `analysis` | Анализ данных | entities | analysis_result |
| `action` | Выполнение действия | analysis_result | action_result |
| `validation` | Проверка результата | action_result | validation_result |
| `completed` | Задача выполнена | validation_result | final_result |

### Переходы между фазами

```typescript
type Phase = 
  | 'idle' 
  | 'discovery' 
  | 'recognition' 
  | 'analysis' 
  | 'action' 
  | 'validation' 
  | 'completed';

interface PhaseTransition {
  from: Phase;
  to: Phase;
  condition: () => boolean;
  onTransition?: () => void;
}

const transitions: PhaseTransition[] = [
  { from: 'idle', to: 'discovery', condition: () => hasRequest() },
  { from: 'discovery', to: 'recognition', condition: () => dataCollected() },
  { from: 'recognition', to: 'analysis', condition: () => entitiesIdentified() },
  { from: 'analysis', to: 'action', condition: () => analysisComplete() },
  { from: 'action', to: 'validation', condition: () => actionExecuted() },
  { from: 'validation', to: 'completed', condition: () => validationPassed() },
  { from: 'validation', to: 'action', condition: () => needsRetry() },
  { from: 'completed', to: 'idle', condition: () => resetRequested() },
];
```

### Обработка ошибок

#### Типы ошибок по фазам

| Фаза | Типичные ошибки | Стратегия восстановления |
|------|----------------|------------------------|
| `discovery` | Network error, timeout | Retry с exponential backoff |
| `recognition` | Invalid input, parsing error | Return to discovery |
| `analysis` | AI timeout, invalid result | Retry analysis |
| `action` | Execution failed | Retry или fallback |
| `validation` | Validation failed | Return to action |

#### Коды состояний ошибок

```typescript
enum PhaseErrorCode {
  DISCOVERY_FAILED = 1000,
  RECOGNITION_FAILED = 2000,
  ANALYSIS_FAILED = 3000,
  ACTION_FAILED = 4000,
  VALIDATION_FAILED = 5000,
  TIMEOUT = 6000,
}

interface PhaseError {
  code: PhaseErrorCode;
  phase: Phase;
  message: string;
  retryable: boolean;
  maxRetries: number;
}
```

#### Обработка ошибок в каждой фазе

```typescript
class PhaseMachine {
  private currentPhase: Phase = 'idle';
  private errorHistory: PhaseError[] = [];
  private maxRetriesPerPhase = 3;

  async transition(): Promise<void> {
    try {
      await this.executeCurrentPhase();
      this.moveToNextPhase();
    } catch (error) {
      await this.handleError(error);
    }
  }

  private async handleError(error: Error): Promise<void> {
    const phaseError = this.mapToPhaseError(error);
    this.errorHistory.push(phaseError);

    if (phaseError.retryable && this.canRetry(phaseError)) {
      await this.retryPhase();
    } else if (this.canFallback(phaseError)) {
      await this.fallbackToPreviousPhase();
    } else {
      this.moveToErrorState(phaseError);
    }
  }
}
```

### State Machine Implementation

```typescript
interface PhaseMachineState {
  phase: Phase;
  context: RequestContext;
  metadata: {
    startedAt: Date;
    lastTransitionAt: Date;
    retryCount: number;
    errors: PhaseError[];
  };
}

class PhaseMachine {
  private state: PhaseMachineState;
  
  constructor(context: RequestContext) {
    this.state = {
      phase: 'idle',
      context,
      metadata: {
        startedAt: new Date(),
        lastTransitionAt: new Date(),
        retryCount: 0,
        errors: [],
      },
    };
  }

  async process(): Promise<RequestContext> {
    while (!this.isTerminalState()) {
      await this.transition();
    }
    return this.state.context;
  }

  private isTerminalState(): boolean {
    return this.state.phase === 'completed' || 
           this.state.phase === 'error';
  }
}
```

## Последствия

### Положительные

- **Понятный поток:** Чёткая последовательность обработки
- **Отладка:** Легко отследить текущее состояние
- **Тестирование:** Каждую фазу можно тестировать изолированно
- **Расширяемость:** Легко добавить новые фазы

### Отрицательные

- **Сложность:** Дополнительный слой абстракции
- **Оверхед:** Накладные расходы на переходы между фазами

### Риски

- Циклические переходы (необходимо ограничить количество retry)
- Deadlock состояния (необходимо timeout для каждой фазы)
