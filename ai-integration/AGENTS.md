# AGENTS instructions for ai-integration
Поддерживайте прозрачный, итеративный режим изучения и доработки проекта, организуя работу через следующие секции.

## Текущее состояние
- Записывайте краткий контекст задачи, недавние действия и статус (например, блокируется или в процессе).
- Указывайте, что изучено, какие гипотезы подтвердились, есть ли ошибки/запросы на уточнение.
- Поддерживайте фактическую дату (формат ДД.ММ.ГГГГ) рядом с каждым обновлением.

## Scratchpad / план на следующие шаги
- Фиксируйте идеи, новые шаги, ссылки на задачи и промежуточные выводы.
- Разбивайте крупные задачи на маленькие подзадачи и отмечайте, какие пункты можно сразу выполнить.
- Обязательно указывайте, какие действия должны быть следующими, чтобы не терять нить итерации.

## Memories
- Храните здесь устойчивые наблюдения, архитектурные решения, открытые вопросы и источники знаний (например, важные README, конфиги, цели).
- Обновляйте только то, что действительно будет полезно в следующих итерациях, чтобы не перегружать память.

## TODO.md / организационные указания
- Если появилось новое задание, оформляйте его в TODO.md (или аналогичной задаче) по шаблону: краткое описание — ожидаемый результат — владелец — срок.
- Привязывайте TODO к контексту (файл/модуль, окружение) и отмечайте приоритетные зависимости.
- Уточняйте, кто отвечает за следующий шаг (в человеко-терминах: “я”, “вы”, “team”) и каков критерий завершения.

## Инструкции итеративности работ
- Цель каждой итерации — продвинуться минимум на один рабочий шаг (исследование, изменение, проверка) и зафиксировать результат в Scratchpad.
- По завершении шага обновляйте DEV_STATE.md: удалите уже выполненный пункт, добавьте новый в конец, отметьте дату и вывод.
- Если встретили неопределённость, фиксируйте её в текущем состоянии с пометкой «нужна ясность» и обращайтесь за уточнением до продолжения.
- Всегда проверяйте зависимости (конфиги, env, сторонние сервисы) до выполнения изменений, чтобы избежать незапланированных блоков.

## Short State Governance (mandatory)
- `DEV_STATE.md` is the single source of truth for current status.
- Every task must have explicit status (`TODO` / `IN_PROGRESS` / `DONE`).
- After each meaningful action: update state, remove stale items, add next executable step.
- If uncertain, log it as `risk` or `question` (no silent assumptions).
- Priority order: finish in-progress work -> stabilize -> production readiness.
