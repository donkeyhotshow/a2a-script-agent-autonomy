# Grey-Room Sequence Control and Planning

В серой комнате надо вести **предсказуемый pipeline задач** и контролировать, какие шаги впереди. Этот файл описывает принципы, которые должны применяться при каждом новом запросе или пачке работ. Промты и планы — это описание подхода и шаблонный каркас, а не источник фактического состояния; за правду отвечает очередь, чеклисты и сигнал `step_complete`.

## 1. Планы/задачи по шагам
1. Каждый новый входной запрос попадает в очередь `sequence`, которая содержит текущий шаг и минимум 3 следующими предположениями о действиях (например: «оценка входа», «поиск ошибки», «предложение правки», «применение», «валидация»). Можно менять порядок шагов в любой момент, но всегда держать длину очереди не менее 4.
2. При добавлении задачи фиксируем: цель (что нужно сделать), ожидаемый результат и критерий «шаг выполнен». Эти записи фигурируют в чек-листе или в документации по управляющему сценарию.
3. Если пачка убывает (меньше запланированных шагов), автоматически пересчитываем последнюю фазу — добавляем прогноз финального шага, куда должен прийти ИИ, чтобы задача считалась закрытой.

- После выполнения шага ИИ возвращает контрольное сообщение `step_complete` с идентификатором шага и краткой сводкой результатов.
- Это сообщение переводит серую комнату в режим следующего шага (или завершения, если очередь закончена).
- Если `step_complete` пропущен, система удерживает текущий шаг и может запросить уточнение.

- Когда количество активных задач становится меньше, чем число будущих шагов, включаем визуальный индикатор (или лог) «предсказание последнего шага». Он содержит: что осталось сделать, зависимости, возможные блокеры.
- Показатель «последний шаг» обновляется каждый раз, когда шаг переходит в статус `step_complete`.
- При необходимости добавляем новых участников/промтов в очередь, чтобы заполнить look-ahead до трех будущих шагов.

## 4. Обработка запросов на изменение pipeline
- Любой запрос от оператора, который меняет порядок шагов, документируется как новая композиция (напр., `sequence/step-combo.md`). Новая композиция сохраняется и становится частью `sequence` очереди.
- Серую комнату нельзя останавливать до получения хотя бы краткого подтверждения, что текущее `sequence` обновлён.

## 5. Ссылки
- Использовать `system/core.txt` как описание «ядра» обработки JSON-мутатора.
- Структура: `system/sequence.txt` хранит фактические шаги, `mutation/step_prompts.txt` содержит промты.
- `system-sequence-guidance.md` и `system-collection/version-6/README.md` — вспомогательные справочники для настройки многосоставных цепочек.
