# Plan: Distribute Tests to Their Own Packages

## Goal
Reorganize the test files currently located in the root `tests/` directory by moving them into the appropriate package's `tests/` subdirectory. This will improve code organization and make it easier to run package-specific tests.

## Analysis
- Current structure: Most unit tests are in `tests/unit/`, integration tests in `tests/integration/`, e2e tests in `tests/e2e/`, human-review tests in `tests/human-review/`
- Target packages: shared, web, vite-plugin, sdk, and possibly others
- Some packages already have tests/ directories, others need them created

## Implementation Steps

### 1. Create missing `tests/` directories
For packages that don't have tests/ directory:
- `packages/core/tests/`
- `packages/execution/tests/`
- `packages/protocol/tests/`
- `packages/storage/tests/`
- `packages/types/tests/`

### 2. Move test files to appropriate packages
Use `mv` commands to move each test file from root `tests/` to the corresponding package's `tests/` directory.

### 3. Update import paths in moved test files
After moving, update the relative import paths in the test files to reflect their new location.

### 4. Consolidate SDK tests
Move the scattered test files in `packages/sdk/src/` subdirectories into `packages/sdk/tests/`.

### 5. Update vitest configurations
Ensure that `vitest.config.ts` files in each package are configured to run the tests in their respective `tests/` directories.

### 6. Update root test scripts
Modify the root `vitest.config.ts` and any npm scripts to exclude the moved tests and run package-specific tests instead.

### 7. Verify and run tests
After moving, run the tests in each package to ensure they still pass with updated paths.

## Risks and Considerations
- Import path updates must be accurate to avoid breaking tests
- Some tests may import from multiple packages, requiring careful handling
- Integration tests that span packages should remain in root
- Ensure vitest configurations are updated to discover tests in new locations
- Check for any hardcoded paths in test files that need updating

## Validation
- Run `npm test` or equivalent in each package after changes
- Ensure all tests pass
- Verify that test coverage reports are still generated correctly
- Check that CI/CD pipelines are updated if necessary
