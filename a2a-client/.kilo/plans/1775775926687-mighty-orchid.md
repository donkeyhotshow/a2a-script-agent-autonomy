# Plan: Normalize File Tree Structure

## Overview
Standardize the monorepo file structure to improve consistency, maintainability, and developer experience. This involves normalizing package structures, consolidating documentation, centralizing test management, and organizing shared resources.

## Current Issues Identified

### 1. Package Structure Inconsistencies
- **Mixed source directories**: Some packages use `src/` only, others have both `src/` and `js/` directories
- **Inconsistent documentation**: Docs scattered between package-level and root-level directories
- **Test location inconsistency**: Tests exist both in root `tests/` and package-specific `tests/` directories
- **Build artifacts**: Some packages contain `node_modules/` which should be ignored

### 2. Storage and Session Data
- **Scattered session data**: Session directories exist in multiple locations (`packages/storage/sessions/`, `storage/sessions/`)
- **Mixed storage patterns**: Some storage is package-specific, some is global

### 3. Documentation Organization
- **Fragmented docs**: Documentation split between root `docs/` and individual package `docs/`
- **Inconsistent naming**: Some docs use README.md, others use specific names

## Normalization Strategy

### 1. Standardize Package Structure
Establish a consistent structure for all packages:
```
packages/[package-name]/
├── src/                    # Source code (main directory)
├── tests/                  # Package-specific tests
├── docs/                   # Package documentation
├── scripts/                # Package-specific scripts
├── package.json            # Package configuration
└── [other config files]    # tsconfig.json, etc.
```

### 2. Consolidate Source Code
- **Migrate mixed structures**: Move content from `js/` directories into `src/` where applicable
- **Standardize entry points**: Ensure all packages use consistent main entry patterns
- **Clean up duplicates**: Remove redundant directories after migration

### 3. Centralize Test Management
- **Root-level tests**: Keep integration and e2e tests at root level
- **Package tests**: Ensure each package has its own `tests/` directory for unit tests
- **Standardize test configs**: Use consistent vitest/jest configurations

### 4. Normalize Storage Structure
- **Central storage**: Consolidate all session/storage data under `storage/` at root
- **Clean up scattered data**: Move and merge session directories from `packages/storage/`
- **Define storage conventions**: Establish clear patterns for different types of storage

### 5. Organize Documentation
- **Root docs**: Keep architectural and cross-package documentation at root
- **Package docs**: Maintain package-specific documentation in `packages/[name]/docs/`
- **Standardize formats**: Use consistent naming (README.md, API.md, etc.)

### 6. Clean Up Build Artifacts
- **Remove node_modules**: Delete package-level node_modules directories
- **Clean dist directories**: Remove build artifacts from source control
- **Update .gitignore**: Ensure consistent ignore patterns across packages

## Implementation Plan

### Phase 1: Analysis and Planning
1. Document current structure of all packages
2. Identify all inconsistencies and duplicates
3. Create migration mapping for each affected file/directory

### Phase 2: Source Code Normalization
1. Migrate `js/` directories to `src/` where appropriate
2. Standardize package.json entry points and exports
3. Update import paths across the codebase

### Phase 3: Test Structure Normalization
1. Move package-specific tests to `tests/` directories
2. Ensure consistent test configuration
3. Update test scripts and CI configurations

### Phase 4: Storage Consolidation
1. Move all session data to centralized `storage/` directory
2. Update storage-related imports and configurations
3. Clean up old storage locations

### Phase 5: Documentation Organization
1. Review and reorganize documentation structure
2. Update README files and documentation references
3. Ensure consistent documentation patterns

### Phase 6: Cleanup and Validation
1. Remove build artifacts and temporary files
2. Update .gitignore patterns
3. Run comprehensive tests to ensure nothing broke
4. Update CI/CD configurations if needed

## Expected Benefits

- **Improved Developer Experience**: Consistent structure makes navigation easier
- **Better Maintainability**: Standardized patterns reduce cognitive load
- **Simplified CI/CD**: Consistent structure enables standardized build/test processes
- **Cleaner Repository**: Reduced duplication and clearer organization
- **Easier Onboarding**: New developers can quickly understand the codebase structure

## Risks and Mitigations

- **Breaking Changes**: Comprehensive testing required after each phase
- **Import Path Updates**: Automated refactoring tools should be used for large-scale changes
- **Documentation Updates**: Ensure all documentation references are updated
- **Build Process Changes**: Verify all build scripts work after restructuring
