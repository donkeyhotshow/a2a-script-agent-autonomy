# File Tree Normalization Plan

## Objective
Normalize the directory structure across all packages in the monorepo to ensure consistency, maintainability, and adherence to standard practices.

## Current Inconsistencies Identified
- Some packages (e.g., `core`, `history`) lack `package.json` files, preventing them from being proper workspace packages.
- Source files are placed directly in package root for some packages (`core`) instead of in `src/` directories.
- Test directories vary: some use `tests/`, others use `__tests__/`, and some have tests inside `src/`.
- Not all packages have consistent metadata files (`README.md`, `tsconfig.json`).

## Proposed Normalized Structure
Each package should have the following structure:
```
packages/{package-name}/
├── package.json          # Workspace package definition
├── src/                  # Source code directory
│   ├── index.ts/js       # Main entry point
│   └── ...               # Other source files
├── tests/                # Test files (if applicable)
├── docs/                 # Documentation (if applicable)
├── README.md             # Package documentation
└── tsconfig.json         # TypeScript configuration (if TypeScript is used)
```

## Action Items

### 1. Create Missing `package.json` Files
Create `package.json` for packages that don't have them:
- `packages/core/package.json`
- `packages/history/package.json`

Include appropriate `name`, `version`, `type`, `exports`, etc., following patterns from existing packages.

### 2. Reorganize Source Files
Move source files to `src/` directories:
- Move `packages/core/*.js` and `packages/core/*.mjs` to `packages/core/src/`
- Ensure all packages have source files in `src/`

### 3. Standardize Test Directories
- Move `packages/history/src/__tests__/` to `packages/history/tests/`
- Remove empty `tests/` directories from packages that don't have tests
- Ensure test files follow consistent naming and location

### 4. Add Missing Metadata Files
- Ensure all packages have `README.md`
- Add `tsconfig.json` to packages that use TypeScript but lack it
- Add `docs/` directories where appropriate

### 5. Update Import Paths
After reorganization, update any relative imports that reference the old file locations.

### 6. Verify Workspace Configuration
Ensure the root `package.json` workspaces include all packages correctly.

## Implementation Order
1. Create missing `package.json` files
2. Reorganize source files into `src/` directories
3. Standardize test directories
4. Add missing metadata files
5. Update import paths and test configurations
6. Run tests and linting to verify changes

## Risks and Considerations
- Updating import paths may break existing functionality; thorough testing required
- Some packages may be imported relatively; ensure workspace dependencies are updated
- Preserve existing functionality and exports
