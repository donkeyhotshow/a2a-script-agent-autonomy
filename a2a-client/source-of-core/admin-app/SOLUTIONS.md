## 💡 Принятые Решения и Типовые Проблемы - Admin App

### Описание:
Данный документ служит для документирования ключевых архитектурных и технических решений, принятых в проекте `Admin App`, а также для сбора и описания типовых проблем и их решений. Цель — предоставить централизованную базу знаний для разработчиков, ускорить онбординг и обеспечить консистентность в подходах.

### Формат записей для решений:
Каждая запись о решении должна включать:
- **Дата:** Дата принятия решения (YYYY-MM-DD).
- **Проблема/Задача:** Описание проблемы или задачи, которую решали.
- **Предложенные варианты:** Краткое описание рассмотренных альтернативных решений.
- **Принятое решение:** Детальное описание выбранного решения и обоснование выбора.
- **Последствия/Риски:** Потенциальные последствия или риски, связанные с принятым решением.

### Примеры решений:
#### Решение: Выбор фреймворка для UI
- **Дата:** 2024-01-10
- **Проблема/Задача:** Выбор фреймворка для клиентской части `Admin App`.
- **Предложенные варианты:** Vue 3 (использовался в других проектах), React (индустриальный стандарт), Svelte (легковесный).
- **Принятое решение:** React с Next.js для SSR и экосистемой Shadcn/UI/Tailwind CSS, что обеспечивает современную и масштабируемую архитектуру.
- **Последствия/Риски:** Требуется обучение команды React, больший размер бандла по сравнению с Svelte.

### Формат записей для типовых проблем и решений:
Каждая запись о проблеме должна включать:
- **Дата обнаружения/решения:** Дата, когда проблема была обнаружена или решена.
- **Проблема:** Краткое описание проблемы, симптомы.
- **Причина:** Коренная причина проблемы (root cause).
- **Решение:** Подробное описание шагов, необходимых для решения проблемы.
- **Предотвращение:** Меры, которые можно предпринять для предотвращения повторения проблемы.

### Примеры типовых проблем:
#### Проблема: Отсутствие SSH-пароля для развертывания
- **Дата:** 2024-03-15
- **Проблема:** Невозможность развернуть приложение на удаленном сервере из-за отсутствия или некорректности SSH-пароля/ключа.
- **Причина:** Отсутствие стандартизированной процедуры проверки учетных данных перед развертыванием.
- **Решение:** Внедрение атомарного действия `Валидация Учетных Данных для Развертывания` (`servers/templates/work/procedures/validate-deployment-credentials.md`).
- **Предотвращение:** Обязательное выполнение процедуры валидации перед любой операцией развертывания.
