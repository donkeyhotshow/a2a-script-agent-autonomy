# Input.vue (Intermediate Input Wrapper)

**Source:** `resources/common/js/Elements/Primevue/VModel/Input.vue`

**Wrapper Chain:** `@RenderJson.md` -> `@Presets.md` -> `@VModel.md` -> `Input.vue` -> (e.g., `InputText.vue`,
`Textarea.vue`)

## Purpose

`Input.vue` acts as an intermediate wrapper component, positioned between the main `@VModel.md` wrapper and specific
input components like `@InputText.md`, `@Textarea.md`, `@Password.md`, etc. Its primary responsibilities are:

* **Label Rendering:** It renders the `<label>` element associated with the input field, using the `inputId` passed down
  from `VModel.vue` and the label text from the component's configuration (`component.props.label`).
* **Dynamic Input Component Rendering:** It dynamically loads and renders the final, specific input component (e.g.,
  `InputText`, `Textarea`) based on the `component.type` specified in the JSON configuration.
* **Attribute Forwarding:** It passes down the necessary `id` attribute and all other attributes and `v-model`
  handlers (received via `$attrs` from `VModel.vue`) to the final input component.

## Rendering Flow & Data Binding

1. **`@VModel.md` Calls `Input.vue`:** When `@VModel.md` determines that the component type requires this intermediate
   wrapper (likely based on `component-map.json` or internal logic), it renders `Input.vue`.
2. **Props Received by `Input.vue`:**
    * `component`: The full JSON configuration object for the component.
    * `inputId`: A unique ID generated by `@VModel.md` (usually based on `props.vAddress`).
    * `$attrs`: Contains the `v-model` handlers managed by `@VModel.md` and any other attributes from `component.props`
      intended for the final PrimeVue component (like `placeholder`, `rows`, `disabled`, etc.).
3. **Label Rendering:** `Input.vue` renders a `<label :for="inputId">` using the text from `component.props.label`.
4. **Dynamic Component Rendering:** It uses `<component :is="component.type" ...>` to render the specific input
   component (e.g., `InputText`, `Textarea`).
5. **Attribute Passing:** It passes the `inputId` as the `id` prop and forwards all received `$attrs` (including
   `v-model` and other props) to the final rendered component (e.g., `<InputText :id="inputId" v-bind="$attrs" />`).

## JSON Configuration Interaction

`Input.vue` itself doesn't directly consume many unique properties from the JSON. It relies on properties processed or
passed down by `@VModel.md`:

* `component.type`: Used to determine which final input component to render (e.g., `"InputText"`, `"Textarea"`).
* `component.props.label`: The text used for the `<label>`.
* `props.vAddress` (consumed by `VModel.md`): Used by `VModel.md` to generate the `inputId` prop passed to `Input.vue`.
* Other properties within `component.props` (like `placeholder`, `rows`, `disabled`): Passed via `$attrs` through
  `VModel.vue` and `Input.vue` to the final component.

## Dependencies

- `@VModel.md`: The parent wrapper component that handles `FormManager` integration, error display, and passes necessary
  props (`inputId`, `$attrs`).
- Specific Input Components (Dynamically Loaded):
    - `./Input/InputText.vue`
    - `./Input/Textarea.vue`
    - `./Input/Password.vue`
    - *(Others like AutoComplete, InputNumber, etc. - Note: Many of these were moved to `docs_cleaning` as
      unused/unimplemented)*
