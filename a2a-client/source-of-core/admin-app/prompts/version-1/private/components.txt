# JSON UI Components Documentation

## Core Components

### 1. Accordion
**Source:** `resources/common/js/Elements/Primevue/ComplexContainer/Accordion.vue`

#### Purpose
Wrapper for PrimeVue Accordion component that renders collapsible content sections based on JSON configuration.

#### JSON Structure
```json
{
  "type": "Accordion",
  "props": {
    "multiple": true,          // Allow multiple tabs open
    "activeIndex": [0],        // Initially open tab(s)
    "class": "custom-style"    // Custom styling
  },
  "items": [
    {
      "props": { 
        "header": "Panel Title",
        "disabled": false      // Optional: disable panel
      },
      "children": [
        // Content components
      ]
    }
  ]
}
```

#### Dependencies
- PrimeVue Accordion
- PrimeVue AccordionTab
- RenderJson component

### 2. AlertManager
**Source:** `resources/common/components/AlertManager.vue`

#### Purpose
Manages and displays system alerts and notifications.

#### JSON Structure
```json
{
  "type": "AlertManager",
  "props": {
    "severity": "info",        // info, success, warn, error
    "message": "Alert text",
    "closable": true,
    "life": 5000              // Auto-close timeout
  }
}
```

## Component Standards

### 1. Naming Conventions
- Use PascalCase for component types
- Use kebab-case for form/field names
- Use descriptive names for custom hooks

### 2. Props Structure
```json
{
  "type": "ComponentName",
  "props": {
    "class": "tailwind-classes",
    "data": "{state/path}",
    "custom": "value"
  },
  "model": {
    "form": "form-name",
    "field": "field-name"
  },
  "customHooks": {
    "event": [
      {
        "action": "action-name",
        "data": {}
      }
    ]
  }
}
```

### 3. Event Handling
```json
{
  "customHooks": {
    "click": [
      {
        "action": "sendData",
        "data": {
          "sendTo": "api/endpoint",
          "form": "form-name"
        }
      }
    ]
  }
}
```

## Best Practices

1. **Component Organization**
   - Keep components in appropriate directories
   - Use consistent naming patterns
   - Document component purpose and usage

2. **State Management**
   - Use FormManager for form state
   - Use StateManager (hub) for global state
   - Avoid direct component state when possible

3. **Event Handling**
   - Use standard actions from actions-documentation.md
   - Centralize event logic in ActionManager
   - Document custom event handlers

4. **Styling**
   - Use Tailwind CSS classes
   - Follow project style guidelines
   - Use PrimeVue Pass Through for component customization
