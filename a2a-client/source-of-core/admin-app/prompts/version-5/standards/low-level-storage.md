## 1. Address Formats
Адреса используются в инструкциях (`from`, `to`) для указания источника или назначения данных. Формат адреса определяет тип хранилища или сущности, с которой производится работа.

### 1.1 `buffer:<path>`
- Указывает на данные, хранящиеся во временном буфере сессии.
- Доступ к данным осуществляется по пути (`<path>`).
- Данные в буфере сохраняются только на время выполнения текущей сессии/задачи.

### 1.2 `file!<path>`
- Указывает на файл в файловой системе.
- `<path>` - относительный путь к файлу в рамках настроенного диска хранилища (например, `local` или `ai`).
- Используется для чтения данных из файлов (`from`) и записи данных в файлы (`to`).
- Для работы с этим адресом используется модуль данных `File`.

### 1.3 `output:<path>`
- Указывает на выходные данные инструкции.
- Используется в поле `to` для передачи результата выполнения инструкции в выходные данные.

## 2. Storage Modules (DataHub)
- Класс `DataHub` выступает в роли роутера, который по префиксу адреса определяет, какой **модуль данных** (`File`, `Buffer`, `Model` и т.д.) нужно использовать для работы.
- Действия в инструкциях (`update`, `save`, `get`, `remove`) на самом деле вызывают соответствующие методы у экземпляра этого модуля данных.

## 3. Action Interaction with Addresses
Взаимодействие действий с адресами зависит от типа модуля данных, который обрабатывает адрес.

### 3.1 Действие `update`
- Вызывает метод `set()` у соответствующего модуля данных.
- Назначение: обновление или установка данных в хранилище модуля.

### 3.2 Действие `save`
- Вызывает метод `save()` у соответствующего модуля данных.
- Назначение: запуск персистентной логики сохранения данных, реализованной модулем.

### 3.3 Действие `get`
- Вызывает метод `get()` у соответствующего модуля данных.
- Назначение: получение данных из хранилища модуля.

### 3.4 Действие `remove`
- Вызывает метод `remove()` у соответствующего модуля данных.
- Назначение: удаление данных из хранилища модуля.

## 4. File Persistence (`file!` addresses)
Работа с файлами через адреса `file!` имеет специфику:

- **`update` на `file!`: Вызывает метод `File::set()`**. Этот метод обновляет внутреннее свойство `$this->data` экземпляра модуля `File` **в оперативной памяти**. Думайте об этом как о внесении изменений в документ в текстовом редакторе, но **без сохранения**. Изменения видны "на экране" (в памяти системы), но **НЕ записаны немедленно на жесткий диск**.

- **`save` после операций с `file!`: Вызывает метод `File::save()`**. Этот метод берет текущее состояние данных из внутреннего свойства `$this->data` модуля `File` (то, что было обновлено в памяти) и **ФИЗИЧЕСКИ ЗАПИСЫВАЕТ ЭТИ ДАННЫЕ В ФАЙЛ НА ДИСК**. Это действие **СОХРАНЯЕТ** изменения.

**КРАЙНЕ ВАЖНОЕ ПРАВИЛО:**
Для того чтобы изменения, сделанные через действие `update` (или любые другие действия, которые изменяют данные в памяти модуля `File`, вызывая `File::set()`), были окончательно сохранены в файл на диске, **НЕОБХОДИМО ЯВНО ВЫЗВАТЬ ДЕЙСТВИЕ `save`** после этих операций с тем же `file!` адресом.

**Если вы `update` данные в `file!` и СРАЗУ ЖЕ пытаетесь их ПРОЧИТАТЬ обратно из того же `file!`, без промежуточного `save`, вы, скорее всего, прочитаете старые данные с диска, а не те, что только что были записаны в память!** Действие `save` — это команда "Записать на диск прямо сейчас!".

**Пример:**
Если вы хотите записать данные в файл `temp.json` и потом использовать их в этой же сессии, ваш блок инструкций должен выглядеть примерно так:
```json
{
    "action": "update",
    "batch": [
        {
            "from": "buffer:готовые_данные",
            "to": "file!путь/к/temp.json" // Данные записаны в память модуля File
        }
    ]
},
{
    "action": "save",
    "from": "file!путь/к/temp.json" // Данные из памяти записаны на диск
},
{
    "action": "update",
    "batch": [
        {
            "from": "file!путь/к/temp.json", // Теперь читаем с диска (актуальные данные)
            "to": "buffer:прочитанные_данные"
        }
    ]
}
```

**Запомните:** `update` = изменить в памяти (не сохранено), `save` = записать из памяти на диск (СОХРАНЕНО).

## 5. Examples

### Пример сохранения в файл:
```json
{
    "type": "Instructions",
    "instructions": [
        {
            "action": "update",
            "batch": [
                {
                    "from": "buffer:some_data",
                    "to": "file!path/to/temp_file.json"
                } // Данные записаны в память модуля File
            ]
        },
        {
            "action": "save"
            // Вызывает File::save(), который записывает данные из памяти в temp_file.json на диск
        }
    ]
}
```
