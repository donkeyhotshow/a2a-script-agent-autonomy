## **Главные принципы для переработки**

1. **В начале каждого файла — системный промт**  
   - Кратко и максимально чётко: роль, цель, ограничения, формат работы.
   - Это первое, что увидит и “запомнит” модель.

2. **Первый промт — самый объёмный и контекстный**  
   - Должен задавать весь контекст задачи, примеры, ограничения, стиль, формат вывода.
   - Включает плейсхолдеры для будущих расширений.

3. **Далее — секции для отдельных операций/ролей**  
   - Для каждой операции: отдельный промт, примеры (input → output), пояснения.
   - Для каждой роли: чётко описать, что делает модель на этом этапе.

4. **В конце файла — секция “Удалить после доработки”**  
   - Всё устаревшее, лишнее, временные заметки — сюда, чтобы не мешали основной логике.

5. **Плейсхолдеры для расширения**  
   - В каждом файле и секции: `## [Плейсхолдер] Для новых операций/примеров/ролей`

- В начале каждого файла: системный промт для роли “Валидатор структуры/схемы”.

- Примеры: исходный JSON → целевая структура.
- Плейсхолдеры для новых трансформаций.

### 3. **mutation/**
- Системный промт: “AI-редактор/мутатор, пошагово исправляющий ошибки”.

- Плейсхолдеры для новых стратегий/шаблонов.

### 4. **documentation/**
- Системный промт: “Генератор документации/тест-кейсов/примеров”.

- Примеры: структура → документация, структура → тест-кейс.
- Плейсхолдеры для новых форматов/примеров.

### 5. **system/**
- Системный промт: “Оркестратор пайплайна/контроллер цепочки”.
- Далее: промты для запуска, координации, сбора результатов, оптимизации.

## Главные принципы переработки промтов

1. **Модульность и композиция**  
   - Каждый промт — это отдельный файл, отвечающий за одну роль, шаг или функцию.
   - Файлы не содержат дублирующегося контента: общие части выносятся в отдельные шаблоны или включаются через `{include:...}` или аналогичный механизм.
   - Возможность комбинировать промты в любой последовательности без потери смысла и без повторов.

2. **Ограничение по размеру**  
   - Каждый отдельный промт-файл не должен превышать лимит модели (например, 8000 символов для Qwen 2.5 1.5B).
   - Первый (общий/системный) промт максимально насыщен и приближен к лимиту, чтобы дать максимум контекста.
   - Остальные промты — специализированные, короткие, легко комбинируются.

3. **Структура папок и именование**  
   - Вместо номеров в именах файлов используем вложенные папки для логической группировки (например, `validation/`, `transformation/`, `mutation/`, `system/`, `steps/`).
   - Каждый файл — атомарный элемент серии промтов (например, `validation/step-parse-json.txt`, `validation/step-check-schema.txt`).
   - Для общих блоков — папка `common/` или `includes/` (например, `includes/system-header.txt`).

4. **Шаблонизация и включения**  
   - Используем шаблоны `{...}` для переменных и `{include:...}` для вставки других файлов.
   - Варианты комбинирования описываем в отдельных файлах (например, `combos/validation-full.txt`), где просто перечисляем последовательность включаемых промтов.

5. **Гибкость и расширяемость**  
   - Любой промт можно заменить, добавить или переставить без необходимости переписывать другие.
   - Легко поддерживать и тестировать отдельные шаги.

### 3. **Генерация комбинаций**

```php
// build_prompt.php
```

```sql
CREATE TABLE combos (
```

- Быстрые выборки: `SELECT * FROM combos WHERE status=0;`
- Массовое обновление: `UPDATE combos SET status=1 WHERE combo='combos/combo1.json';`
- Можно хранить дополнительные поля (результат, лог, время выполнения и т.д.)

**Плюсы:**

## Пример: Python + SQLAlchemy

**Модель:**
```python
from sqlalchemy import create_engine, Column, Integer, String, DateTime
from sqlalchemy.orm import declarative_base, sessionmaker
from datetime import datetime

Base = declarative_base()

class Combo(Base):
    __tablename__ = 'combos'
    id = Column(Integer, primary_key=True)
    combo = Column(String, unique=True)
    status = Column(Integer, default=0)
    last_run = Column(DateTime)

engine = create_engine('sqlite:///combos.db')
Base.metadata.create_all(engine)
Session = sessionmaker(bind=engine)
session = Session()

# Пример добавления
combo = Combo(combo='combos/combo1.json')
session.add(combo)
session.commit()

# Пример выборки
for c in session.query(Combo).filter_by(status=0):
    print(c.combo)

# Пример обновления
c = session.query(Combo).filter_by(combo='combos/combo1.json').first()
c.status = 1
c.last_run = datetime.now()
session.commit()
```

## Пример: Node.js + Sequelize

```js
const { Sequelize, DataTypes } = require('sequelize');
const sequelize = new Sequelize('sqlite:combos.db');

const Combo = sequelize.define('Combo', {
  combo: { type: DataTypes.STRING, unique: true },
  status: { type: DataTypes.INTEGER, defaultValue: 0 },

});

await sequelize.sync();

// Добавление
await Combo.create({ combo: 'combos/combo1.json' });

c.status = 1;
c.lastRun = new Date();
await c.save();
```
