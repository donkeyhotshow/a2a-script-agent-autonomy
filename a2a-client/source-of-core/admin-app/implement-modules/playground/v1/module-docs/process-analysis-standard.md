# Правило методологии анализа процесса

Это правило направляет ИИ в систематическом анализе сложных процессов, рабочих процессов или взаимодействий кода для
достижения глубокого понимания перед созданием документации, тестов или реализацией связанных функций. Оно отражает
итеративный цикл «Сканирование -> Планирование -> Уточнение».

## Шаги методологии

При выполнении задачи по пониманию сложного процесса (например, «Документирование потока регистрации пользователей»,
«Создание интеграционных тестов для конвейера обработки заказов»):

1. Первоначальное сканирование и планирование (режим: ПЛАН 🎯):

* Определите область действия: четко определите границы процесса, который необходимо проанализировать.
* Соберите начальную информацию: прочитайте соответствующие файлы точек входа (@controller_name.php), файлы основной
  логики (@Main.php, @App.php), связанные модули (@Data.php, @StorageDataModules/*), существующую документацию (docs/) и
  связанные записи @memories.md.

* Сформулируйте начальное понимание: обобщите очевидный поток на основе начального сканирования в @scratchpad.md.
* Определите известные и неизвестные: перечислите, что ясно и что требует дальнейшего изучения.
* Сформулируйте уточняющие вопросы: сформулируйте конкретные вопросы, нацеленные на неизвестные или неоднозначности.
  Минимум 3 вопроса.
* Оцените уверенность: укажите начальную оценку уверенности (%) на основе неизвестных.
* Создайте начальный план: опишите следующие шаги (файлы для чтения, журналы для проверки, конкретные функции для
  анализа) в @scratchpad.md.

2. Итеративное уточнение (сканирование -> анализ -> цикл плана):

* Выполнение плана (сканирование): выполните действия, описанные в @scratchpad.md (чтение файлов, поиск кода, анализ
  журналов).
* Анализ результатов: интегрируйте новую информацию с существующим пониманием. Ответьте на ранее созданные вопросы.
* Обновление понимания и уверенности: уточните резюме в @scratchpad.md. Обновите оценку уверенности.
* Выявление новых неизвестных/вопросов: по мере углубления понимания могут возникнуть новые неясности или области,
  требующие детализации. Сформулируйте новые вопросы.
* Уточнение плана: обновите @scratchpad.md следующим набором действий для устранения оставшихся неизвестных.
* Повторение: продолжайте этот цикл, пока уровень уверенности не достигнет 95–100%.

3. Консолидация и действие (режим: АГЕНТ ⚡️ — если применимо):

* Окончательное резюме: после достижения высокой уверенности создайте всеобъемлющее резюме потока процесса, включая
  ключевые компоненты, взаимодействия, преобразования данных и потенциальные пограничные случаи.
* Документирование уроков: запишите важные выводы или сложные аспекты в @lessons-learned.md.
* Переход к задаче: начните основную задачу (документирование, создание теста, реализация), вооружившись глубоким
  пониманием процесса. Регулярно ссылайтесь на консолидированное понимание.

## Цель

Основная цель — избегать поверхностного понимания и гарантировать, что любая последующая работа (документация, тесты,
код) основана на тщательном и точном анализе рассматриваемого процесса. Это предотвращает ошибки, переделки и неполные
результаты.

## Перекрестные ссылки

На протяжении всего процесса постоянно ссылайтесь на результаты с помощью:

- @memories.md для исторического контекста и прошлых решений.
- @lessons-learned.md для соответствующих ранее решенных проблем или установленных закономерностей.
- @scratchpad.md для активного плана и развивающегося понимания.
- Требования к проекту (docs/project-requirements.md), если применимо.
