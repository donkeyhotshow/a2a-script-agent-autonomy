# Чеклист и план развития: модуль playground (v1)

## 1. Назначение и структура

Модуль предназначен для тестирования, обучения и демонстрации возможностей фреймворка AiRudeDepot. Здесь создаются серии усложняющихся примеров, а также showcase-страницы для ключевых возможностей, включая интеграцию с другими модулями (landing-main-page, contact-form, page и др.).

---

## 2. Существующие страницы и примеры

- **index.json** — оглавление/стартовая страница playground
- **model-test-v1.json** — CRUD и фильтрация моделей
- **mysql-test-v1.json** — работа с MySQL (запросы, фильтрация, транзакции)
- **session-test-v1.json**, **session-test-v2.json** — базовые и расширенные примеры работы с сессией

### Actions (по сериям)
- Для каждой серии (model-test-v1, mysql-test-v1, session-test-v1/v2) — отдельные actions: save, load, update, delete и др.
- Для сложных примеров — предусмотреть автоматические тесты и сценарии edge-case.

### Документация
- module-docs/ — стандарты, методички, примеры
- @playground-json-module.md — описание подходов к созданию примеров

## 3. План развития: серии примеров и демонстрационные страницы

### A. Серии усложняющихся примеров
- session-test: от простого сохранения/чтения до сложных сценариев с удалением, сериализацией, вложенными структурами
- model-test: CRUD, фильтрация, валидация, связи между моделями, массовые операции
- mysql-test: базовые запросы, фильтрация, сортировка, транзакции, обработка ошибок
- future: добавить примеры с асинхронностью, очередями, интеграцией с внешними API
- Для каждой серии — предусмотреть уровни сложности: **basic**, **advanced**, **pro** (с отдельными страницами и meta)
- Для каждой страницы — добавить сценарии тестирования, edge-cases, визуализацию прогресса (например, чекбоксы "пройдено/не пройдено")

### B. Демонстрационные страницы возможностей AiRudeDepot
- Визуализация структуры данных (деревья, графы, схемы)
- Динамические формы (автоматическая генерация UI по схеме)
- Работа с событиями и хуками (демонстрация реактивности)
- Интеграция с actions (цепочки действий, обработка ошибок)
- Пользовательские сценарии (мастер-деталь, пошаговый процесс)
- Встроенные валидаторы и кастомные правила
- Работа с meta/инструкциями внутри файлов
- Демонстрация расширяемости: подключение новых actions, страниц, секций на лету
- Для каждой демонстрации — добавить описание, какие возможности/фичи фреймворка она иллюстрирует

### C. Showcase: компоненты sakai
- **sakai/** — ранее использовавшиеся компоненты (до модернизации системы)
- Планируется повторное подключение этих примеров для демонстрации:
  - Как минимизировать избыточное использование Primevue-компонентов
  - Как строить компактные и эффективные UI на базе AiRudeDepot
  - Сравнение подходов: sakai vs. Primevue-heavy
- Для каждой showcase-страницы — добавить аннотацию, что это пример «минималистичного» подхода
- Для showcase — предусмотреть сравнение производительности, читаемости кода, удобства поддержки

### D. Интеграция с другими модулями
- Для примеров, связанных с landing-main-page, contact-form, page — предусмотреть отдельные страницы, демонстрирующие интеграцию (например, использование компонентов/данных из contact-form на страницах playground)
- Для showcase — добавить примеры, где используются части других модулей (например, формы из contact-form, секции из page)

## 4. Чеклист для развития модуля playground

- [ ] Для каждой серии примеров — отдельная папка pages/ и actions/
- [ ] Для каждой страницы — meta-блок с описанием, статусом, категорией (пример, демонстрация, тест, интеграция)
- [ ] Для каждой серии — предусмотреть усложнение: от простого к сложному (например, session-test-v1 → session-test-v2 → session-test-advanced)
- [ ] Для демонстрационных страниц AiRudeDepot — отдельная категория (например, demo-*)
- [ ] Для showcase sakai — отдельная категория, аннотация о цели
- [ ] Для каждой демонстрации — кратко описать, какую особенность/возможность она иллюстрирует
- [ ] Для интеграционных примеров — явно указывать, какие модули используются
- [ ] Вести README или index.json с оглавлением и ссылками на все примеры и демонстрации
- [ ] Для сложных примеров — визуальные схемы, комментарии, ссылки на документацию
- [ ] Для actions — тестовые данные и сценарии использования
- [ ] Для новых возможностей фреймворка — сразу создавать демонстрационные страницы
- [ ] Для каждой страницы — предусмотреть автоматические тесты (если возможно)

- Все новые примеры и демонстрации снабжать meta и кратким описанием (title, description, status, category, relatedModules)
- Для каждой серии — предусмотреть "уровни сложности" (basic, advanced, pro)
- Для AiRudeDepot — отдельные showcase-страницы по ключевым возможностям
- Для showcase sakai — явно отмечать цель (минимизация Primevue, компактность, сравнение)
- Для интеграционных примеров — указывать связи с другими модулями
- В README или index.json поддерживать актуальное оглавление с краткими аннотациями
- Для сложных примеров — поддерживать автоматические тесты и визуализацию прогресса
