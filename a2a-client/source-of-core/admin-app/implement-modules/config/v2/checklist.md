# Чеклист и визуальное описание: модуль config/v2

## 1. Обзор существующих файлов

### actions/
- set_module_enabled_status.json
- FileActions.json
- list_log_files.json
- save_config_file.json
- ModuleActions.json
- load_config_file.json
- load_log_file.json
- LogActions.json
- list_modules.json

**Назначение:**
- Управление состоянием модулей (включение/отключение)
- Операции с файлами конфигов
- Загрузка/сохранение/список логов
- Универсальные действия для работы с модулями и логами

#### Детализация actions/

| Файл                      | Назначение                                      | Основные поля/структура                | Пример сценария использования         | Статус         |
|---------------------------|------------------------------------------------|----------------------------------------|---------------------------------------|----------------|
| set_module_enabled_status.json | Включение/отключение модуля по ID             | moduleId, enabled (bool)               | Включить/отключить модуль через UI    | Требует описания|
| FileActions.json          | Операции с файлами (чтение, запись, удаление)   | action, filePath, data                 | Сохранить/удалить/прочитать файл      | Требует описания|
| list_log_files.json       | Получение списка лог-файлов                     | filter, limit, offset                  | Показать список логов в UI            | Требует описания|
| save_config_file.json     | Сохранение конфигурационного файла              | filePath, data                         | Сохранить изменения в конфиге         | Требует описания|
| ModuleActions.json        | Универсальные действия с модулями               | action, moduleId, params               | Создать/удалить/обновить модуль       | Требует описания|
| load_config_file.json     | Загрузка конфигурационного файла                | filePath                               | Открыть конфиг для редактирования     | Требует описания|
| load_log_file.json        | Загрузка содержимого лога                       | logFile, range                         | Просмотреть лог в UI                  | Требует описания|
| LogActions.json           | Универсальные действия с логами                 | action, logFile, params                | Очистить/удалить/экспортировать лог   | Требует описания|
| list_modules.json         | Получение списка всех модулей                   | filter, limit, offset                  | Показать все модули в UI              | Требует описания|

### validations/
- scanGroupSchema.json
- groupDefinitionSchema.json
- scanGroupArraySchema.json
- periodicActionsSchema.json
- scriptSettingsSchema.json

**Назначение:**
- Схемы для валидации групп, сканов, периодических действий, настроек скриптов

#### Детализация validations/

| Файл                      | Назначение                                      | Основные поля/структура                | Где используется / сценарий           | Статус         |
|---------------------------|------------------------------------------------|----------------------------------------|---------------------------------------|----------------|
| scanGroupSchema.json      | Валидация структуры группы сканирования         | groupId, name, rules, targets          | Проверка корректности группы сканирования при сохранении | Требует описания|
| groupDefinitionSchema.json| Валидация определения группы                    | groupId, members, description          | Проверка структуры группы при создании/редактировании    | Требует описания|
| scanGroupArraySchema.json | Валидация массива групп сканирования            | groups: [scanGroupSchema]              | Проверка списка групп при массовом импорте/экспорте      | Требует описания|
| periodicActionsSchema.json| Валидация периодических действий                | actions, schedule, enabled             | Проверка расписания и параметров периодических задач     | Требует описания|
| scriptSettingsSchema.json | Валидация настроек скриптов                     | scriptId, settings, params             | Проверка параметров скрипта при запуске/сохранении       | Требует описания|

## 3. Визуальное описание будущих рабочих страниц (ui/pages/)

### A. scripts_config.json
- **Назначение:** Управление скриптами, настройками, параметрами запуска
- **Основные элементы:**
  - Список скриптов (таблица с фильтрами)
  - Форма редактирования параметров выбранного скрипта
  - Кнопки запуска/остановки скрипта
  - Индикация статуса выполнения (progress bar, статус-иконка)
  - История запусков/лог ошибок (опционально)
- **Сценарии:**
  - Пользователь выбирает скрипт, редактирует параметры, запускает выполнение, отслеживает статус

### B. ui_presets.json / ui_presets_editor.json
- **Назначение:** Управление UI-пресетами (темы, стили, шаблоны)
- **Основные элементы:**
  - Список пресетов (сортировка, поиск)
  - Форма редактирования/создания пресета (цвета, шрифты, layout)
  - Кнопки сохранения/удаления/применения пресета
- **Сценарии:**
  - Пользователь выбирает или создает пресет, настраивает параметры, сохраняет и применяет

### C. top_bar_config.json
- **Назначение:** Конфигурирование верхней панели интерфейса
- **Основные элементы:**
  - Список элементов топ-бара (drag&drop порядок)
  - Настройка видимости, иконок, действий для каждой кнопки
  - Привязка кастомных действий/скриптов
- **Сценарии:**
  - Админ настраивает топ-бар под задачи команды, добавляет/удаляет элементы, меняет порядок

### D. module_versions.json / module_management.json
- **Назначение:** Управление версиями и состоянием модулей
- **Основные элементы:**
  - Список модулей (название, версия, статус)
  - Информация о доступных обновлениях
  - Кнопки включения/отключения, обновления, удаления
  - История изменений (опционально)
- **Сценарии:**
  - Админ просматривает список модулей, обновляет или отключает нужные, отслеживает историю изменений

### E. logs_viewer.json
- **Назначение:** Просмотр и фильтрация логов системы
- **Основные элементы:**
  - Список лог-файлов (сортировка, фильтры)
  - Просмотр содержимого выбранного лога (поиск, пагинация)
  - Кнопки скачивания, очистки, экспорта
- **Сценарии:**
  - Пользователь выбирает лог, просматривает события, фильтрует по дате/типу, скачивает или очищает

## 4. Визуальное описание будущих экшенов (actions/)

- **set_module_enabled_status.json** — Включение/отключение модуля по ID
  - Основные поля: moduleId, enabled
  - Сценарий: пользователь включает/отключает модуль через UI, состояние сохраняется
- **FileActions.json** — Операции с файлами (чтение, запись, удаление)
  - Основные поля: action (read/write/delete), filePath, data
  - Сценарий: пользователь сохраняет или удаляет файл конфига через UI
- **list_log_files.json** — Получение списка лог-файлов
  - Основные поля: filter, limit, offset
  - Сценарий: пользователь открывает страницу логов, видит список файлов
- **save_config_file.json** — Сохранение конфигурационного файла
  - Основные поля: filePath, data
  - Сценарий: пользователь редактирует и сохраняет конфиг
- **ModuleActions.json** — Универсальные действия с модулями
  - Основные поля: action (create/delete/update), moduleId, params
  - Сценарий: админ создает, удаляет или обновляет модуль
- **load_config_file.json** — Загрузка конфигурационного файла
  - Основные поля: filePath
  - Сценарий: пользователь открывает конфиг для просмотра/редактирования
- **load_log_file.json** — Загрузка содержимого лога
  - Основные поля: logFile, range
  - Сценарий: пользователь просматривает содержимое лога
- **LogActions.json** — Универсальные действия с логами
  - Основные поля: action (clear/delete/export), logFile, params
  - Сценарий: пользователь очищает, удаляет или экспортирует лог
- **list_modules.json** — Получение списка всех модулей
  - Основные поля: filter, limit, offset
  - Сценарий: пользователь открывает страницу модулей, видит список
