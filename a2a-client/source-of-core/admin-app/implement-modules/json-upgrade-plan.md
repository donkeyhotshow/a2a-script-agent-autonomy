## Текущие задачи и стандартизация

### 1. Расширение синтаксиса для type: Page
- [ ] Для всех компонентов типа Page:
    - Ввести обязательный параметр `meta` (title, description, status, category и др.)
    - Убрать использование `props` на верхнем уровне Page
    - Все дополнительные данные (описание, ссылки, критические моменты, документация) размещать в meta
    - Обновить валидатор для поддержки meta и отказа от props
    - Пример:
      ```json
      {
        "type": "Page",
        "meta": {
          "title": "...",
          "description": "...",
          "status": "...",
          "category": "..."
        },
        "content": [ ... ]
      }
      ```
- [ ] Для всех существующих страниц провести рефакторинг структуры

### 2. Компоненты для системных операций (action: operation и др.)
- [ ] Для компонентов, предназначенных для использования системой (action, operation и др.):
    - Ввести строгую валидацию входящих данных по типу
    - В каждом файле предусмотреть секцию (например, meta или system), которая не попадает в рендер, но содержит служебные данные, описания, ссылки на документацию, критические моменты и т.д.
    - Использовать компонент Instructions для структурных подсказок и управляющих данных (уже внедрён, но не полностью имплементирован)

### 3. Нейминг новых типов массивов (TASK-CORE-ADD-ARRAY-SCHEMAS-001)
- [ ] Утвердить финальные имена для новых типов:
    - IndexedArrayTemplate → ObjectContainer
    - ArrayOfTemplates → BlocksArray
- [ ] Обновить все схемы, документацию и usage-примеры согласно финальному неймингу
