# Серверные действия (Actions) в модулях JSON UI

Этот документ описывает механизм серверных действий (`actions`), используемый в системе `JSON UI` для реализации
динамического взаимодействия и обработки данных на стороне сервера.

## Назначение серверных действий

Серверные действия (`actions`) позволяют реализовать динамическое взаимодействие пользователя со страницей,
обрабатываемое на стороне сервера. Это может включать:

* Отправку данных из форм (например, контактной формы, формы подписки, формы заказа).
* Загрузку динамического контента, зависящего от действий пользователя.
* Управление состоянием пользователя (например, сохранение предпочтений).
* Выполнение сложных операций, требующих доступа к базе данных или внешним `API`.
* Открытие модальных окон с серверной загрузкой контента.

**Примечание:** В простых модулях, таких как Landing Page (`landing-main-page`), где основная цель - представление
статического контента, серверные `actions` **обычно не используются**. Для базовой навигации и простых UI-эффектов
достаточно клиентских `customHooks`. Серверные `actions` становятся необходимы при добавлении функциональных форм или
другой сложной серверной логики.

## Структура и расположение

Определения действий для модуля размещаются в `JSON`-файлах (или `PHP`-файлах) внутри директории `actions/` модуля.

<!-- ```bash
storage/aiInstaller/{module-name}/
└── actions/
    ├── contact-form-submit.json
    ├── subscribe-newsletter.json
    └── process-order.php
    └── ...
``` -->

Каждый файл (`.json` или `.php`) описывает логику, которая должна быть выполнена на сервере при вызове этого действия.
`JSON`-файлы содержат декларативную последовательность шагов (инструкций).

<!-- ```json
// Пример: actions/contact-form-submit.json
[
  {
    "action": "validate", // Шаг валидации
    "rules": "contact-form-rules", // Ссылка на правила валидации
    "from": "input:formData" // Данные для валидации (из запроса)
  },
  {
    "action": "call", // Шаг вызова PHP-метода/команды
    "method": "App\\Services\\NotificationService::sendContactEmail",
    "params": ["{input:formData}"] // Передача данных формы
  },
  {
    "action": "update", // Шаг обновления UI (например, показать сообщение об успехе)
    "to": "output:showSuccessMessage",
    "value": true
  },
  {
    "action": "return", // Возврат данных на клиент
    "from": "output"
  }
]
``` -->

## Поток обработки действий

Когда пользователь инициирует действие на клиенте (например, нажимает кнопку с `actionType: 'submit'` или
`actionType: 'call'`), происходит следующий процесс:

1. **Клиент:** Frontend отправляет `POST`-запрос на сервер, содержащий адрес вызываемого действия (например,
   `landing-page/actions/contact-form-submit`) и полезную нагрузку (`payload`, обычно данные формы).
2. **Маршрутизация:** Laravel направит запрос к `ModuleController`.
3. **`ModuleController`:**
    * Определит запрошенный модуль и действие.
    * Вызовет `Main::runAppEnv()`, передавая информацию о запросе и модуле.
4. **`Main::runAppEnv()`:**
    * Создаст экземпляр класса приложения для модуля (например, `App\AiRudeDepot\App\Modules\LandingPage\App`).
    * Вызовет `Main::processActions()`.
5. **`Main::processActions()`:**
    * Вызовет метод `actions()` соответствующего экземпляра `App`.
6. **`App::actions()` / `App::moduleActions()`:**
    * Этот метод является **основным обработчиком** действий для модуля.
    * Он анализирует `POST`-запрос.
    * Для каждого действия в запросе он будет использовать `DataProcessor::processAction()`, передавая ему путь к файлу
      действия (например, `landing-page/actions/contact-form-submit`) и `payload`.
7. **`DataProcessor::processAction()`:**
    * Загрузит файл действия (`.json` или `.php`).
    * Если это `JSON`, последовательно выполнит инструкции, используя `ProcessInstruction::executeInstructions()`. Это
      включает шаги `update`, `call`, `validate`, `save`, `return` и т.д., взаимодействуя с `StorageSession` для доступа
      к данным.
    * Если это `PHP`, выполнит соответствующий метод.
    * Сформирует `StepResponse` с результатами выполнения действия.
8. **Возврат ответа:** `StepResponse` вернется через `Main` и `ModuleController` на клиент.
9. **Клиент:** Frontend обработает `StepResponse`, обновляя `UI` в соответствии с полученными данными (например,
   отображая сообщение об успехе, очищая форму, выполняя редирект).

## Связанные компоненты ядра

* [`app/Http/Controllers/Common/ModuleController.php`](../../../../laravel-ui/Controllers/Common/ModuleController.md):
  Точка входа, маршрутизация запросов к модулям.
* [`app/AiRudeDepot/Main.php`](../../../../core/AiRudeDepot/Main.md): Оркестратор жизненного цикла запроса и вызова

  инструкции/логику действий (`processAction`).
* [`app/AiRudeDepot/Render/ProcessInstruction.php`](../../../../core/AiRudeDepot/Render/ProcessInstruction.md): Трейт,
  реализующий логику выполнения шагов `JSON`-инструкций.
* [`app/AiRudeDepot/Support/StorageSession.php`](../../../../core/AiRudeDepot/Support/StorageSession.md): Управляет
  доступом к данным (сессия, буфер, файлы, модели).
* [`app/AiRudeDepot/StepResponse/StepResponse.php`](../../../../core/AiRudeDepot/StepResponse/README.md):
  Стандартизированный объект ответа сервера.

## Заключение

Серверные действия являются ключевым механизмом для добавления динамики и серверной логики в модули `JSON UI`. Они
позволяют обрабатывать формы, взаимодействовать с базой данных и выполнять другие операции на стороне сервера в ответ на
действия пользователя. В простых модулях Landing Page они используются редко, уступая место клиентским `customHooks`.
