# Как создать модуль Landing Page (V1 - Текущий Подход)

> **Важно:** Этот документ описывает **текущий (V1)** подход к созданию модулей Landing Page. Для информации о
> планируемом V2 подходе см. документацию v2+.

Это руководство описывает процесс создания модулей JSON UI Landing Page в **текущей версии V1**, с акцентом на
*структуру, статический контент и базовые UI-взаимодействия*.

> **Важно:** Перед началом разработки **V1 модуля** ознакомьтесь
> с [чек-листом верификации модуля](../../../checklists/verifications/module-verification.md)
> и [чек-листом стандартов UI компонентов](../../../standards/component-standards.md), чтобы обеспечить соответствие
> стандартам проекта.

## 1. Определение Цели и Структуры (V1)

- **Цель:** Отображение информации, маркетинг, простая навигация с использованием **секций и компонентов V1**.
- **Основной подход (V1):**
    - Композиция UI из **страниц** (`page.json`, `booking.json` и т.д.) и **секций** (`sections/*.json`).
    - Использование **статического контента** (часто встроенного прямо в JSON страниц/секций или опционально в
      `data/*.json`).
    - Базовые UI-взаимодействия через `customHooks` (навигация, UI-эффекты).
- **Типичная структура директории (V1 - Пример: `landing-main-page`):**
  ```bash
  storage/aiInstaller/landing-main-page/
  ├── page.json # Основная страница лендинга
  ├── booking.json # Страница записи
  ├── services.json # Страница услуг
  ├── contact.json # Страница контактов
  ├── about-us.json # Страница "О нас"
  ├── sections/ # Секции, включаемые в страницы
  │ ├── header-section.json
  │ ├── hero-section.json
  │ ├── footer-section.json
  │ ├── booking/ # Поддиректория секций для страницы booking
  │ │ └── booking-form-section.json
  │ ├── services/ # Поддиректория секций для страницы services
  │ │ └── ...
  │ ├── contact/ # Поддиректория секций для страницы contact
  │ │ └── ...
  │ └── about-us/ # Поддиректория секций для страницы about-us
  │ └── ...
  ├── data/ # Опционально: Статический контент (JSON)
  │ └── ...
  ├── assets/ # Ресурсы модуля (изображения, иконки)
  │ └── ...
  ├── code/ # PHP-класс модуля
  │ └── BarberAndTattooLandingPage.php
  └── _i/ # Метаданные установщика
  ```
  *Примечание V1:* В V1 используется структура на основе файлов страниц (`*.json`) в корне модуля и включаемых секций в
  директории `sections/`.

## 2. Создание Страниц (`page.json`, `booking.json` и т.д.)

- Каждый корневой `*.json` файл (кроме файлов в `sections/`, `data/` и т.д.) определяет **отдельную страницу** модуля.
- Определяет метаданные страницы (`title`, `description`) и основное содержимое (`content`).
- **Композиция (V1):** Используйте операции `include` (для замены) или `add` (для добавления в массив) для вставки
  переиспользуемых секций (например, `header-section`, `footer-section`) или специфичных для страницы секций из
  `sections/*`.

```json
// Пример: page.json (V1)
{
  "page": {
    "title": "Головна",
    "description": "...",
    "content": {
      "type": "Panel", // или div
      "name": "landing-page",
      "children": [
        {
          "type": "operation",
          "action": "include",
          "source": "landing-main-page/sections/header-section"
        },
        {
          "type": "operation",
          "action": "include",
          "source": "landing-main-page/sections/hero-section"
        },
        // ... другие include для секций главной страницы ...
        {
          "type": "operation",
          "action": "include",
          "source": "landing-main-page/sections/footer-section"
        }
      ]
    }
  }
}
```

## 3. Создание Секций (`sections/**/*.json`)

- Каждый `*.json` файл в `sections/` (или ее поддиректориях) описывает **переиспользуемую секцию** или часть страницы.
- Секции компонуются из **компонентов `PrimeVue`** и **базовых HTML элементов** (представленных как JSON UI компоненты,
  например, `div` с `content`).
- **Контент (V1):** Используйте **статический контент**, встроенный напрямую в JSON секции или опционально загружаемый
  из файлов `data/*.json`.
- **Стилизация (V1):** Применяйте классы `PrimeVue` и `Tailwind CSS` через `props.class`. Дополнительные стили через
  `props.style`.

## 4. Добавление Статического Контента (`data/*.json` - Опционально)

- Директория `data/` может использоваться для хранения **статического контента** (тексты, списки), если не удобно
  встраивать его напрямую в секции.
- **Подключение контента (V1):** На сервере, при обработке JSON, через операции `include` или `add`, ссылающиеся на
  файлы в `data/` или других местах. Либо через серверные `actions` (в V2+).

## 5. Реализация Базовой Интерактивности (`customHooks`)

- Используйте `customHooks` для простой клиентской интерактивности:
    - **Навигация:** `navigateTo` с `route` (внутренние страницы), `url` (внешние ссылки), `fragment` (якоря на той же
      странице).
    - **UI-эффекты:** `toggleClass` для показа/скрытия элементов (например, мобильное меню).
- Ссылки на документацию по действиям: [Справочник UI Команд](../../json-ui/commands-and-operations/ui-documentation.md)

## 6. Верификация Модуля по Чек-листам (V1)

**Обязательный шаг перед завершением разработки V1 модуля.**

1. [**Чек-лист верификации модуля**](../../../checklists/verifications/module-verification.md) - проверка структуры V1,
   именования файлов, расположения ресурсов.
2. [**Чек-лист стандартов UI компонентов**](../../../standards/component-standards.md) - проверка соответствия JSON UI
   компонентов стандартам V1.

**Ключевые аспекты для V1:**

- Использование V1 структуры директорий и файлов (страницы в корне, секции в `sections/`).
- Применение компонентов `PrimeVue` и базовых HTML элементов.
- Использование `customHooks` для базовых UI-взаимодействий (`navigateTo`, `toggleClass`).
- Статический контент (встроенный или в `data/`).
- Отсутствие функциональных форм и серверных `actions`.

## Ключевые Принципы (V1)

- **Страницы и Секции:** UI строится из **страниц** (`*.json` в корне) и **секций** (`sections/*.json`).
- **Статичность:** Основной контент **статичен**.
- **Базовая Интерактивность:** Ограничена **простыми действиями `customHooks`**.
- **Представление:** Фокус на **визуальном представлении**.
- **Минимум логики:** Отсутствие сложной бизнес-логики или серверного взаимодействия.
