# Пример: Модуль `landing-main-page`

Этот документ содержит описание модуля `landing-main-page` как примера реализации Landing Page.

## Общее описание

Модуль `landing-main-page` представляет собой набор `JSON`-файлов, формирующих статическую посадочную страницу и
связанные с ней страницы (услуги, контакты, о нас, запись) для барбершопа/тату-салона. Текущая реализация включает:

- Основную страницу (`page.json`), собираемую из секций (`sections/*.json`).
- Отдельные страницы для услуг (`services.json`), контактов (`contact.json`), информации "О нас" (`about-us.json`) и
  формы записи (`booking.json`).
- Стандартный хедер и футер, включаемые во все страницы.
- Секции для отображения контента: Hero, Преимущества, Особенности, Цены, Карта (плейсхолдер), Ценности, История,
  Команда, FAQ, Галерея.
- **Ограниченную интерактивность:**
    - Навигация между страницами (`navigateTo` + `route`).
    - Навигация к секциям на той же странице (`navigateTo` + `fragment`).
    - Ссылки на внешние ресурсы (`navigateTo` + `url`).
    - Переключение видимости элементов (`toggleClass`).
    - Стандартные ссылки в футере (`Link` + `href`).
- **Нефункциональные формы:** Формы записи и контактов присутствуют визуально, но кнопки отправки **неактивны**. Для их
  активации потребуется доработка с использованием серверных `actions` и, возможно, `FormManager`.

## Структура модуля

- `page.json`, `booking.json`, `services.json`, `contact.json`, `about-us.json`: Определения страниц.
- `sections/*.json`: `JSON`-файлы отдельных секций.
- `code/BarberAndTattooLandingPage.php`: Минимальный `PHP`-класс модуля, наследующий `App\AiRudeDepot\App\App`.
- `assets/`: Статические ресурсы (изображения и т.д.).
- `_i/`, `data/`: Метаданные установщика и (возможно) статичные данные.

Подробное описание структуры кода модуля см.
в [Структура Директорий Модуля](../../json-ui/module-installation/directory-structure.md).

## Установка и использование

Процесс установки стандартный для модулей `JSON UI` через `ModuleInstaller`.

<!-- ```php
// Пример установки
$installer = new ModuleInstaller();
$installer->install('landing-main-page');
``` -->

После установки страницы модуля будут доступны по соответствующим роутам (например, `/landing-main-page/page`,
`/landing-main-page/booking` и т.д.).

## Настройка и кастомизация

В текущей реализации настройка модуля **ограничена прямым редактированием `JSON`-файлов**:

- **Контент:** Тексты, заголовки, описания услуг, данные команды и т.д. редактируются непосредственно в файлах `*.json`
  страниц и секций.
- **Изображения:** Пути к изображениям (`src`) указываются в компонентах `Image` внутри `JSON`-файлов.
- **Стили:** Основная стилизация задается через классы `Tailwind CSS` в `props.class`. Дополнительные стили могут быть
  добавлены через `props.style`.

**⚠️ Важно:** В этой реализации **отсутствуют** централизованные файлы `data.json`, `theme.json`, `analytics.json` для
упрощенной конфигурации. Конфигурация и контент **встроены** в основные `JSON`-файлы структуры.

## Формы

Модуль содержит `JSON`-структуру для форм записи (`booking.json` и его включения) и контактов (`contact.json` и его
включения). Однако эти формы **не являются функциональными**:

- Кнопки отправки (`Button` с `label` "Записатись" или "Надіслати повідомлення") **не имеют** `customHooks` или других
  механизмов для отправки данных.
- Они служат только для **визуального представления** интерфейса.
- Для реализации функциональных форм требуется доработка с использованием серверных `actions` и `FormManager`.

## Примеры интерактивности

Модуль использует следующие `customHooks`:

### `navigateTo` + `route` (Навигация по страницам модуля)

<!-- ```json
// Пример: Кнопка "Записатися" в хедере или CTA
{
  "type": "Button",
  "props": { "label": "Записатися", ... },
  "customHooks": {
    "click": [
      {
        "action": "navigateTo",
        "data": { "route": "/landing-main-page/booking" }
      }
    ]
  }
}
``` -->

### `navigateTo` + `fragment` (Прокрутка к секции)

<!-- ```json
// Пример: Кнопка навигации на странице Услуг
{
  "type": "Button",
  "props": { "label": "Барбер-послуги", ... },
  "customHooks": {
    "click": [
      {
        "action": "navigateTo",
        "data": { "fragment": "barber-services" }
      }
    ]
  }
}
``` -->

### `navigateTo` + `url` (Внешняя ссылка)

<!-- ```json
// Пример: Кнопка "Відкрити в Google Maps"
{
  "type": "Button",
  "props": { "label": "Відкрити в Google Maps", ... },
  "customHooks": {
    "click": [
      {
        "action": "navigateTo",
        "data": { "url": "https://maps.google.com", "target": "_blank" }
      }
    ]
  }
}
``` -->

### `toggleClass` (Переключение видимости)

<!-- ```json
// Пример: Кнопка мобильного меню в хедере
{
  "type": "Button",
  "props": { "icon": "pi pi-bars", "class": "lg:hidden ..." },
  "customHooks": {
    "click": [
      {
        "action": "toggleClass",
        "data": { "selector": ".mobile-menu", "class": "hidden" }
      }
    ]
  }
}
``` -->

### `Link` + `href` (Стандартная навигация)

<!-- ```json
// Пример: Ссылка в футере
{
  "type": "Link",
  "props": {
    "href": "/landing-main-page/services",
    "label": "Послуги",
    "class": "text-gray-300 ..."
  }
}
``` -->

Дополнительная информация о действиях доступна
в [Справочнике UI Команд](mdc:../../../../ui/json-ui/commands-and-operations/ui-documentation.md).

## Связь с другими модулями

Текущая версия модуля Landing Page является самодостаточной и **не предполагает глубокой интеграции** с другими
модулями, требующими сложной серверной логики (например, `Login Form`, `Primary Form`). Для реализации такой интеграции
потребуются доработки.

## Известные ограничения текущей реализации

1. Отсутствие функциональных форм.
2. Отсутствие серверной логики и обработки данных в этом модуле.
3. Контент и стили в основном встроены в `JSON`-структуру, что усложняет кастомизацию без правки кода.
4. Ограниченная интерактивность (только базовая навигация и UI-эффекты).

Более подробно см. в [Известные проблемы](mdc:./known-issues.md).
