# Пользовательский код в модуле Landing Page

## Обзор

Модули типа Landing Page, такие как `storage/aiInstaller/landing-main-page/`, фокусируются на *декларативном описании
интерфейса* с помощью `JSON` и стандартных компонентов `JSON UI`. Пользовательский `PHP`-код в таких модулях обычно
минимален.

## Структура директории `code/`

В модуле `landing-main-page` директория `code/` содержит основной `PHP`-класс модуля. Этот класс является точкой входа,
необходимой для регистрации модуля в системе и определения его расположения.

<!-- ```bash
storage/aiInstaller/landing-main-page/
└── code/
    └── BarberAndTattooLandingPage.php  # Основной PHP класс модуля
``` -->

### `BarberAndTattooLandingPage.php`

Этот класс наследуется от базового `App\\AiRudeDepot\\App` (см. `app/AiRudeDepot/App.php`) и, как минимум, определяет
имя папки модуля через свойство `$folder`.

**Важно:** Хотя класс использует пространство имен `App\\AiRudeDepot\\Modules`, сам файл физически находится **внутри
директории модуля**: `storage/aiInstaller/landing-main-page/code/BarberAndTattooLandingPage.php`. Он не создается
автоматически в основной структуре `app/`.

В простых модулях типа Landing Page этот класс обычно **не содержит** сложной логики. Методы вроде `actions()` или
`moduleRun()` либо не переопределяются, либо содержат базовую логику для инициализации. Основная логика отображения и
простейших взаимодействий определяется в `JSON`-файлах.

<!-- ```php
<?php
namespace App\\AiRudeDepot\\Modules; // Пространство имен
use App\\AiRudeDepot\\App;

// Файл находится в: storage/aiInstaller/landing-main-page/code/
class BarberAndTattooLandingPage extends App
{
    // Определяет директорию модуля для ядра системы
    public $folder = 'landing-main-page';

    // В Landing Page модулях эти методы обычно не содержат сложной логики.
    // Основная работа происходит через рендеринг JSON-файлов страниц/секций.
    // public function actions() { ... }
    // public function moduleRun() { ... }
}
``` -->

## Отсутствие сложной серверной логики

- **Серверный `PHP`:**
    - В модулях Landing Page обычно отсутствует обработка серверных действий (т.е. директория `actions/` с `JSON`/`PHP`
      файлами не используется или используется минимально).
    - Нет сложной логики обработки данных или взаимодействия с `БД` внутри `PHP`-класса модуля.
    - Пользовательский `PHP`-код в `code/` минимален и служит в основном для регистрации.

Для сравнения, в более сложных модулях, таких как `Primary Form`, `PHP`-класс в директории `code/` может содержать
значительную логику, включая определение серверных `actions`, валидацию, взаимодействие с моделями и т.д. (Пример не
найден).

## Заключение

При работе с модулями Landing Page основной фокус делается на `JSON`-конфигурации (`layout.json`, `page.json`,
`sections/*.json`, `data/*.json`). Пользовательский код в `code/` ограничивается стандартным классом модуля для его
регистрации. Для реализации сложной логики (функциональные формы, серверные действия) следует либо использовать
серверные `actions` (если они поддерживаются текущей архитектурой для Landing Page), либо разрабатывать модули других
типов (например, `Primary Form`).
