## (Innactive standard/recheck) JSON Schema для шаблонов страниц

Этот документ описывает принципы и структуру JSON-схем, используемых для определения шаблонов страниц в системе
динамического UI. JSON-схема служит контрактом, определяющим структуру данных, необходимую для рендеринга страницы,
включая компоненты, их свойства, взаимосвязи и поведение.

### Основные принципы

1. **Декларативность**: JSON-схема должна быть декларативной, описывая желаемый результат (структуру UI) вместо
   императивных инструкций о том, как его достичь.
2. **Компонентная структура**: UI описывается как иерархия компонентов. Каждый компонент представлен объектом JSON,
   определяющим его тип, свойства и дочерние компоненты.
3. **Переиспользуемость**: Схемы должны быть разработаны с учетом переиспользования компонентов и шаблонов. Это
   достигается за счет модульности и параметризации.
4. **Расширяемость**: Схема должна быть расширяемой, позволяя добавлять новые типы компонентов и свойства без нарушения
   существующей структуры.
5. **Читаемость и понятность**: JSON должен быть легко читаемым и понятным как для разработчиков, так и для системы,
   обрабатывающей его.
6. **Валидация**: Схема должна быть валидируемой, чтобы можно было автоматически проверять корректность
   JSON-конфигурации перед рендерингом.

### Структура JSON-схемы

Основная структура JSON-схемы для шаблона страницы представляет собой объект, который может содержать следующие ключевые
свойства:

* **`type` (String)**:  Обязательное свойство, указывающее тип компонента. Это строковое значение, которое
  сопоставляется с зарегистрированным компонентом Vue (например, `"Grid"`, `"Column"`, `"InputText"`,
  `"Button"`).
* **`props` (Object)**:  Необязательное свойство, представляющее собой объект свойств (props), которые будут переданы
  компоненту Vue. Эти свойства могут включать HTML-атрибуты, стили, данные и другие параметры, специфичные для
  компонента.
* **`children` (Array)**:  Необязательное свойство, массив JSON-объектов, описывающих дочерние компоненты. Используется
  для создания иерархической структуры UI. Для компонентов-контейнеров (таких как `Grid`, `div`, `Card`).
* **`items` (Array)**:  Аналогично `children`, но может использоваться для компонентов, которые отображают список
  элементов, таких как `Menu`, `TreeSelect`, `PathBreadcrumb`.
* **`model` (Object)**:  Свойство для связывания компонента с данными формы. Используется в основном для VModel
  компонентов. Содержит следующие под-свойства:
    * **`form` (String)**: Имя формы, к которой привязан компонент.
    * **`field` (String)**: Имя поля в форме, к которому привязано значение компонента.
    * **`options` (Array)**: (Опционально) Массив опций для компонентов выбора (например, `Select`, `TreeSelect`).
    * **`optionLabel` (String)**: (Опционально) Имя свойства в объекте опции, которое будет использоваться в качестве
      метки.
    * **`optionValue` (String)**: (Опционально) Имя свойства в объекте опции, которое будет использоваться в качестве
      значения.
    * **`default` (Any)**: (Опционально) Значение по умолчанию для поля модели.
* **`customHooks` (Object)**:  Объект для определения обработчиков событий для компонента. Ключи объекта - это имена
  событий (например, `"click"`, `"change"`, `"mouseover"`), а значения - массивы действий, которые нужно выполнить при
  возникновении события. Каждое действие описывается объектом с свойствами `action` и `data`.
    * **`action` (String)**: Имя действия, которое нужно выполнить (например, `"sendData"`, `"changeAttribute"`,
      `"openDialog"`, `"copyToClipboard"`).
    * **`data` (Object)**: Объект данных, передаваемый действию. Содержимое `data` зависит от типа действия.
* **`validation` (Object)**:  Объект для определения правил валидации для VModel компонентов. Содержит правила валидации
  и сообщения об ошибках(не имплементировано).
    * **`required` (Boolean)**: Указывает, является ли поле обязательным для заполнения.
    * **`min` (Number)**, **`max` (Number)**, **`minLength` (Number)**, **`maxLength` (Number)**, **`pattern` (String)**
      и другие правила валидации, поддерживаемые системой валидации.
    * **`message` (String)**: Сообщение об ошибке валидации.
* **`name` (String)**:  Имя компонента или формы. Используется для идентификации компонента в форме или для управления
  состоянием.
* **`vAddress` (String)**:  Уникальный адрес компонента в дереве компонентов. Используется для точного управления
  компонентом через `ActionManager`(будет заменен на `id`).
* **`disabled` (Boolean)**:  Указывает, должен ли компонент быть отключен.

### Примеры структуры JSON-схемы

**Простая кнопка:**

```json
{
  "type": "Button",
  "props": {
    "label": "Кнопка",
    "icon": "pi pi-check",
    "class": "p-button-primary"
  },
  "customHooks": {
    "click": [
      {
        "action": "sendData",
        "data": { "sendTo": "buttonClicked", "payload": "Кнопка была нажата" }
      }
    ]
  }
}
```

**Форма с текстовым полем ввода:**

```json
{
  "type": "Form",
  "name": "user-form",
  "props": { "class": "card flex flex-col gap-4" },
  "children": [
    {
      "type": "InputText",
      "name": "userName",
      "props": { "label": "Имя пользователя", "placeholder": "Введите имя" },
      "model": { "form": "user-form", "field": "name", "default": "" },
      "validation": { "required": true, "minLength": 3, "message": "Имя должно быть не менее 3 символов" }
    },
    {
      "type": "Button",
      "props": { "label": "Сохранить", "class": "p-button-success" },
      "customHooks": {
        "click": [
          { "action": "submitForm", "data": { "form": "user-form" } }
        ]
      }
    }
  ]
}
```

**Макет страницы с Grid и Card:**

```json
{
  "type": "Grid",
  "children": [
    {
      "type": "Column",
      "props": { "class": "col-span-12 md:col-span-6" },
      "children": [
        {
          "type": "Card",
          "props": { "header": "Первая карточка" },
          "children": [
            { "type": "div", "props": { "content": "Содержимое первой карточки" } }
          ]
        }
      ]
    },
    {
      "type": "Column",
      "props": { "class": "col-span-12 md:col-span-6" },
      "children": [
        {
          "type": "Card",
          "props": { "header": "Вторая карточка" },
          "children": [
            { "type": "div", "props": { "content": "Содержимое второй карточки" } }
          ]
        }
      ]
    }
  ]
}
```

### Лучшие практики

* **Модульность**: Разделяйте сложные схемы на более мелкие, переиспользуемые фрагменты !!!! сюда ссылку на операции
  инклую и адд. Используйте `children` или
  `items` для структурирования компонентов.
* **Консистентность**: Придерживайтесь единого стиля и структуры во всех схемах. Используйте одни и те же имена свойств
  и типы данных.
* **Документирование**: Документируйте каждую схему, описывая ее назначение, структуру и свойства.

### Заключение

JSON-схема для шаблонов страниц является мощным инструментом для динамического создания пользовательских интерфейсов.
Понимание принципов и структуры JSON-схем, а также следование лучшим практикам, позволит вам создавать гибкие,
расширяемые и легко поддерживаемые UI для вашего приложения.
