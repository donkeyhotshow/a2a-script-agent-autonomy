# Документация: Модуль `question-to-user` (QTU) v5

## 1. Назначение и Архитектура

### 1.1. Основное назначение

Модуль `question-to-user` (QTU) версии v5 предназначен для динамического отображения наборов вопросов пользователю и
сбора его ответов. Ключевой особенностью является обработка массива определений вопросов (из `data/question_sets/` или
переданного через сценарий) и его преобразование в интерактивную форму в пользовательском интерфейсе. Модуль не
занимается генерацией самих вопросов или сложной логикой их ветвления; он служит UI-интерфейсом для заранее
подготовленных данных.

ИИ (через системные сценарии) может:

1. Предоставлять структурированный набор вопросов для отображения модулем.
2. Получать ответы пользователя, сохраненные модулем, для дальнейшего анализа.

Прямого взаимодействия "ИИ-в-модуле" для интерпретации ответов или изменения вопросов на лету в текущей версии v5 не
предусмотрено; все интеллектуальные операции вынесены на уровень сценариев и специализированных AI-сервисов.

### 1.2. Архитектурные принципы

- **Декларативный UI**: Пользовательский интерфейс (страницы, секции, шаблоны) описывается статически в JSON-файлах.
  Логика отображения (например, какие поля формы создавать) инкапсулирована в общем UI-движке фреймворка, который
  обрабатывает эти JSON-определения.
- **Stateless Actions**: Серверные действия (`actions/*.json`) оперируют данными через DataHub (`buffer:`, `file:`,
  `input:`) и не изменяют UI-файлы напрямую. Они могут подготавливать данные для UI (например, генерировать
  JSON-структуру формы в буфер), но сам рендеринг и обновление UI выполняет клиентская часть фреймворка.
- **Динамическая генерация форм**: Наборы вопросов (массивы JSON-объектов) обрабатываются действием
  `load-question-set.json`, которое генерирует соответствующую UI-структуру для отображения в виде формы. Эта структура
  помещается в буфер (например, `buffer:qtu.generatedUI`), откуда ее подхватывает UI-компонент для рендеринга.
- **Совместимость версий**: Модуль v5 может сосуществовать с другими версиями. Системный механизм сборки/установки
  определяет, какая версия активна. Команда `php artisan module:merge question-to-user` используется для управления
  версиями и возможной дедупликации общих ресурсов при необходимости.

## 2. Основной сценарий использования

1. **Загрузка набора вопросов**:
    * Пользователь (или система через автоматический запуск) инициирует действие `load-question-set.json`.
    * Это действие считывает определения вопросов из указанного источника (например,
      `file!question-to-user/data/question_sets/default-set`).
    * На основе этих определений `load-question-set.json` генерирует JSON-структуру UI-компонентов (поля ввода,
      выпадающие списки и т.д.).
    * Сгенерированная UI-структура помещается в `buffer:qtu.generatedUI`.
    * Эта структура также может быть сохранена в файл (например,
      `file!question-to-user/data/generated/question-ui.json`) для отладки или кеширования.

2. **Отображение вопросов**:
    * Страница `pages/page.json` включает секцию `sections/main-qtu-interface.json`.
    * `main-qtu-interface.json` содержит элемент (например, через `operation: "include"`) который рендерит содержимое
      `buffer:qtu.generatedUI` (обычно через `templates/question-area.json`).
    * UI фреймворка отображает форму с вопросами пользователю.

3. **Ввод ответов**:
    * Пользователь заполняет поля формы. Ответы привязываются к модели формы (например, `mainQtuResponseForm`).

4. **Сохранение ответов**:
    * Пользователь нажимает кнопку "Сохранить".
    * Это инициирует действие `save-current-answers.json`.
    * Действие считывает все данные из формы (например, `input:all` из `mainQtuResponseForm`).
    * Данные сохраняются в файл (например, `file!question-to-user/data/user_answer_sets/current_answers`).

5. **Очистка ответов**:
    * Пользователь нажимает кнопку "Очистить".
    * Это инициирует действие `clear-current-answers.json`.
    * Действие может очистить файл с сохраненными ответами и перезапустить `load-question-set.json` для отображения
      чистой формы.

## 3. Ключевые actions и их назначение

* **`load-question-set.json`**:
    * **Вход**: Может принимать ID набора вопросов или использовать путь по умолчанию.
    * **Логика**:
        1. Читает JSON-файл с определениями вопросов (массив объектов).
        2. Для каждого вопроса в массиве генерирует соответствующий UI-компонент (InputText, Select, Checkbox и т.д.) на
           основе `type`, `label`, `modelField` и других свойств из определения вопроса.
        3. Собирает массив сгенерированных UI-компонентов.
    * **Выход**: Помещает массив UI-компонентов в `buffer:qtu.generatedUI`. Сохраняет этот же массив в
      `file!question-to-user/data/generated/question-ui.json`.

* **`save-current-answers.json`**:
    * **Вход**: Данные из формы (например, `input:formName` из `mainQtuResponseForm`).
    * **Логика**:
        1. Получает данные из формы.
        2. Сохраняет данные в файл (например, `file!question-to-user/data/user_answer_sets/current_answers`).
    * **Выход**: Сохраняет ответы в файл.

* **`clear-current-answers.json`**:
    * **Вход**: Нет.
    * **Логика**:
        1. Очищает файл с сохраненными ответами (например,
           `file!question-to-user/data/user_answer_sets/current_answers`).
        2. Перезапускает `load-question-set.json` для отображения чистой формы.
    * **Выход**: Очищает файл с ответами и обновляет форму.
