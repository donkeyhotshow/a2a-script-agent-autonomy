# QTU-BulkConfirmPage: Проектирование

## Назначение
Страница для группового подтверждения или отклонения серии вопросов/действий, связанных с задачами или сериями задач.

---

## Best Practices
- Для bulk-операций использовать отдельные секции и шаблоны (см. playground/templates).
- Для группировки — использовать входящие данные с предустановленными группами (см. playground).
- Для статусов и комментариев — отдельные поля в каждом вопросе (см. page, playground).
- Для динамических секций использовать operation: include (см. page/sections, playground/sections).

### Пример секции с dynamic include
```json
{
  "type": "section",
  "props": { "title": "Группы вопросов" },
  "children": [
    { "operation": "include", "source": "file!qtu/sections/bulk-confirm-group-list.json" }
  ]
}
```

---

## Пример структуры данных (view-only)
```json
{
  "type": "Page",
  "props": { "title": "Bulk Confirm QTU" },
  "content": [
    {
      "type": "section",
      "props": { "title": "Группы вопросов" },
      "children": [
        { "operation": "include", "source": "file!qtu/sections/bulk-confirm-group-list.json" }
      ]
    }
  ]
}
```

---

## Расширяемость
- Для добавления новых типов bulk-групп — добавить шаблон в sections и использовать operation: include.
- Для динамических секций — использовать только operation: include.

## Шаблон формы (view-only)

**BulkConfirmView**
- Входные данные: массив групп вопросов с полями (groupId, taskInfo, questions[], files, progress, errors, ...)
- Для каждой группы:
  - Краткая информация о задаче (taskInfo)
  - Список вопросов (questions[]), для каждого:
    - Текст вопроса
    - Причина отклонения (если есть)
    - Комментарий к действию (если есть)
  - Ссылки на файлы (если есть)
  - Прогресс по обработке группы (например, 2/5 обработано)
  - Кнопка отклонить группу (с подтверждением)
  - Кнопка отменить действие (если поддерживается)
  - Уведомления об ошибках (если есть)
- Нет ручного выбора вопросов, поиска, сортировки, drag-and-drop
- Мобильная адаптивность обязательна
