This file defines the validation schema for "Instructions" components, which are sequences of operations typically used in server-side actions (e.g., `actions/*.json`) and commands.

Key aspects of this schema:

*   **`componentName`**: "Instructions".
*   **`tags`**: Requires metadata tags, including `keywords` (array of strings, min 10 items) and an `ai_summary` (string, minLength 10). A `features` array is optional.
*   **`instructions` (array, required)**: This is the core, an array of individual instruction objects. Each instruction object has:
    *   **`action` (string, required)**: The type of operation. The schema lists specific allowed actions: `"comment"`, `"coment"` (likely a typo for comment), `"update"`, `"save"`, `"print_r"`, `"for"`, `"add"`, `"remove"`, `"call"`, `"return"`.
    *   **`disabled` (boolean, optional)**: If true, the instruction is skipped.
    *   **`condition` (string or array, optional)**: Determines if the instruction runs. Can be a DataHub path to a boolean or a more complex expression (array syntax for compound logic like 'and', 'isEmpty').
    *   **Common properties**: `from` or `address` (string or array, for data source), `to` (string, for data destination), `value` (any type, for literal values). These are generally optional, their requirement depends on the specific `action`.
    *   **`batch` (array or object, optional)**: Specifically mentioned for the `update` action, allowing multiple update operations to be grouped. The items within a batch can also have properties like `action`, `condition`, `from`, `to`, `value`.
    *   **Nested `instructions` (array, optional)**: Allows for sub-routines or grouped actions within an instruction, essentially making the structure recursive.
    *   Other optional fields like `key`, `with`, `comment`, `_comment`, `target`.

The schema includes examples and links to further documentation for certain properties like `condition`. It aims to ensure that instruction sequences are well-formed and use recognized operations and parameters.
