Привет!

Обновление по задаче улучшения скрипта `main-work.ps1` и обработки ошибок:

В этой сессии мы сфокусировались на улучшении структуры скрипта `main-work.ps1` и обработке ошибок, связанных с вызовом скрипта.

Ключевые моменты:
1.  Исследовали проблему с некорректным синтаксисом параметров (например, `-параметр=значение` вместо `-параметр значение`). Обнаружили, что PowerShell перехватывает такие ошибки до начала выполнения скрипта и не позволяет реализовать "дружелюбный" перехват на ранней стадии внутри самого скрипта.
2.  Добавили валидацию *после* обработки параметров PowerShell, чтобы скрипт выдавал понятное сообщение, если обязательные параметры (например, `-ScenarioId` для режимов `RunScenario` или `ShowScenario`) пропущены.
3.  **Выполнили рефакторинг:** Вся основная логика диспетчеризации режимов, находившаяся в большом блоке `switch ($Mode) { ... }` в `main-work.ps1`, была **вынесена в отдельный файл:** `./script/main-work-dispatch.ps1`.
4.  Сам `main-work.ps1` теперь стал "шлюзом". Он загружает начальное состояние, выполняет базовую проверку режима Help/invalid, а затем **вызывает `./script/main-work-dispatch.ps1` через dot-sourcing** внутри блока `try/catch`.
5.  Такая структура обеспечивает верхнеуровневую обработку необработанных исключений, возникающих во время выполнения логики режимов, и улучшает модульность скрипта.

**Итог:** Скрипт `main-work.ps1` теперь более структурирован, а необработанные ошибки из логики режимов будут перехватываться на верхнем уровне с общим сообщением. Валидация пропущенных обязательных параметров также добавлена.

Мы готовы продолжить работу над интеграцией индекса или сфокусироваться на других аспектах системы, возможно, используя новую структуру `main-work.ps1`.

Конец обновления.
