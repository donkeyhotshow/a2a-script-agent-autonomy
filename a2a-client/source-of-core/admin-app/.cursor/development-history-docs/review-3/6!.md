## Предлагаемая методология: "Library-Rules-Validate" (LRV)

Вот усовершенствованный подход для разработки модулей:

### 1. Каждый этап начинается с консультации документации (Library)
- ИИ обязательно читает соответствующие документы перед каждым этапом
- Фокус на применимых стандартах и примерах из эталонных модулей
- Без этого шага невозможно двигаться дальше

### 2. Правила определяют границы реализации (Rules)
- Четкое применение правил валидации на каждом шаге
- Приоритет имеют правила из установленных стандартов, не догадки
- Запрет на "креативные решения" в обход стандартов

### 3. Валидация как обязательный рубеж (Validate)
- После каждого изменения - валидация
- Отказ от перехода к следующему шагу без прохождения валидации
- Документирование решений после успешной валидации

## Пошаговый процесс:

1. **Подготовка (Prep-LRV)**
   - Чтение `module-structure-and-installation.md` и `StrictModuleChecklist.md`
   - Сканирование эталонных модулей (primary-form, login-form)
   - Формирование структурной карты будущего модуля

2. **Структура (Structure-LRV)**
   - Чтение `file-structure.md` и соответствующих разделов документации
   - Создание всех необходимых директорий и базовых файлов
   - Валидация структуры через соответствующие инструменты

3. **Метаданные (Meta-LRV)**
   - Чтение документации по _i/ и meta.json
   - Настройка всех метаданных модуля
   - Валидация метаданных

4. **UI-компоненты (UI-LRV)**
   - Изучение `component-map.json` и стандартов UI
   - Имплементация UI-компонентов с опорой только на поддерживаемые типы
   - Валидация каждого компонента

5. **Данные (Data-LRV)**
   - Чтение документации по работе с данными и DataHub
   - Разработка структур данных и моделей
   - Валидация структур данных

6. **Действия (Actions-LRV)**
   - Изучение `server-actions-reference.md`
   - Разработка действий строго по документации
   - Валидация всех actions

7. **Интеграция (Integration-LRV)**
   - Чтение документации по интеграции модулей
   - Связывание всех компонентов
   - Финальная валидация модуля целиком

8. **Документирование (Doc-LRV)**
   - Обновление всей документации модуля
   - Фиксирование усвоенных уроков
   - Создание чеклиста для следующих итераций

## Ключевые улучшения:

1. **Библиотечный подход**: ИИ всегда сначала идет в "библиотеку" (документацию)
2. **Строгие границы**: работаем только в рамках валидных конструкций
3. **Пошаговая валидация**: не переходим к следующему шагу без валидации текущего
4. **Документирование решений**: фиксируем все успешные паттерны
5. **Эталонная сверка**: постоянно сверяемся с уже работающими модулями
