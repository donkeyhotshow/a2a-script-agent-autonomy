# Анализ модулей admin-app: primary-form, login-form и landing-main-page

## 1. Общая структура модулей

Все три модуля следуют стандартной модульной архитектуре admin-app с четко определенной структурой директорий, которая соответствует требованиям установщика и соглашениям системы.

### Ключевые принципы организации модулей

- **Версионирование**: Модули организованы с использованием директорий версий (`v1`, `v2`), что позволяет постепенно наращивать функциональность
- **Стандартизированная структура**: Все модули содержат необходимые директории: `_i/`, `pages/`, `actions/`, `templates/`, `data/` и т.д.
- **Инсталляционные метаданные**: Каждый модуль имеет `_i/meta.json` с информацией для установщика
- **JSON-ориентированная UI**: Интерфейсы определены в декларативном формате JSON

## 2. Модуль primary-form

### Назначение и функциональность

Primary Form представляет собой базовый модуль для работы с формами в приложении, предоставляя типовые шаблоны форм и обработки данных.

### Особенности структуры

- Наличие директорий `v1/` и `v2/` для пошагового развития модуля
- Структурированная организация с четким разделением представления (`pages/`, `templates/`), данных (`data/`) и логики (`actions/`, `commands/`)
- Есть документация по модульной разработке (storage-code-structure.md), описывающая принципы версионированной разработки модулей

### Ключевые компоненты

- `v1/_i/meta.json`: Определяет название, описание, версию и зависимости модуля
- `v1/code/`: Содержит PHP-классы для обработки форм
- `v1/programs/`: Специфичные для модуля программные компоненты
- `v1/data/`: Шаблоны данных форм и вспомогательные структуры

## 3. Модуль login-form

### Назначение и функциональность 

Login Form - это модуль аутентификации, предоставляющий интерфейс входа и логику обработки аутентификации пользователей.

### Особенности структуры

- Полная структура модуля с директориями для всех компонентов: UI, логики, данных, валидации
- Четкое разделение между страницами (`pages/`), действиями (`actions/`), шаблонами (`templates/`) и состоянием (`state/`)
- Наличие `docs/` для документации модуля
- Включает `validations/` для правил валидации форм

### Ключевые компоненты

- `v1/pages/index.json`: Определяет страницу входа с формой, включающей поля логина и пароля
- `v1/actions/login-form/login.json`: Содержит инструкции для обработки действия входа в систему:
  - Получение входных данных
  - Вызов команды аутентификации
  - Обновление сессии для аутентифицированного пользователя
  - Возврат сообщения об успешной аутентификации

## 4. Модуль landing-main-page

### Назначение и функциональность

Landing Main Page - это модуль целевой страницы для маркетплейса барбершопа, который предоставляет визуально привлекательный интерфейс с множеством секций.

### Особенности структуры

- Модуль переходит от концепции барбершопа/тату студии к магазину косметики для мужчин
- Разделение контента на секции для легкой композиции страницы
- Использование операций включения (`include`) для сборки страницы из модульных секций

### Ключевые компоненты

- `v2/page.json`: Основная структура страницы, которая включает множество секций через операцию `include`
- `v2/sections/`: Содержит секции, которые инклюдятся в основную страницу
- `json-template-schema.md`: Описывает стандарты JSON-схем для шаблонов страниц:
  - Определяет структуру компонентов с полями `type`, `props`, `children`, `model`, `customHooks` и т.д.
  - Предоставляет примеры использования компонентов: кнопки, формы, сетки
  - Определяет лучшие практики для модульности и консистентности

## 5. Сравнительный анализ модулей

### Общие черты

- Все модули следуют стандартизированной структуре директорий
- Каждый модуль имеет метаданные `_i/meta.json` для установки
- Все используют JSON для определения UI и логики
- Везде используется модульный подход с разделением на компоненты

### Различия в функциональности

- **primary-form**: Базовый модуль для работы с формами, более общего назначения
- **login-form**: Специализированный модуль для аутентификации пользователей
- **landing-main-page**: Фокусируется на презентационной стороне с богатым визуальным представлением

### Различия в подходе к разработке

- **primary-form**: Акцент на поэтапной разработке через версионирование
- **login-form**: Акцент на функциональности аутентификации и безопасности
- **landing-main-page**: Акцент на композиции страницы из секций и визуальной привлекательности

## 6. Интеграция с архитектурой admin-app

Все три модуля идеально интегрируются с архитектурой admin-app:

- Используют единую систему адресации в DataHub через операции `include`
- Действия определены в формате JSON-инструкций, обрабатываемых StorageHelper
- Представление определено в JSON-формате для рендеринга через RenderJson.vue
- Метаданные модулей совместимы со стандартами установщика

Эти модули демонстрируют мощь и гибкость JSON-ориентированной архитектуры admin-app, позволяя создавать сложные интерфейсы и бизнес-логику декларативным способом без необходимости в глубоком программировании.
