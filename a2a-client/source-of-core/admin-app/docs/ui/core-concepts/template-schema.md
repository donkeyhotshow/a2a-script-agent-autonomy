# Схемы шаблонов JSON UI

[[toc]]

> **Важно:** Перед созданием новых компонентов или шаблонов рекомендуется ознакомиться
> с [чек-листом стандартов UI компонентов](../../../checklists/component-standards.md), чтобы обеспечить соответствие
> всем
> требованиям проекта.

Схемы шаблонов — это основной способ определения пользовательского интерфейса в JSON UI. Они представляют собой
JSON-структуры, которые описывают компоненты интерфейса, их свойства, вложенность и поведение.

Все поддерживаемые типы элементов UI и их сопоставление с категориями рендеринга (например, \\\\\Component\\\\\, \\\\\Container\\\\\, \\\\\VModel\\\\\, \\\\\ComplexContainer\\\\\, \\\\\Customs\\\\\, \\\\\Tag\\\\\) определены в файле
[\\\\\install-modules/aiCore/js/component-map.json\\\\\](../../../../../install-modules/aiCore/js/component-map.json). Этот файл является авторитетным источником для проверки существования и категории любого типа компонента.

## Основные концепции

Схема шаблона в JSON UI состоит из следующих ключевых элементов:

- **Тип элемента** - определяет, какой компонент будет использоваться (например, \\\\\div\\\\\, \\\\\InputText\\\\\, \\\\\Card\\\\\). Должен соответствовать одному из ключей в \\\\\component-map.json\\\\\ или быть стандартным HTML-тегом.
- **Свойства (\\\\\props\\\\\)** - настройки и параметры компонента, передаются через объект \\\\\props\\\\\. Свойства статичны в V1; динамическое обновление UI происходит через получение новой JSON-структуры с сервера.
- **Содержимое (\\\\\children\\\\\, \\\\\content\\\\\)** - вложенные элементы (\\\\\children\\\\\) или текстовое содержимое (\\\\\content\\\\\).
- **Обработчики событий (\\\\\customHooks\\\\\)** - привязка клиентских действий к событиям компонента, обрабатывается \\\\\hub.actionManager\\\\\. Часто используется для вызова серверных действий через \\\\\sendData\\\\\.
- **Модель данных (\\\\\model\\\\\)** - связывание компонента ввода с \\\\\hub.formManager\\\\\ для автоматического обновления состояния формы на клиенте.

### Базовая структура

\\\\\\\\\\\\\\\javascript
{
  //?////type//?////: //?////имя-компонента//?////,
  //?////props//?////: {
    // свойства компонента
  },
  //?////children//?////: [
    // вложенные элементы
  ],
  //?////customHooks//?////: {
    // обработчики событий
  },
  //?////model//?////: { // для компонентов ввода
    //?////form//?////: //?////имя-формы//?////,
    //?////field//?////: //?////имя-поля//?////
  }
}
\\\\\\\\\\\\\\\

## Типы элементов и их категории рендеринга

Типы элементов, используемые в JSON UI, определены в [\\\\\component-map.json\\\\\](../../../../../install-modules/aiCore/js/component-map.json) и разделены на категории, которые соответствуют компонентам-оберткам, используемым в конвейере рендеринга (см. \\\\\rendering-pipeline.md\\\\\).

### 1. Элементы категории \`Tag\`

Эти типы соответствуют **подмножеству** базовых HTML-тегам из фиксированного списка и рендерятся компонентом \`Tag.vue\`. Если тип не входит в этот список, будет использован тег \`div\` по умолчанию.

```
pre, h1, h2, h3, h4, h5, h6, p, ul, li, img, span, table, tr, td, th, div
```

*Источник: Метод \`getComponentName()\` в \`resources/common/js/Elements/Primevue/Containers/Tag.vue\` (список \`tag_list\`) и [\`component-map.json\`](../../../../../install-modules/aiCore/js/component-map.json) где \`//?////type//?////: //?////Tag//?////\`*

> **Примечание:** Для полного и актуального списка элементов категории Tag, включая все поддерживаемые HTML-теги, всегда сверяйтесь с файлом [component-map.json] и кодом компонента Tag.vue.

### 2. Элементы категории \`Component\`

Эти типы соответствуют простым компонентам, рендерятся компонентом \\\\\Component.vue\\\\\.

\\\\\\\\\\\\\\\
//?////button//?////, //?////avatar//?////, //?////buttonmenu//?////, //?////datepicker//?////, //?////divider//?////, //?////icon//?////, //?////image//?////, //?////listbox//?////, //?////logo//?////, //?////breadcrumb//?////
\\\\\\\\\\\\\\\

*Источник: [\`component-map.json\`](../../../../../install-modules/aiCore/js/component-map.json) где \`//?////type//?////: //?////Component//?////\`*

> **Примечание:** Для полного и актуального списка элементов категории Component всегда сверяйтесь с файлом [component-map.json].

### 3. Элементы категории \`Container\`

Эти типы соответствуют компонентам-контейнерам для группировки элементов, рендерятся компонентом \\\\\Container.vue\\\\\.

\\\\\\\\\\\\\\\
//?////buttongroup//?////, //?////column//?////, //?////fieldset//?////, //?////fluid//?////, //?////form//?////, //?////floatlabel//?////, //?////iconfield//?////, //?////inputgroup//?////, //?////inputgroupaddon//?////, //?////inputicon//?////, //?////panel//?////, //?////row//?////, //?////scrollpanel//?////, //?////label//?////, //?////link//?////, //?////tag//?////
\\\\\\\\\\\\\\\

*Источник: [\`component-map.json\`](../../../../../install-modules/aiCore/js/component-map.json) где \`//?////type//?////: //?////Container//?////\`*

> **Примечание:** Для полного и актуального списка элементов категории Container всегда сверяйтесь с файлом [component-map.json].

### 4. Элементы категории \`VModel\`

Эти типы соответствуют компонентам ввода, поддерживающим двустороннюю привязку данных через \\\\\model\\\\\ и \\\\\hub.formManager\\\\\. Рендерятся компонентом \\\\\VModel.vue\\\\\.

\\\\\\\\\\\\\\\
//?////checkbox//?////, //?////inputtext//?////, //?////input//?////, //?////knob//?////, //?////password//?////, //?////textarea//?////, //?////select//?////, //?////selectbutton//?////, //?////treeselect//?////
\\\\\\\\\\\\\\\

*Источник: [\`component-map.json\`](../../../../../install-modules/aiCore/js/component-map.json) где \`//?////type//?////: //?////VModel//?////\`*

> **Примечание:** Для полного и актуального списка элементов категории VModel всегда сверяйтесь с файлом [component-map.json].

### 5. Элементы категории \`ComplexContainer\`

Эти типы соответствуют сложным компонентам-контейнерам, часто имеющим специфическую структуру свойств (\\\\\items\\\\\) или дополнительные функции (\\\\\dialogConfig\\\\\). Рендерятся компонентом \\\\\ComplexContainer.vue\\\\\.

\\\\\\\\\\\\\\\
//?////accordion//?////, //?////card//?////, //?////carousel//?////, //?////grid//?////, //?////splitter//?////, //?////splitterpanel//?////, //?////steps//?////, //?////tabs//?////, //?////toolbar//?////, //?////drawer//?////, //?////datatable//?////
\\\\\\\\\\\\\\\

*Источник: [\`component-map.json\`](../../../../../install-modules/aiCore/js/component-map.json) где \`//?////type//?////: //?////ComplexContainer//?////\`*

> **Примечание:** Для полного и актуального списка элементов категории ComplexContainer всегда сверяйтесь с файлом [component-map.json].

### 6. Элементы категории \`Customs\`

Эти типы соответствуют кастомным компонентам или тем, которые не вписываются в стандартные категории. Рендерятся компонентом \\\\\Customs.vue\\\\\.

\\\\\\\\\\\\\\\
//?////pathbreadcrumb//?////
\\\\\\\\\\\\\\\

*Источник: [\`component-map.json\`](../../../../../install-modules/aiCore/js/component-map.json) где \`//?////type//?////: //?////Customs//?////\`*

> **Примечание:** Для полного и актуального списка элементов категории Customs всегда сверяйтесь с файлом [component-map.json].

## Проверка Соответствия Стандартам

После создания или модификации шаблонов JSON UI рекомендуется провести проверку на соответствие установленным
стандартам:

1. [Чек-лист стандартов UI компонентов](../../../checklists/component-standards.md) - проверка структуры, именования,
   стилизации и общего качества UI компонентов.
2. [Чек-лист верификации модуля](../../../checklists/module-verification.md) - если компонент является частью модуля,
   убедитесь, что он соответствует общим требованиям к модулям.

Регулярное использование этих чек-листов поможет обеспечить:

- Единообразие кода и интерфейса
- Соответствие принятым в проекте практикам
- Высокое качество пользовательского опыта
- Упрощение поддержки и дальнейшей разработки

Периодически возвращайтесь к чек-листам в процессе разработки, чтобы убедиться, что все требования соблюдаются.
