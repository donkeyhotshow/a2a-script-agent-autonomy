# Документация MySQL операций в JSON UI

## Обзор

Модуль MySQL в JSON UI предоставляет прямой доступ к базе данных MySQL (или совместимой, например, SQLite в тестах),
позволяя выполнять запросы с использованием унифицированного синтаксиса адресов. Этот модуль особенно полезен в случаях,
когда стандартных операций с моделями Eloquent недостаточно, и требуются более сложные запросы или работа с таблицами
без моделей.

Основной класс, отвечающий за эти операции, расположен в `app/AiRudeDepot/StorageDataModules/Mysql.php`. Как и другие
модули хранения, он редко используется напрямую, а доступ к нему осуществляется через классы `DataHub` и `Data`,
используя адреса с префиксом `mysql!`.

## Особенности модуля MySQL

- Прямой доступ к таблицам базы данных через синтаксис адресов.
- Поддержка основных операций Query Builder: SELECT (`find`/`where`), INSERT (неявно), UPDATE (неявно), DELETE (
  `remove`), COUNT (`count`).
- Гибкие параметры для фильтрации (`where`), сортировки (`order`) и ограничения (`limit`) через сегменты пути.
- Взаимодействие через стандартный Laravel Query Builder.

## Формат адресов модуля MySQL (Path-Based)

Адреса для модуля MySQL используют префикс `mysql!` за которым следует имя таблицы и опциональные **сегменты пути**,
определяющие операцию и параметры:

```
mysql!имя_таблицы[/операция][/параметр1/значение1][/параметр2/значение2]...
```

где:

- `имя_таблицы` - имя таблицы в базе данных.
- `/операция` - сегмент, указывающий на тип операции чтения или модификации условия.
- `/параметр/значение` - сегменты для передачи условий `WHERE`, `ORDER BY`, `LIMIT`.

### Ключевые Сегменты Пути

| Сегмент Пути                                 | Описание                                                                                                                                                                                                           | Пример Адреса                                   |
|:---------------------------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:------------------------------------------------|
| (отсутствует)                                | Указывает на таблицу в целом. Используется для **неявного INSERT** при вызове `action: "update"` + `action: "save"`.                                                                                               | `mysql!users`                                   |
| `/find/{id}`                                 | Поиск записи по первичному ключу (`id`).                                                                                                                                                                           | `mysql!products/find/123`                       |
| `/where/{column}/{value}`                    | Добавляет простое условие `WHERE column = value`.                                                                                                                                                                  | `mysql!orders/where/status/pending`             |
| `/where/{col}/{op}/{val}`                    | Добавляет условие `WHERE` с оператором (`eq`, `ne`, `gt`, `lt`, `gte`, `lte`, `like`, `in`, `notin`). **(Примечание: Текущая реализация `StoragePathParser` может поддерживать только `/where/{column}/{value}`)** | `mysql!logs/where/level/ne/info` (Теоретически) |
| `/count`                                     | Подсчет количества записей (без `WHERE`).                                                                                                                                                                          | `mysql!users/count`                             |
| `/count/where/{column}/{value}`              | Подсчет количества записей с условием `WHERE`.                                                                                                                                                                     | `mysql!products/count/where/category_id/5`      |
| `/order/{column}/{direction}`                | Сортировка (`asc` или `desc`).                                                                                                                                                                                     | `mysql!articles/order/published_at/desc`        |
| `/limit/{number}`                            | Ограничение количества записей.                                                                                                                                                                                    | `mysql!comments/limit/10`                       |
| `/limit/{offset}/{number}`                   | Ограничение количества записей со смещением.                                                                                                                                                                       | `mysql!comments/limit/20/10`                    |
| `/where/{col}/{val}/...` (для UPDATE/DELETE) | Определяет записи для **неявного UPDATE** (`action: "update"` + `action: "save"`) или **DELETE** (`action: "remove"`).                                                                                             | `mysql!tasks/where/id/456` (для update/delete)  |

**Важно:**

* Текущая реализация `StoragePathParser::processMysql` может иметь **ограничения** в парсинге сложных сегментов пути (
  например, множественные `where` или операторы, отличные от `=`). Предпочтительным для сложных условий остается формат
  **query string** (`mysql!table?where[...]...`), если он все еще поддерживается парсером как fallback. Однако, эта
  документация фокусируется на **path-based** формате.
* Операции **INSERT** и **UPDATE** являются **неявными** и управляются через последовательность инструкций
  `action: "update"` (для установки данных на адрес) и `action: "save"` (для фактического сохранения).
* Операция **DELETE** выполняется через `action: "remove"` с адресом, указывающим на удаляемую запись.

## Примеры использования в инструкциях `actions`

### Чтение записей (SELECT)

#### Все записи (с лимитом)

```json
[
  {
    "action": "update",
    "from": "mysql!users/limit/50", // Получить первые 50 пользователей
    "to": "output:userList"
  }
]
```

#### Поиск по ID

```json
[
  {
    "action": "update",
    "from": "mysql!products/find/{input:productId}", // ID берется из input
    "to": "output:productDetails"
  }
]
```

#### Выборка с условием `WHERE` и сортировкой

```json
[
  {
    "action": "update",
    // Найти активных пользователей, отсортированных по дате создания
    "from": "mysql!users/where/status/active/order/created_at/desc", 
    "to": "output:activeUsers"
  }
]
```

### Подсчет записей (COUNT)

#### Общее количество

```json
[
  {
    "action": "update",
    "from": "mysql!products/count",
    "to": "output:productCount"
  }
]
```

#### Количество с условием `WHERE`

```json
[
  {
    "action": "update",
    "from": "mysql!products/count/where/category_id/5",
    "to": "output:categoryProductCount"
  }
]
```

### Создание записи (INSERT - неявный)

Данные для вставки передаются в `action: "update"`, а затем вызывается `action: "save"`.

```json
[
  // 1. Установить данные на адрес таблицы
  {
    "action": "update",
    "from": "input:userCreateForm", // Данные из формы
    "to": "mysql!users"            // Адрес указывает только на таблицу
  },
  // 2. Сохранить данные (вызывает INSERT)
  {
    "action": "save",
    "from": "mysql!users"
  },
  // 3. Опционально: обновить UI
  {
    "action": "update",
    "value": "User created!",
    "to": "output:statusMessage" 
    // Примечание: Получение ID созданной записи может потребовать доп. шага
  }
]
```

### Обновление записи (UPDATE - неявный)

Данные для обновления передаются в `action: "update"` с адресом, указывающим на конкретную запись, а затем вызывается
`action: "save"`.

```json
[
  // 1. Установить обновленные данные на адрес конкретной записи
  {
    "action": "update",
    "from": "input:userUpdateForm", // Данные из формы
    "to": "mysql!users/where/id/{input:userId}" // Адрес указывает на запись по ID
  },
  // 2. Сохранить изменения (вызывает UPDATE)
  {
    "action": "save",
    "from": "mysql!users/where/id/{input:userId}" // Сохраняем по тому же адресу
  },
  // 3. Опционально: обновить UI
  {
    "action": "update",
    "value": "User {input:userId} updated!",
    "to": "output:statusMessage"
  }
]
```

### Удаление записи (DELETE - через `remove`)

Используется `action: "remove"` с адресом, указывающим на удаляемую запись.

```json
[
  // 1. Удалить запись по ID
  {
    "action": "remove",
    "to": "mysql!users/where/id/{input:userId}" // Адрес указывает на запись для удаления
  },
  // 2. Опционально: обновить UI
  {
    "action": "update",
    "value": "User {input:userId} deleted!",
    "to": "output:statusMessage"
  }
]
```

### Удаление с условием `WHERE`

```json
[
  {
    "action": "remove",
    "to": "mysql!logs/where/level/debug" // Удалить все debug логи
  },
  {
    "action": "update",
    "value": "Debug logs removed.",
    "to": "output:statusMessage"
  }
]
```

## Сложные запросы

Для запросов, которые сложно или невозможно выразить через стандартные сегменты пути (`JOIN`, подзапросы, сложные
агрегатные функции), рекомендуется использовать:

1. **Выделенные методы в PHP:** Создать метод в соответствующем классе (например, контроллере или сервисном классе),
   который выполняет сложный SQL-запрос с использованием Query Builder или Eloquent, и вызывать этот метод из действия (
   `action: "call"` или через кастомный Modificator).

## Транзакции

*(Примечание: В текущей реализации `ProcessInstruction` нет встроенного действия `transaction`. Для выполнения атомарных
операций необходимо либо реализовать такое действие, либо вызывать специальный PHP-метод/серверное действие, которое
будет управлять транзакцией базы данных).*

## Обработка ошибок

При работе с MySQL модулем важно учитывать возможные ошибки:

1. **Ошибки запросов**: Неправильный синтаксис, несуществующие таблицы/поля.
2. **Ошибки целостности данных**: Нарушение ограничений (`UNIQUE`, `FOREIGN KEY`).
3. **Ошибки соединения**.

*(Примечание: В текущей реализации `ProcessInstruction` нет встроенных действий `try`/`catch`/`finally` или
параметров `errorTo`/`resultTo`. Обработка ошибок должна выполняться путем проверки результата выполнения инструкций на
клиенте или в последующих шагах серверных действий, если это необходимо и возможно).*

## Интеграция с другими модулями

Модуль MySQL часто используется совместно с другими модулями хранения:

1. **Model**: Используется Model для простых операций CRUD с Eloquent, а MySQL - для сложных запросов или работы с
   таблицами без моделей.
2. **Buffer**: Для временного хранения результатов запросов или данных для вставки/обновления.
3. **Session**: Для хранения ID пользователя, используемого в `WHERE` условиях.
4. **File**: Для сохранения результатов запросов в файлы (например, для экспорта).

## Сравнение с модулем Model

| Функциональность                                   | MySQL (Query Builder) | Model (Eloquent) |
|----------------------------------------------------|-----------------------|------------------|
| Базовые операции CRUD                              | ✓                     | ✓                |
| Работа с моделями Laravel (связи, события, скоупы) | ✗                     | ✓                |
| Сложные запросы с JOIN                             | ✓                     | (через Eloquent) |
| Доступ к скоупам моделей                           | ✗                     | ✓                |
| Прямой доступ к таблицам                           | ✓                     | (через Eloquent) |
| Транзакции                                         | ✓ (через `DB::`)      | ✓ (через `DB::`) |
| Производительность (простые запросы)               | ~                     | ~                |
| Производительность (сложные запросы)               | +                     | -                |
| Удобство использования (простые CRUD)              | -                     | +                |

## Лучшие практики

1. **Безопасность**: Избегайте конкатенации строк для построения запросов. Используйте возможности Query Builder для
   биндинга параметров (передавая данные через `value` или `args`).
2. **Выбор модуля**: Используйте Model для стандартных операций с Eloquent, MySQL - для сложных запросов или прямого
   доступа к таблицам.
3. **Производительность**: Запрашивайте только необходимые поля (`columns` параметр, если реализован в парсере для
   mysql!). Используйте индексы БД.
4. **Транзакции**: Оборачивайте связанные операции в `transaction`.
5. **Инкапсуляция**: Сложные или часто используемые запросы выносите в именованные серверные действия (action files).

## Ограничения

1. **Безопасность**: Прямой доступ к базе данных требует повышенного внимания к безопасности и валидации входных данных.
2. **Переносимость**: Запросы могут быть специфичны для MySQL (хотя Query Builder сглаживает многое).
3. **Сложность**: Формат адреса с параметрами может быть сложнее для чтения, чем вызовы методов Eloquent.

## Взаимосвязь с Laravel Query Builder

Модуль MySQL является оберткой над Laravel Query Builder. Операции, выполняемые через модуль MySQL, соответствуют
методам Query Builder:

| Операция MySQL (через `Mysql.php`) | Примерный вызов Query Builder (`DB::table(...)`) |
|------------------------------------|--------------------------------------------------|
| `select` (с параметрами)           | `->where(...)->orderBy(...)->limit(...)->get()`  |
| `count` (с параметрами)            | `->where(...)->count()`                          |
| `insert` (с данными из `set()`)    | `->insert($data)`                                |
| `update` (с `where` и `set()`)     | `->where(...)->update($data)`                    |
| `delete` (с `where`)               | `->where(...)->delete()`                         |
