# Документация операций с моделями в JSON UI

## Обзор

Модуль Model в JSON UI предоставляет интерфейс для взаимодействия с моделями данных Laravel Eloquent. Этот модуль
позволяет выполнять стандартные операции CRUD (Create, Read, Update, Delete) и другие действия с моделями данных через
унифицированный синтаксис адресов.

Основной класс, отвечающий за эти операции, расположен в `app/AiRudeDepot/StorageDataModules/Model.php`. Как и другие
модули хранения, он редко используется напрямую, а доступ к нему осуществляется через классы `DataHub` и `Data`,
используя адреса с префиксом `model!`.

## Особенности модуля Model

- Унифицированный доступ к моделям Laravel через синтаксис адресов.
- Поддержка основных операций: получение (`find`, `where`, `all`), создание (неявно через `update`+`save`), обновление (
  неявно через `update`+`save`), удаление (через `remove`), подсчет (`count`).
- Автоматическое преобразование данных между JSON и моделями Laravel.
- Работа с атрибутами и (потенциально) связями моделей.
- Интеграция с системой аутентификации Laravel.

## Формат адресов модуля Model (Path-Based)

Адреса для модуля Model используют префикс `model!` за которым следует имя модели Eloquent (без неймспейса
`App\Models\`) и опциональные **сегменты пути**, определяющие операцию и параметры:

```
model!ИмяМодели[/операция][/параметр1/значение1]...
```

где:

- `ИмяМодели` - имя класса модели Laravel (например, `User`, `Product`, `Order`).
- `/операция` - сегмент, указывающий на тип операции чтения или модификации условия.
- `/параметр/значение` - сегменты для передачи условий `WHERE`, `ORDER BY`, `LIMIT`.

### Ключевые Сегменты Пути

| Сегмент Пути                                 | Описание                                                                                                                                                                                                           | Пример Адреса                                  |
|:---------------------------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:-----------------------------------------------|
| (отсутствует)                                | Указывает на модель в целом. Используется для **неявного INSERT** (`action: "update"` + `action: "save"`) или для получения всех записей (`all`).                                                                  | `model!User`                                   |
| `/find/{id}`                                 | Поиск записи по первичному ключу (`id`).                                                                                                                                                                           | `model!Product/find/123`                       |
| `/where/{column}/{value}`                    | Добавляет простое условие `WHERE column = value`.                                                                                                                                                                  | `model!Order/where/status/completed`           |
| `/where/{col}/{op}/{val}`                    | Добавляет условие `WHERE` с оператором (`eq`, `ne`, `gt`, `lt`, `gte`, `lte`, `like`, `in`, `notin`). **(Примечание: Текущая реализация `StoragePathParser` может поддерживать только `/where/{column}/{value}`)** | `model!Log/where/level/ne/info` (Теоретически) |
| `/count`                                     | Подсчет количества записей (без `WHERE`).                                                                                                                                                                          | `model!User/count`                             |
| `/count/where/{column}/{value}`              | Подсчет количества записей с условием `WHERE`.                                                                                                                                                                     | `model!Product/count/where/category_id/5`      |
| `/order/{column}/{direction}`                | Сортировка (`asc` или `desc`).                                                                                                                                                                                     | `model!Article/order/published_at/desc`        |
| `/limit/{number}`                            | Ограничение количества записей.                                                                                                                                                                                    | `model!Comment/limit/20`                       |
| `/limit/{offset}/{number}`                   | Ограничение количества записей со смещением.                                                                                                                                                                       | `model!Comment/limit/40/20`                    |
| `/where/{col}/{val}/...` (для UPDATE/DELETE) | Определяет записи для **неявного UPDATE** (`action: "update"` + `action: "save"`) или **DELETE** (`action: "remove"`).                                                                                             | `model!Task/where/id/456` (для update/delete)  |

**Важно:**

* Текущая реализация `StoragePathParser::processModel` может иметь **ограничения** в парсинге сложных сегментов пути.
  Для сложных `WHERE` предпочтительным остается формат **query string** (`model!Model?where[...]...`), если он
  поддерживается парсером как fallback.
* Операции **INSERT** и **UPDATE** являются **неявными**: `action: "update"` (для установки данных на адрес
  модели/записи) + `action: "save"` (для сохранения в БД).
* Операция **DELETE** выполняется через `action: "remove"` с адресом, указывающим на удаляемую запись.

## Примеры использования в инструкциях `actions`

### Получение всех записей (`all`)

```json
[
  {
    "action": "update",
    "from": "model!User/limit/100", // Получить первые 100 пользователей
    "to": "output:allUsers"
  }
]
```

### Поиск записи по ID (`find`)

```json
[
  {
    "action": "update",
    "from": "model!User/find/{input:userId}", // ID из input
    "to": "output:currentUser"
  }
]
```

### Поиск записей по условию (`where`)

```json
[
  {
    "action": "update",
    "from": "model!User/where/email/{input:userEmail}", // Поиск по email из input
    "to": "output:userByEmail"
  }
]
```

### Подсчет записей (`count`)

```json
[
  {
    "action": "update",
    "from": "model!Product/count/where/category_id/5",
    "to": "output:categoryProductCount"
  }
]
```

### Создание новой записи (INSERT - неявный)

Данные берутся из формы `userCreateForm`.

```json
[
  // 1. Установить данные на адрес модели
  {
    "action": "update",
    "from": "input:userCreateForm", 
    "to": "model!User"
  },
  // 2. Сохранить (вызывает create)
  {
    "action": "save",
    "from": "model!User"
  },
  // 3. Обновить UI 
  {
    "action": "update",
    "value": "User created!",
    "to": "output:statusMessage"
    // Примечание: Получение ID новой записи может потребовать доп. шага
  }
]
```

### Обновление существующей записи (UPDATE - неявный)

ID берется из поля `userId`, остальные данные - из формы `userUpdateForm`.

```json
[
  // 1. Установить данные на адрес конкретной записи
  {
    "action": "update",
    "from": "input:userUpdateForm", 
    "to": "model!User/where/id/{input:userId}"
  },
  // 2. Сохранить (вызывает update)
  {
    "action": "save",
    "from": "model!User/where/id/{input:userId}"
  },
  // 3. Обновить UI
  {
    "action": "update",
    "value": "User {input:userId} updated!",
    "to": "output:statusMessage"
  }
]
```

### Удаление записи (DELETE - через `remove`)

ID берется из поля `userId`.

```json
[
  // 1. Удалить запись по ID
  {
    "action": "remove",
    "to": "model!User/where/id/{input:userId}"
  },
  // 2. Обновить UI
  {
    "action": "update",
    "value": "User {input:userId} deleted!",
    "to": "output:statusMessage"
  }
]
```

## Использование с аутентификацией

Модуль Model часто используется в сценариях аутентификации.

### Вход пользователя (упрощенный пример с path-based адресами)

```json
[
    // 1. Найти пользователя по email
    {
      "action": "update",
      "from": "model!User/where/email/{input:email}", 
      "to": "buffer:foundUser" 
      // Примечание: errorTo не поддерживается
    },
    // 2. Проверить пароль, вызвав отдельный файл действий
    {
      "action": "call", 
      "from": "actions/auth/checkLogin" // Путь к файлу с логикой проверки
      // Примечание: Файл actions/auth/checkLogin.json должен:
      // - Прочитать buffer:foundUser и input:password
      // - Выполнить проверку пароля
      // - Записать результат (например, ID пользователя или false) в session:user или buffer:loginResult
    },
    // 3. Обновить UI на основе результата 
    {
      "action": "update",
      "value": "Login attempt processed. Check session/UI.",
      "to": "output:statusMessage"
    }
    // Логика проверки if/then удалена, она должна быть внутри checkLogin.json или на клиенте
]
```

### Регистрация пользователя (упрощенный пример с path-based адресами)

```json
[
    // 1. Хешировать пароль, вызвав отдельный файл действий
    {
      "action": "call",
      "from": "actions/auth/hashPassword" // Путь к файлу с логикой хеширования
      // Примечание: Файл actions/auth/hashPassword.json должен:
      // - Прочитать input:password
      // - Выполнить хеширование
      // - Записать результат в buffer:hashedPassword
    },
    // 2. Установить данные для новой модели (используя хеш из буфера)
    {
      "action": "update",
      "value": {
        "name": "{input:name}",
        "email": "{input:email}",
        "password": "{buffer:hashedPassword}"
       },
      "to": "model!User"
    },
    // 3. Сохранить модель (вызовет create)
    {
      "action": "save",
      "from": "model!User"
      // Примечание: Нет стандартного способа получить результат (ID или true/false) 
      // или ошибку (errorTo) от save в буфер
    },
    // 4. Обновить UI 
    // (Требует отдельного шага для проверки успеха, например, повторного чтения или проверки ответа)
    {
       "action": "update", 
       "value": "Registration attempt finished. Login to verify.",
       "to": "output:statusMessage" 
    }
]
```

*(**Важно:** Хеширование пароля и сложная валидация должны выполняться на стороне сервера через вызов `serverAction!`
или аналогичный механизм)*.

## Обработка ошибок

При работе с Model важно учитывать возможные ошибки:

1. **Модель не найдена** (`find` не нашел ID, `where` не вернул результатов).
2. **Ошибки валидации** (при `save` для `create`/`update`, если модель использует валидацию Laravel).
3. **Ошибки доступа** (если используются политики авторизации).
4. **Конфликты** (например, попытка создать пользователя с уже существующим email).

*(Примечание: В текущей реализации `ProcessInstruction` нет встроенных действий `try`/`catch`/`finally` или
параметров `errorTo`/`resultTo`. Обработка ошибок должна выполняться путем проверки результата выполнения инструкций на
клиенте или в последующих шагах серверных действий, если это необходимо и возможно).*

## Интеграция с другими модулями

Модуль Model часто используется совместно с другими модулями хранения:

1. **Session**: Для хранения ID аутентифицированного пользователя.
2. **Buffer**: Для временного хранения данных моделей между операциями.
3. **MySQL**: Для сложных запросов, не покрываемых Eloquent.
4. **File**: Для сохранения файлов, связанных с моделями (например, аватары).

## Лучшие практики

1. **Безопасность**: Никогда не передавайте необработанные данные из пользовательского ввода напрямую в `update`+`save`
   для `create` или `update`. Используйте валидацию на стороне сервера.
2. **Производительность**: Используйте `select()` в Eloquent (если возможно через параметры `model!`), чтобы запрашивать
   только необходимые поля. Используйте `with()` для eager loading связей, если это необходимо и поддерживается.
3. **Кэширование**: Используйте буфер (`buffer:`) для кэширования часто запрашиваемых моделей.
4. **Транзакции**: Используйте транзакции базы данных через серверные действия для связанных операций.
5. **Валидация**: Реализуйте валидацию в моделях Laravel или в серверных действиях перед вызовом `update`+`save`.

## Ограничения

1. **Сложные запросы**: Для сложных `JOIN`, подзапросов и агрегатных функций используйте модуль `MySQL` или серверные
   действия.
2. **Производительность**: Массовые операции или запросы с большим количеством связей могут быть медленными.
3. **Связи**: Работа с отношениями (загрузка, сохранение) через адреса `model!` может быть ограничена или потребовать
   специального синтаксиса/серверных действий.

## Взаимосвязь с Laravel Eloquent

Модуль Model является оберткой над Laravel Eloquent ORM. Операции, выполняемые через модуль Model, соответствуют методам
моделей Eloquent:

| Операция Model (через `Model.php`)            | Примерный вызов Eloquent (`User::...`) | Примечание  | 
|-----------------------------------------------|----------------------------------------|-------------|
| `all` (адрес `model!User`)                    | `User::all()`                          |             |
| `find` (адрес `model!User/find/X`)            | `User::find(X)`                        |             |
| `where` (адрес `.../where/...`)               | `User::where(...)->get()`              |             |
| `count` (адрес `.../count/...`)               | `User::where(...)->count()`            |             |
| `create` (`update`+`save` на `model!User`)    | `User::create($data)`                  |             |
| `update` (`update`+`save` на `.../where/...`) | `User::find(X)->update($data)`         | (Упрощенно) |
| `delete` (`remove` на `.../where/...`)        | `User::find(X)->delete()`              | (Упрощенно) |
