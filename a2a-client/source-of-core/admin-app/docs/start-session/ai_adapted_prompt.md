# Гайдлайн для AI-ассистента в проекте AI Task System

Этот документ является адаптированной версией общих принципов взаимодействия с AI (`copilot-promt.md`) под специфику
проекта AI Task System. Он предназначен для использования AI-ассистентом (мной) для эффективной работы в рамках данного
проекта.

## Раздел 1: Scan (Сбор Контекста)

**Цель:** Быстро и эффективно собрать первоначальный контекст о состоянии системы, активных задачах и релевантной
документации для выполнения поставленной задачи. Этот процесс должен быть максимально автоматизирован с использованием
доступных инструментов и скриптов проекта.

**Основные Шаги Сканирования:**

1. **Определение Рабочего Контекста:**
    * **Активная Задача:** Проверить `script/engine/state/system.state.json` для определения `publishedTaskId`. Если
      `publishedTaskId` установлен, это приоритетная задача.
    * **Пользовательский Ввод:** Проанализировать первоначальный запрос пользователя на предмет указания конкретной
      задачи (`TaskId`), сценария (`ScenarioId`) или области работы.
    * **Инициализация:** Если нет явной задачи, подготовиться к общему обзору или задаче, которую поставит пользователь.

2. **Изучение Ключевых Скриптов и Конфигураций:**
    * **`main.ps1`**: Понять основные режимы работы и как он вызывает другие модули/скрипты (через
      `config/scripts_config.json`).
    * **`main-work.ps1`**: Изучить режимы (`RunScenario`, `ResetScenario`, `ShowTask` и т.д.) и как он взаимодействует с
      PHP движком сценариев (`invoke-scenario-engine.php`).
    * **`main-index.ps1`**: Понять, как он используется для запросов к индексу (взаимодействие с
      `script/engine/index/index-processor.php`) и какие типы запросов (`QueryIndex`) он поддерживает.
    * **`invoke-scenario-engine.php`**: Ознакомиться с общей логикой обработки шагов сценария (actions, queries,
      conditions).

3. **Анализ Структуры `script/engine/`:**
    * **`task_definitions/`**: Просмотреть несколько примеров файлов `.task.json`, чтобы понять их структуру и типичное
      содержимое (сопоставить со стандартом `task-definition-standard.json`).
    * **`task_types/`**: Изучить структуру типовых задач, наличие шаблонов (`.template.json`) и конфигурационных
      файлов (`.task_type_data.json`).
    * **`scenarios/`**: Просмотреть несколько файлов `.scenario.json` (например, `SCN-ActivateTask`,
      `SCN-FullyCollectTaskData`, `SCN-QueryIndex`), понять их структуру (шаги, типы действий, условия).
    * **`actions/powershell/` и `actions/php/` (если существует)**: Ознакомиться с перечнем доступных переиспользуемых
      действий.
    * **`partials/`**: Понять, какие вспомогательные PHP скрипты используются движком сценариев.
    * **`markers/`**: Знать, где искать файлы состояния выполнения сценариев.
    * **`state/system.state.json`**: Проверить актуальное состояние (например, `publishedTaskId`).

4. **Изучение Стандартов и Документации:**
    * **Ключевые Стандарты из `script/docs/standards/`**:
        * `task-manager/task-definition-standard.json`
        * `ai-agent/operational-principles.json`
        * `ai-agent/question-to-user-standard.json`
        * `ai-agent/ai-task-system-operation-standard.md`
        * Другие релевантные стандарты, упомянутые в `ai-task-system-guide` или `fact-based-operations-rule`.
    * **Документация по Разработке из `docs/development/`**:
        * `lessons-learned.md`: Для понимания общей архитектуры, PHP-ядра, обработки JSON, клиентской части, принципов
          модульности.
        * `StrictModuleChecklist.md`: Для понимания требований к структуре модулей.
        * Другие документы, которые могут быть релевантны для текущей задачи.
    * **Проектные Руководства:**
        * `script-commands`
        * `script-workflow`
        * `ai-task-system-guide`

5. **Обзор Индексной Системы (`index/` и `main-index.ps1`):**
    * Понять, какие данные индексируются (структура подпапок в `index/`).
    * Как использовать `main-index.ps1` для поиска информации, необходимой для выполнения задачи (например, поиск
      связанных файлов, определений задач, документации).

6. **Обзор Других Важных Директорий (по необходимости):**
    * `install-modules/`: Структура модулей для установки.
    * `resources/`: Общие ресурсы.
    * `config/`: Конфигурационные файлы проекта.

**Инструменты для Сканирования:**

* `list_dir` для обзора структуры каталогов.
* `read_file` для чтения содержимого ключевых файлов и документации.
* `file_search` для быстрого поиска файлов по имени.
* `grep_search` для поиска конкретных строк или паттернов в коде/документации.
* `run_terminal_cmd` для запуска скриптов (`main-index.ps1`, `main-work.ps1 -Mode ShowTask`, и т.д.) для получения
  динамической информации.

## Раздел 2: Plan (Планирование)

**Цель:** Сформулировать четкий, пошаговый план для выполнения поставленной задачи, основываясь на собранном контексте,
стандартах проекта и доступных инструментах (сценариях, действиях).

**Основные Шаги Планирования:**

1. **Уточнение Цели Задачи:**
    * Если задача задана через `TaskId`, загрузить ее определение (`main-work.ps1 -Mode ShowTask -TaskId <ID>`) и
      внимательно изучить поля `goal`, `description`, `acceptanceCriteria`.
    * Если задача неформальная, уточнить у пользователя конечную цель и ожидаемый результат. Использовать QTU (
      Question-To-User) при необходимости.

2. **Декомпозиция Задачи:**
    * Разбить основную цель на более мелкие, управляемые подзадачи.
    * Определить зависимости между подзадачами.

3. **Выбор Подходящих Инструментов и Подходов:**
    * **Поиск Существующих Сценариев:** Проверить `script/engine/scenarios/` на наличие сценариев, которые могут
      полностью или частично решить подзадачи (например, `SCN-GenerateTaskType`, `SCN-FullyCollectTaskData`,
      `SCN-UpdateModule` и т.д.).
        * Анализировать параметры сценария и его шаги.
    * **Использование `main-index.ps1`:** Определить, какие запросы к индексу (`QueryIndex`) могут понадобиться для
      сбора дополнительных данных или поиска релевантных артефактов (файлов, других задач, документации).
    * **Прямое Взаимодействие со Скриптами:** Если нет подходящего сценария, определить, какие основные скрипты (
      `main-work.ps1`, `main.ps1`) и в каких режимах нужно будет использовать.
    * **Разработка Новых Компонентов (если необходимо):**
        * **Новые Действия:** Если для подзадачи требуется новая атомарная операция, спланировать создание нового
          PowerShell (`script/engine/actions/powershell/`) или PHP (`script/engine/actions/php/`) действия.
        * **Новые Части PHP-движка (`partials`):** Если требуется более сложная логика внутри сценария.
        * **Модификация Существующих Скриптов/Сценариев:** Оценить объем и риски таких изменений.

4. **Определение Необходимых Данных и Их Источников:**
    * Какие данные нужны для каждого шага плана?
    * Откуда их можно получить (индекс, файлы конфигурации, пользовательский ввод, вывод других шагов)?

5. **Формирование Последовательности Шагов:**
    * Описать каждый шаг плана, указывая:
        * Используемый инструмент/сценарий/скрипт и его параметры.
        * Ожидаемый ввод и вывод.
        * Критерии успеха для шага.

6. **Учет Стандартов и Ограничений:**
    * План должен соответствовать `operational-principles.json` (факт-ориентированный подход).
    * При генерации/модификации JSON (задачи, сценарии) следовать `task-definition-standard.json` и другим релевантным
      `.schema.json` файлам.
    * Учитывать `StrictModuleChecklist.md` при планировании работ с модулями.
    * Соблюдать `script-workflow` и рекомендации из `script-commands`.

7. **Оценка Рисков и Альтернативные Пути:**
    * Какие могут возникнуть проблемы на каждом шаге?
    * Есть ли запасные варианты или обходные пути?

**Результат Планирования:** Детальный, пошаговый план, который может быть представлен пользователю для утверждения (если
это сложная задача) или сразу взят в работу. План должен быть достаточно гибким, чтобы адаптироваться к непредвиденным
обстоятельствам.

## Раздел 3: Refine (Уточнение и Улучшение)

**Цель:** Итеративно улучшать план и результаты работы на основе обратной связи, новой информации и возникающих проблем.
Обеспечить прозрачность процесса и документирование ключевых решений.

**Основные Шаги Уточнения и Улучшения:**

1. **Исполнение Плана (пошаговое):**
    * Выполнять шаги плана, внимательно отслеживая результаты и возможные ошибки.
    * Использовать `Write-Log` (в PowerShell) или `php_log` (в PHP) для подробного логирования процесса выполнения,
      особенно для сложных или новых сценариев/действий.
    * Сохранять промежуточные результаты и артефакты (например, сгенерированные JSON, выводы скриптов) для анализа.

2. **Мониторинг и Обработка Ошибок:**
    * При возникновении ошибок:
        * Проанализировать сообщение об ошибке и логи.
        * Проверить состояние маркера сценария (`engine/markers/`), если ошибка произошла при выполнении
          сценария.
        * Попытаться определить причину (неверные данные, ошибка в скрипте/сценарии, проблема с окружением).
        * Если причина неясна, собрать дополнительную информацию (например, прочитать связанные файлы, проверить
          конфигурации).
    * **Корректировка Плана:** Если ошибка требует изменения плана, внести необходимые корректировки и, если это
      значительное изменение, сообщить пользователю.

3. **Сбор Обратной Связи:**
    * Регулярно (после выполнения значимых этапов или при возникновении сложностей) представлять пользователю текущие
      результаты и запрашивать обратную связь.
    * Использовать QTU-сценарии для формализованных запросов к пользователю, если это предусмотрено процессом или
      требует стандарт `question-to-user-standard.json`.

4. **Итеративное Улучшение:**
    * На основе полученной обратной связи, новой информации или выявленных проблем, пересматривать и уточнять:
        * Цели задачи.
        * План выполнения.
        * Выбранные инструменты и подходы.
        * Сгенерированный код или конфигурации.
    * Если были созданы новые сценарии, действия или документация, убедиться, что они соответствуют стандартам и хорошо
      документированы.

5. **Документирование Ключевых Решений и Результатов:**
    * Фиксировать важные решения, принятые в ходе выполнения задачи, особенно если они отклоняются от первоначального
      плана или стандартов (с обоснованием).
    * По завершении задачи подготовить краткий отчет о проделанной работе, достигнутых результатах и возникших
      проблемах (если это требуется).
    * Обновлять релевантную документацию (`script/docs/` или документацию модулей), если в ходе работы были выявлены
      неточности или сделаны улучшения, которые стоит задокументировать.

6. **Проверка Соответствия Стандартам:**
    * Перед финализацией работы убедиться, что все артефакты (код, JSON, документация) соответствуют принятым в проекте
      стандартам (`task-definition-standard.json`, `StrictModuleChecklist.md`, и т.д.).

7. **Завершение и Архивирование (если применимо):**
    * Для задач, управляемых через AI Task System, использовать соответствующие сценарии для закрытия задачи (например,
      `SCN-CloseTask`).
    * Убедиться, что все маркеры сценариев корректно завершены или сброшены.

**Принципы Уточнения:**

* **Прозрачность:** Пользователь должен понимать, что происходит и почему.
* **Гибкость:** Быть готовым адаптировать план.
* **Качество:** Стремиться к созданию надежных и соответствующих стандартам решений.
* **Факт-ориентированность:** Всегда опираться на проверенную информацию и документацию проекта.

## Раздел 4: Общие Принципы Взаимодействия и Ограничения

**Цель:** Определить общие правила поведения, коммуникации и ограничения для AI-ассистента при работе в проекте AI Task
System.

**Основные Принципы и Ограничения:**

1. **Факт-Ориентированность (см. `fact-based-operations-rule`):**
    * Всегда основывать свои действия, выводы и предоставляемую информацию на данных из проекта (скрипты, JSON-файлы,
      документация, стандарты) или на информации, явно предоставленной пользователем.
    * Избегать догадок и предположений. Если информации недостаточно, запросить ее у пользователя через QTU или указать
      на ее отсутствие.
    * Приоритетные источники: активная задача, стандарты типа задачи, общепроектные стандарты, `main-index.ps1`.

2. **Следование Стандартам Проекта:**
    * Строго придерживаться форматов данных, определенных в стандартах (`task-definition-standard.json`, схемы для
      сценариев и т.д.).
    * При генерации или модификации кода/скриптов/JSON соблюдать принятые в проекте конвенции именования,
      структурирования и комментирования (если применимо).
    * Следовать инструкциям из `ai-task-system-guide`, `script-workflow`, `script-commands` и другим релевантным
      руководствам.

3. **Проактивность и Автономность (в рамках задачи):**
    * После получения задачи и согласования плана (если необходимо), стремиться к автономному выполнению шагов.
    * Проактивно использовать доступные инструменты (`main-index.ps1`, `main-work.ps1` и т.д.) для сбора необходимой
      информации, не дожидаясь явных указаний на каждый мелкий шаг.
    * Предвидеть возможные проблемы и предлагать решения.

4. **Четкая Коммуникация:**
    * Предоставлять ясные и структурированные ответы.
    * При запросе информации у пользователя, формулировать вопросы конкретно (следуя `question-to-user-standard.json`,
      если это QTU-сценарий).
    * Информировать пользователя о ходе выполнения сложных задач, особенно при возникновении проблем или необходимости
      изменения плана.
    * При использовании инструментов, кратко пояснять, зачем вызывается тот или иной инструмент.

5. **Безопасность и Ограничения:**
    * Не выполнять команды или действия, которые могут нанести вред системе или данным, без явного подтверждения от
      пользователя (особенно это касается `run_terminal_cmd`).
    * Не выходить за рамки предоставленных инструкций и ограничений, указанных в `custom_instructions` или других
      документах.
    * **Запрет на `cat` в PowerShell:** Всегда использовать `Get-Content` для чтения файлов и прямой вызов для
      скриптов (см. `no-cat-in-pwsh`).
    * **Работа с JSON:** Не экранировать одиночные кавычки. Экранировать `\r`, `\n`, `"` (см. `json` правило).
    * Придерживаться этических норм, не генерировать неуместный или вредоносный контент.

6. **Работа с Инструментами (`tool_calling`):**
    * Всегда указывать `explanation` для вызова инструментов.
    * Точно следовать схеме вызова инструментов.
    * Не запрашивать разрешения на использование инструментов.
    * Предпочитать получение информации через инструменты, а не через вопросы к пользователю, если это возможно.

7. **Обработка Ошибок Редактирования Файлов (см. `edit_file_tool` и `.cursor/rules/edit_file_tool`):**
    * Применять специальный протокол (коммит, бэкап, пересоздание) в случае многократных неудач при сохранении файлов.
    * Для больших файлов генерировать diff-патчи поэтапно.

8. **Управление Контекстом и Сессиями:**
    * Учитывать историю диалога, но при необходимости использовать шаблон `review-process` (
      `<most_important_user_query>`) для сброса лишнего контекста и переориентации на главную задачу.
    * Понимать, что состояние (например, CWD в терминале) может сохраняться между вызовами `run_terminal_cmd`.

9. **Конфиденциальность:**
    * Не передавать и не сохранять за пределами сессии чувствительную информацию из проекта без явного разрешения.

# Пример использования сценария `SCN-CreateTask`

Сценарий `SCN-CreateTask` автоматизирует процесс создания новой задачи и связанной с ней задачи типа "
FullyCollectTaskData" (FC Task). Ниже приведен пошаговый пример взаимодействия со сценарием для создания задачи типа
`ModuleDevelopment`.

1. **Инициация сценария:**
   ```powershell
   pwsh -File ./main-work.ps1 -Mode RunScenario -ScenarioId SCN-CreateTask
   ```

2. **Ввод типа задачи:** Система запросит тип создаваемой задачи.
    * Запрос: `QUESTION: Введите тип задачи (например WorkflowImprovement)`
    * Ответ: Введите желаемый тип, например, `ModuleDevelopment`.
      ```powershell
      pwsh -File ./main-work.ps1 -Mode RunScenario -ScenarioId SCN-CreateTask -UserInputValue ModuleDevelopment
      ```

3. **Создание и валидация файла задачи:**
    * Система скопирует соответствующий шаблон (например,
      `script/engine/task_types/ModuleDevelopment/ModuleDevelopment.template.json`) в новый файл определения задачи (
      например, `script/engine/task_definitions/ModuleDevelopment-XXXXX.json`).
    * Далее, система попытается валидировать этот файл. Если в шаблоне есть плейсхолдеры, валидация сообщит об этом.

4. **Редактирование файла задачи:** Система предложит отредактировать созданный файл.
    * Запрос:
      `QUESTION: The task file C:\apps\admin-app\script\engine\task_definitions\ModuleDevelopment-XXXXX.json contains placeholder text. Please edit the file to fill in the details...`
    * Действие: Откройте указанный `.json` файл и заполните все плейсхолдеры актуальными данными для вашей задачи.

5. **Подтверждение редактирования:** После сохранения изменений, система спросит, завершено ли редактирование.
    * Запрос: `QUESTION: Have you finished editing the ModuleDevelopment task file ...? Enter 'yes' to re-validate.`
    * Ответ: `yes`
