# Методология "Library-Rules-Validate" (LRV)
## Структурированный подход к разработке и исправлению модулей в AiRudeDepot

> **Кратко:** Методология LRV - это систематический подход к созданию и исправлению модулей, основанный на строгой последовательности: изучение документации (Library), понимание правил (Rules), и обязательная валидация результата (Validate) перед переходом к следующему шагу. Это позволяет избежать "творческих" решений, не соответствующих стандартам системы.

### 3. Meta-LRV: Метаданные и конфигурация

Настройка метаданных модуля в директории `_i/` определяет, как система будет взаимодействовать с модулем, его зависимости и связи.

**Ключевые документы:**
- `docs/guides/module/03-metadata.md` - руководство по метаданным

**Обязательные файлы в `_i/`:**
- `meta.json` - основные метаданные модуля (ID, название, версия, описание)
- `files-by-block.json` - карта файлов модуля по блокам
- `common.json` - общие настройки модуля
- `links.json` - зависимости и связи с другими модулями

**Пример базовой структуры `meta.json`:**
```json
{
  "id": "my-module",
  "version": "1.0.0",
  "name": "My Module",
  "description": "Description of my module",
  "author": "Your Name",
  "requires": [],
  "dependencies": []
```

### 4. UI-LRV: Пользовательский интерфейс

Создание UI-компонентов модуля, включая страницы, секции и шаблоны. Критически важно использовать только поддерживаемые системой типы компонентов.

**Ключевые документы:**
- `docs/guides/module/04-ui-construction.md` - руководство по построению UI
- `install-modules/aiCore/js/component-map.json` - карта поддерживаемых компонентов
- Уроки из `docs/development/lessons-learned.md`, особенно #11 о регистре типов компонентов

**Правила построения UI:**
1. Стандартные HTML-элементы используются в нижнем регистре (`div`, `span`)
2. Vue/PrimeVue компоненты используются в PascalCase (`Panel`, `Button`, `InputText`)
3. Структура страницы должна начинаться с корневого типа `Page`
4. Каждый компонент должен иметь валидный `type` и правильный набор `props`

**Пример базовой структуры страницы:**
```json
{
  "type": "Page",
  "props": {
    "title": "Моя страница"
  },
  "content": [
    {
      "type": "div",
      "props": {
        "class": "container"
      },
      "children": [
        {
          "type": "H1",
          "props": {
            "content": "Заголовок страницы"
          }
        }
      ]
    }
  ]
}
```

**Валидация этапа:**
```bash
# Проверить все UI-файлы на соответствие схемам
php artisan module:merge [ИМЯ_МОДУЛЯ] && php artisan validate:module-json [ИМЯ_МОДУЛЯ]
```

Настройка структур данных, моделей и бланков модуля. Определяет, как модуль будет хранить и обрабатывать информацию.

**Ключевые документы:**
- `docs/guides/module/05-data-handling.md` - руководство по работе с данными

- `app/AiRudeDepot/Storage/DataHub.php` - центральное хранилище данных

**Структура директории `data/`:**
```
data/
├── blanks/           # Шаблоны для новых данных
├── models/           # Модели для хранения постоянных данных
└── *.json            # Другие структуры данных
```

**Важные правила для данных:**
- Файлы в `data/` не должны содержать ключ `type` на корневом уровне
- В JSON-структурах не должно быть UI-компонентов
- Данные должны быть валидными JSON-объектами

**Валидация этапа:**
```bash
# Проверить структуру файлов данных
ls implement-modules/[ИМЯ_МОДУЛЯ]/v[ВЕРСИЯ]/data/

```

### 6. Actions-LRV: Действия и логика

Разработка серверных действий и команд модуля. Определяет логику работы модуля и взаимодействие с данными.

**Ключевые документы:**
- `docs/guides/module/06-actions-logic.md` - руководство по логике и действиям
- `docs/ui/commands-and-operations/server-actions-reference.md` - справочник по действиям
- `app/AiRudeDepot/Processors/InstructionProcessor.php` - процессор инструкций

**Поддерживаемые типы действий:**
- `update` - обновление данных
- `save` - сохранение данных
- `remove` - удаление данных
- `call` - вызов других действий
- `for` - цикл по коллекции
- `condition` - условное выполнение
- и другие (см. `server-actions-reference.md`)

**Пример действия `update`:**
```json
[
  {
    "action": "update",
    "from": "input:formData.userName",
    "to": "buffer:currentUser.name",
    "condition": "input:formData.userName"
  },
  {
    "action": "update",
    "from": "buffer:currentUser.name",
    "to": "path/to/json/file:and.key.in.it",
    "condition": "input:formData.userName"
  },
  {
    "action": "save",
    "from": "buffer:currentUser"
  }
]
```

**DataHub префиксы:**
- `buffer:` - временные данные в рамках запроса
- `input:` - данные, полученные от клиента
- `file!` - данные в JSON-файлах
- `model!` - данные в моделях
- `mysql!` - данные в базе данных
- и другие (см. `StoragePathParser.php`)

**Валидация этапа:**
```bash
# Проверить структуру файлов действий
ls implement-modules/[ИМЯ_МОДУЛЯ]/v[ВЕРСИЯ]/actions/

# Валидировать JSON-структуры
php artisan module:merge [ИМЯ_МОДУЛЯ] && php artisan validate:module-json [ИМЯ_МОДУЛЯ]
```
