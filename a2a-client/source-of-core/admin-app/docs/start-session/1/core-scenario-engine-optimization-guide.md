# Core Scenario Engine Optimization: Enhancing Task Definition and Interactive Workflows

> **Кратко:** Этот гайд — о том, как оптимизировать ядро системы сценариев (в частности `Invoke-ScenarioEngine.ps1` и
`SCN-DefineNewTask.scenario.json`) для поддержки надежного интерактивного создания задач и улучшения обработки
> пользовательского ввода. Работа ведется в соответствии с целями, изложенными в задаче `TASK-DEV-TASKMAN-001.json`.

## 1. Контекст Задачи (`TASK-DEV-TASKMAN-001.json`)

**Основная Цель:** Создать полностью функциональный сценарий `SCN-DefineNewTask.scenario.json`, который надежно
формирует корректные JSON-файлы определения задач на основе интерактивного пользовательского ввода, и обеспечить
поддержку этого интерактивного рабочего процесса соответствующим движком сценариев.

**Ключевые Направления Работы:**

1. **Доработка `SCN-DefineNewTask.scenario.json`**:
    * Обеспечить надежное интерактивное создание новых JSON-файлов задач.
2. **Отладка `Invoke-ScenarioEngine.ps1`** (и его взаимодействия с `invoke-scenario-engine.php`):
    * Корректная обработка последовательных пользовательских вводов (множественные шаги `QUESTION`).
    * Правильное обновление контекста сценария через `input.variable` (на верхнем уровне и для вложенных путей).
    * Обработка различных форматов ввода для полей задачи, таких как `guidanceNotes` и `acceptanceCriteria` (например,
      строки, разделенные запятыми, для преобразования в массив, или строки в формате JSON).
3. **Общие Улучшения Движка Сценариев**:
    * Обеспечить, чтобы маркеры прогресса (`engine/markers/`) сохраняли полный и корректный контекст на каждом
      шаге.
    * Проверить и, при необходимости, улучшить логику обработки ввода в `script/engine/main-index.ps1` в части,
      касающейся запуска и взаимодействия со сценариями.

## 2. Что нельзя делать (Принципы Оптимизации Ядра)

- **Нельзя** вносить изменения, которые нарушают работу существующих, стабильно работающих сценариев.
- **Нельзя** чрезмерно усложнять логику движка, если более простое рефакторинг или исправление может решить проблему.
- **Нельзя** отступать от установленных паттернов проектирования движка и обработки контекста без веских оснований и
  согласования.
- **Нельзя** игнорировать обратную совместимость без крайней необходимости и плана миграции.
- **Нельзя** вносить исправления без тщательного тестирования различных сценариев ввода и последовательностей шагов.

## 3. Как надо делать (Алгоритм Оптимизации)

Методология основана на подходе **Scan-Plan-Refine-LEARN**:

### 3.1. Scan (Сканирование и Анализ)

1. **Изучить `TASK-DEV-TASKMAN-001.json`**: Полностью понять цели, критерии приемки и рекомендации.
2. **Проанализировать `SCN-DefineNewTask.scenario.json`**:
    * Определить текущую структуру шагов, особенно `QUESTION` шаги.
    * Выявить, как предполагается собирать данные для каждого поля задачи.
    * Отметить места, где требуется сложная обработка ввода (например, для списков).
3. **Проанализировать `Invoke-ScenarioEngine.ps1`**:
    * Проследить логику обработки шагов сценария, особенно `QUESTION` и `INPUT_PROMPT`.
    * Понять, как происходит получение `UserInputValue`.
    * Изучить механизм обновления контекста сценария на основе `input.variable`.
    * Оценить текущую обработку различных типов данных, поступающих от пользователя.
4. **Проанализировать `script/engine/main-index.ps1` (в части вызова сценариев)**:
    * Понять, как `main-index.ps1` передает управление и пользовательский ввод в `Invoke-ScenarioEngine.ps1`.
    * Оценить цикл обработки ввода и его влияние на пошаговое выполнение сценария.
5. **Изучить `invoke-scenario-engine.php` (если применимо для понимания низкоуровневой логики)**:
    * Понять, как PHP-скрипт получает данные от PowerShell, обрабатывает шаги, управляет контекстом и маркерами.
6. **Проверить Формат Маркеров Прогресса**:
    * Убедиться, что маркеры в `engine/markers/` корректно сохраняют весь необходимый контекст между шагами.
7. **Обратиться к Стандартам**:
    * `script/docs/standards/ai-agent/question-to-user-standard.json`
    * `script/docs/standards/ai-agent/operational-principles.json`
    * `script/docs/standards/task-manager/task-definition-standard.json`

### 3.2. Plan (Планирование Исправлений и Улучшений)

1. **Составить пошаговый план** для отладки и модификации `Invoke-ScenarioEngine.ps1` и
   `SCN-DefineNewTask.scenario.json`.
2. **Определить стратегию обработки различных типов ввода**:
    * Простые строки.
    * Строки, разделенные запятыми (для преобразования в массив JSON).
    * Строки, являющиеся валидным JSON-массивом или объектом.
3. **Спланировать механизм обновления контекста**:
    * Убедиться, что `input.variable` корректно работает для записи как в корневые, так и во вложенные поля контекста.
    * Рассмотреть возможность автоматического преобразования типов при записи в контекст (если это безопасно и
      необходимо).
4. **Разработать тестовые сценарии**:
    * Для проверки последовательных вопросов.
    * Для проверки различных форматов ввода.
    * Для проверки сохранения и восстановления контекста из маркеров.
    * Для проверки генерации итогового JSON-файла задачи.
5. **Учесть существующие ограничения**: Как указано в `TASK-DEV-TASKMAN-001.json`, полная интерактивная отладка может
   быть затруднена, поэтому предусмотреть тестирование с использованием "single JSON input" как промежуточный этап.

### 3.3. Refine & Implement (Реализация и Итеративное Улучшение)

1. **Внести целевые исправления в `Invoke-ScenarioEngine.ps1`**:
    * Улучшить логику обработки `UserInputValue` для `QUESTION` шагов.
    * Реализовать/отладить парсинг и преобразование строк для полей типа "массив" (например, `guidanceNotes`,
      `acceptanceCriteria`, `linkedFiles`, `keywords`). PowerShell имеет `ConvertFrom-Json` и `-split` для этого.
    * Обеспечить корректное применение `input.variable` для обновления контекста.
2. **Модифицировать `SCN-DefineNewTask.scenario.json`**:
    * Обновить `QUESTION` шаги, чтобы они явно указывали ожидаемый формат ввода, если он специфичен (например, "Введите
      элементы списка через запятую" или "Введите JSON-массив").
    * Убедиться, что `input.variable` для каждого вопроса указывает на правильный путь в контексте для последующего
      формирования JSON.
    * Рассмотреть возможность добавления шагов `OPERATION` для преобразования или валидации данных в контексте перед
      финальной сборкой JSON.
3. **Проверить и доработать сохранение/загрузку маркеров прогресса**:
    * Убедиться, что весь контекст, включая сложные структуры данных, правильно сериализуется и десериализуется.
4. **Провести итеративное тестирование** согласно разработанным тестовым сценариям.
    * Начать с простых случаев, постепенно усложняя.
    * Использовать отладочный вывод в `Invoke-ScenarioEngine.ps1` для мониторинга состояния контекста и обработки ввода.

## 5. Частые Проблемы и Подводные Камни (Применительно к Движку Сценариев)

- **Некорректное слияние контекста**: Новые данные из `UserInputValue` могут перезаписывать или неправильно сливаться с
  существующим контекстом.
- **Ошибки интерпретации типов ввода**: PowerShell может по-разному интерпретировать строки, особенно если они содержат
  специальные символы или выглядят как JSON. Требуется аккуратный парсинг.
- **Проблемы с сериализацией/десериализацией контекста в маркерах**: Сложные объекты или массивы могут неправильно
  сохраняться или восстанавливаться, приводя к потере данных между шагами.
- **"Зацикливание" или неверный переход по шагам**: Ошибки в логике `Invoke-ScenarioEngine.ps1` могут приводить к
  неправильной последовательности выполнения шагов.
- **Недостаточная обработка ошибок**: Если пользовательский ввод не соответствует ожиданиям, движок должен корректно
  сообщать об ошибке и, возможно, предлагать повторный ввод, а не аварийно завершаться.
- **Тонкости `input.variable`**: Ошибки в путях `input.variable` или в логике присвоения по этому пути.
