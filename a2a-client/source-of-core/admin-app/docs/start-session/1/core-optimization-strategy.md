# Core System Optimization & Coverage: A Strategic Guide

> **Кратко:** Этот гайд — о том, как подходить к комплексной оптимизации и развитию ядра системы. Он основан на
> принципах, заложенных в
> задачах [GENERIC-PROJECT-COVERAGE-001](mdc:script/engine/task_definitions/GENERIC-PROJECT-COVERAGE-001.json), [QaJsonModuleAndProposeImprovement-00010](mdc:script/engine/task_definitions/QaJsonModuleAndProposeImprovement-00010.json)
> и [STD-MOD-DOC-001](mdc:script/engine/task_definitions/STD-MOD-DOC-001.json), и нацелен на создание прозрачной,
> управляемой и постоянно развивающейся основной платформы.

## Введение

Цель этого документа — предоставить стратегическую основу и практические шаги для всестороннего понимания, улучшения и
стандартизации ключевых компонентов ядра системы. Оптимизация ядра — это не разовое мероприятие, а непрерывный процесс,
управляемый через систему задач и опирающийся на глубокий анализ и четкие стандарты.

**Движущие задачи и их вклад:**

1. **[GENERIC-PROJECT-COVERAGE-001.json](mdc:script/engine/task_definitions/GENERIC-PROJECT-COVERAGE-001.json) (Полное
   Покрытие Проекта Задачами):**
    * **Принцип:** Ни один аспект ядра (код, документация, процессы, конфигурации) не должен оставаться без внимания.
    * **Вклад:** Методология систематического картирования компонентов ядра и создания задач для их планомерного
      развития и поддержки.

2. *
   *[QaJsonModuleAndProposeImprovement-00010.json](mdc:script/engine/task_definitions/QaJsonModuleAndProposeImprovement-00010.json) (
   Концептуальное Улучшение Модуля QTU):**
    * **Принцип:** Глубокие улучшения начинаются с концептуального проектирования, основанного на данных и исторических
      знаниях.
    * **Вклад:** Адаптация методологии концептуального улучшения (изначально для QTU) для применения к любым компонентам
      ядра, включая внутренние API, логику обработки данных и системные сценарии.

3. **[STD-MOD-DOC-001.json](mdc:script/engine/task_definitions/STD-MOD-DOC-001.json) (Стандарт Документации Внутри
   Модулей):**
    * **Принцип:** Ясность и поддерживаемость системы напрямую зависят от качества и стандартизации ее описания.
    * **Вклад:** Подход к разработке, внедрению и развитию стандартов для критически важных аспектов ядра, начиная с
      документации и распространяя на другие области.

## Общий Подход: Scan-Plan-Refine-LEARN для Ядра

Адаптируем цикл `Scan-Plan-Refine-LEARN` (из [true-module-fix.md](mdc:script/docs/start-session/true-module-fix.md)) для
работы с ядром:

1. **Scan (Сканирование и Анализ Ядра):**
    * Используйте `[main-index.ps1](mdc:main-index.ps1)` для глубокого анализа связей между компонентами ядра, их
      использования и существующей документации.
    * Изучайте `collectedIndexData` в задачах, связанных с ядром (как в `QaJsonModuleAndProposeImprovement-00010`).
    * Анализируйте ключевые PHP классы ([App\\AiRudeDepot\\...](mdc:app/AiRudeDepot/)), системные сценарии (
      `script/engine/scenarios/`) и конфигурационные файлы.
    * Особое внимание на точки расширения, API, и механизмы взаимодействия между ядром и модулями.

2. **Plan (Планирование Оптимизации и Развития Ядра):**
    * На основе сканирования и целей из
      задач ([GENERIC-PROJECT-COVERAGE-001](mdc:script/engine/task_definitions/GENERIC-PROJECT-COVERAGE-001.json))
      создавайте детализированные задачи на улучшение или стандартизацию конкретных частей ядра.
    * Планируйте не только изменения кода, но и обновление документации, стандартов, и создание новых тестов.
    * Определяйте метрики успеха для каждой оптимизационной задачи.

3. **Refine-LEARN (Реализация, Уточнение, Фиксация Знаний):**
    * Вносите изменения итеративно.
    * После каждого значительного изменения обновляйте релевантную документацию ядра и, при необходимости, стандарты.
    * Фиксируйте все новые знания, решения и возникшие проблемы в `docs/development/lessons-learned.md` или
      специализированных документах по ядру.
    * Проводите ревью изменений с командой.

## Столп 1: Достижение Полного Покрытия Системы (по [GENERIC-PROJECT-COVERAGE-001](mdc:script/engine/task_definitions/GENERIC-PROJECT-COVERAGE-001.json))

**Цель:** Обеспечить, чтобы каждый компонент и процесс ядра был идентифицирован, задокументирован (хотя бы на уровне
задачи) и имел назначенную задачу для отслеживания его состояния, поддержки и развития.

**Шаги:**

1. **Картирование Компонентов Ядра:**
    * Составьте исчерпывающий список компонентов ядра:
        * Ключевые PHP классы и пространства имен (например, `App\AiRudeDepot\Processors`, `App\AiRudeDepot\Storage`,
          `App\AiRudeDepot\Managers`).
        * Основные PowerShell-скрипты (`main.ps1`, `main-work.ps1`, `main-index.ps1`).
        * PHP-движок сценариев (`invoke-scenario-engine.php`).
        * Системные сценарии (`script/engine/scenarios/`).
        * Механизмы валидации и мержа модулей.
        * Система управления состоянием (`script/engine/state/`).
        * Стандарты (`script/docs/standards/`).
        * Ключевые конфигурационные файлы.
    * Для каждого компонента кратко опишите его назначение и текущий статус (стабилен, требует рефакторинга, требует
      документации и т.д.).

2. **Создание "Матрицы Покрытия Задачами":**
    * Для каждого идентифицированного компонента создайте или свяжите существующую задачу (типа `Generic`,
      `WorkflowImprovement`, `Documentation`, `Refactor`) в системе управления задачами.
    * Используйте сценарий `SCN-CreateTask` (через `[main-work.ps1](mdc:main-work.ps1)`) для стандартизированного
      создания новых задач.
    * Задачи должны включать:
        * Четкое описание компонента и его роли.
        * Текущие проблемы или области для улучшения.
        * Цели оптимизации/рефакторинга/документирования.
        * Критерии приемки.
        * Ссылки на связанные файлы (`linkedFiles`) и стандарты (`requiredStandards`).

3. **Приоритизация Задач Покрытия:**
    * Определите приоритеты на основе критичности компонента, наличия известных проблем, зависимостей и общих
      стратегических целей проекта.

4. **Непрерывное Обслуживание Карты Покрытия:**
    * Регулярно пересматривайте карту компонентов и матрицу задач, особенно при добавлении новой функциональности или
      рефакторинге существующих частей ядра.

## Столп 2: Глубокое Концептуальное Проектирование и Улучшение (по [QaJsonModuleAndProposeImprovement-00010](mdc:script/engine/task_definitions/QaJsonModuleAndProposeImprovement-00010.json))

**Цель:** Применять проактивный и глубокий подход к улучшению компонентов ядра, не ограничиваясь исправлением ошибок, а
стремясь к концептуальному развитию и повышению эффективности.

**Методология (адаптировано из QTU):**

1. **Фаза 1: Сбор Контекста и Концептуальное Расширение:**
    * **Анализ:**
        * Изучите `collectedIndexData` (если доступно для задачи по ядру) для понимания текущей структуры и связей.
        * Проанализируйте исторические данные: предыдущие задачи, обсуждения, `lessons-learned.md`, логи ошибок,
          связанные с компонентом.
        * Определите "болевые точки" и узкие места.
    * **Концептуализация:**
        * Опираясь на анализ, проведите мозговой штурм по возможным улучшениям:
            * Упрощение API.
            * Повышение производительности.
            * Улучшение расширяемости.
            * Добавление новой необходимой функциональности.
            * Улучшение логирования и диагностики.
        * Не бойтесь предлагать смелые изменения на концептуальном уровне. Задокументируйте все идеи.
    * **Приоритет:** "Focus only on main ideas, avoid getting sidetracked by secondary items."

2. **Фаза 2: Детализация Плана и Прототипирование (при необходимости):**
    * Выберите наиболее перспективные концепции.
    * Разработайте детализированный план их реализации, включая изменения в коде, данных, интерфейсах.
    * Для сложных изменений рассмотрите создание прототипов или PoC.
    * "Develop a comprehensive plan (checklist) ... aiming for maximum conceptual expansion."

3. **Фаза 3: Реализация и Валидация:**
    * Реализуйте запланированные изменения итеративно.
    * Обеспечьте покрытие тестами.
    * Проведите валидацию изменений, включая проверку на обратную совместимость (если применимо).
    * Обновите всю связанную документацию и стандарты.

## Столп 3: Создание и Развитие Стандартов Ядра (по [STD-MOD-DOC-001](mdc:script/engine/task_definitions/STD-MOD-DOC-001.json))

**Цель:** Обеспечить единообразие, предсказуемость и высокое качество компонентов ядра через разработку, внедрение и
поддержку четких стандартов.

**Процесс разработки стандарта (на примере стандарта документации):**

1. **Идентификация Потребности:** Определите область ядра, требующую стандартизации (например, структура документации
   модулей, правила именования API, формат логов, стиль кода PHP/PowerShell).

2. **Анализ Существующей Практики:**
    * Изучите, как данная область реализована сейчас в различных частях системы.
    * Проанализируйте релевантные внешние best practices и стандарты.
    * "Проанализировать структуру существующих модулей..." (из `STD-MOD-DOC-001`).

3. **Определение Ключевых Аспектов Стандарта:**
    * **Структура и Формат:** Как должны быть организованы компоненты/документы? Какие форматы использовать?
    * **Содержание:** Какие обязательные секции/элементы должны присутствовать?
    * **Версионирование:** Как стандарт будет развиваться? Как обеспечить совместимость со старыми версиями компонентов,
      если стандарт меняется?
    * **Механизмы Регистрации/Связывания:** Как стандарт будет интегрирован в систему (например, ссылки в
      `_i/files-by-block.json`, `linkedFiles` задач, правила для валидаторов).
    * "Определить правила структуры, формата и версионирования..." (из `STD-MOD-DOC-001`).

4. **Разработка Документа Стандарта:**
    * Напишите четкий и понятный документ, описывающий стандарт.
    * Разместите его в соответствующей директории (например, `script/docs/standards/`).
    * Приведите примеры корректного и некорректного использования.

5. **Внедрение и Поддержка:**
    * Интегрируйте стандарт в рабочие процессы (ревью кода, создание новых компонентов).
    * Обновите существующие компоненты для соответствия новому стандарту (создайте для этого задачи).
    * Регулярно пересматривайте и обновляйте стандарт по мере развития системы.
    * "Добавить ссылку на новый стандарт в `requiredStandards` для релевантных `task_type_data.json`."

## Общие Принципы Оптимизации Ядра

* **Задаче-Ориентированный Подход:** Вся работа по оптимизации ядра должна управляться через задачи. Используйте
  `[main-work.ps1](mdc:main-work.ps1)` и сценарии (`SCN-CreateTask`, `SCN-ActivateTask`, `SCN-CloseTask` и т.д.) для
  полного жизненного цикла задач.
* **Документация — Часть Ядра:** Относитесь к документации ядра с той же серьезностью, что и к коду. Она должна быть
  актуальной, полной и соответствовать стандартам.
* **Использование Системных Инструментов:** Активно применяйте `[main.ps1](mdc:main.ps1)`,
  `[main-work.ps1](mdc:main-work.ps1)` и `[main-index.ps1](mdc:main-index.ps1)` для анализа, управления и выполнения
  работ.
* **Итеративность и Обратная Связь:** Вносите изменения небольшими, управляемыми шагами. Регулярно получайте обратную
  связь от команды.
* **Тестирование:** Любые изменения в ядре должны сопровождаться созданием или обновлением автоматических тестов.

## Что Нельзя Делать при Оптимизации Ядра

* **Недокументированные Изменения:** Любое изменение в ядре должно быть отражено в задаче и соответствующей
  документации.
* **"Тихие" Правки Критичных Компонентов:** Изменения в ключевых частях ядра должны проходить через процесс ревью.
* **Нарушение Обратной Совместимости без Плана:** Если изменения ломают существующую функциональность или API, должен
  быть четкий план миграции и стратегия версионирования.
* **Игнорирование Стандартов:** Принятые стандарты должны соблюдаться. Если стандарт устарел или неэффективен,
  инициируйте процесс его обновления.
* **Пренебрежение Тестированием:** Недостаточное тестирование изменений ядра может привести к серьезным проблемам в
  стабильности всей системы.
