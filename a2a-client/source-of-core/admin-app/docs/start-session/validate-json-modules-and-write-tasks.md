# Валидация JSON-модулей и автоматическая генерация задач

**Внимание: Изменять код валидатора нельзя!**

Модули бывают разные, не все будут работать корректно, поэтому всегда используйте только правильный синтаксис и следуйте стандартам. Все действия должны быть основаны на фактах, полученных из файлов, вывода команд и документации.

---

## Цель сессии

Автоматически запускать артисан-команду валидатора модулей (например, `php artisan module:validate {module}`), анализировать её вывод и на основе найденных ошибок и предупреждений формировать отдельные задачи на доработку для каждого затронутого модуля. Перед началом работы обязательно проведите исследование системы, чтобы понимать структуру, стандарты и логику работы task-менеджера.

---

## Scan-Plan-Refine-LEARN: Живой цикл дообучения

### 1. Scan (Изучение системы и анализ связей)
- Изучите ключевые директории и файлы AI Task System:
    * Core Scripts: `main.ps1`, `main-work.ps1`, `main-index.ps1` (mdc:main.ps1 и др.)
    * Engine: `script/engine/` (особое внимание: `task_definitions/`, `task_types/`, `scenarios/`, `markers/`, `state/`)
    * Документация и стандарты: `script/docs/standards/` (mdc:script/docs/standards)
    * Валидация: артисан-команда валидатора (например, `php artisan module:validate`), связанные скрипты (`MergeModuleVersions.php`, `ValidateModuleJsonCommand.php`)
    * Связанные сценарии: автоматизация валидации/исправления модулей

- Для каждого этапа фиксируйте, какие файлы и директории участвуют в жизненном цикле валидации и генерации задач (используйте ссылки mdc:...)
- Особое внимание уделяйте жизненному циклу задач, использованию markers, взаимодействию между сценариями, PHP-ядром и генерируемыми задачами.
