# Роли компонентов системы

Документ описывает роли, зависимости и демоны каждого компонента в архитектуре A2A Script Agent.

---

## 1. Browser (Web UI)

| Свойство | Значение |
|----------|----------|
| **Роль** | User interface, event handling |
| **Долбит** | Client API (HTTP) |
| **Не долбит** | A2A Server напрямую |

### Daemons

| Daemon | Описание |
|--------|----------|
| **DialogLoader** | Обеспечивает минимальное время отображения индикатора загрузки (min display time) |
| **DialogPromise poll** | Опрос Client API для получения статуса асинхронных операций |
| **UI ticks (опционально)** | Обновление состояния в taskbar |

---

## 2. Client API (Vite Plugin)

| Свойство | Значение |
|----------|----------|
| **Роль** | REST API, session management, storage |
| **Долбит** | A2A Server (HTTP) |
| **Не долбит** | AI Proxy напрямую |

### Ответственность

- Управление сессиями пользователей
- Персистентное хранение данных сессий в файловой системе
- Проксирование запросов к A2A Server
- Проксирование запросов к Ollama (для RAG)

---

## 3. Daemon (Polling Loop)

| Свойство | Значение |
|----------|----------|
| **Роль** | Async operation tracking |
| **Долбит** | A2A Server (`/api/v1/requests/:id/result`) |
| **Интервал** | 1s |
| **Timeout** | 30s |

### Назначение

Демон отслеживает выполнение асинхронных операций на стороне A2A Server, периодически опрашивая endpoint для получения статуса завершения.

---

## 4. A2A Server

| Свойство | Значение |
|----------|----------|
| **Роль** | Business logic, orchestration |
| **Долбит** | AI Hub (HTTP) |
| **Не долбит** | Ollama напрямую |

### Daemons

| Daemon | Описание |
|--------|----------|
| **Request processor tick** | Обработка очереди запросов |
| **LLM-ready poll** | Опрос AI Hub для диалоговых режимов |
| **Recovery on startup** | Восстановление состояния при запуске |

### Ответственность

- Бизнес-логика приложения
- Оркестрация взаимодействия между компонентами
- Управление контекстом выполнения
- Трансформация запросов и ответов

---

## 5. AI integration (AI Hub)

| Свойство | Значение |
|----------|----------|
| **Роль** | LLM adapter, promise lifecycle |
| **Долбит** | Ollama (HTTP) |

### Daemons

| Daemon | Описание |
|--------|----------|
| **Async LLM job / promise completion worker** | Внутренний воркер для обработки асинхронных LLM задач |

### Ответственность

- Адаптация запросов к формату Ollama
- Управление жизненным циклом промисов
- Обработка асинхронных LLM задач
- Проксирование запросов к Ollama

---

## Таблица: Кто кого poll'ит

| Кто опрашивает | Кого опрашивают | Endpoint | Интервал |
|----------------|----------------|----------|----------|
| Browser (Dialog polling) | Client API | `/api/a2a/sessions/:id/async` | ~1s |
| Client API (Daemon) | A2A Server | `/api/v1/requests/:id/result` | 1s |
| A2A Server (LLM-ready poll) | AI Hub | `/api/promise/:id/status` | ~1s |
| AI Hub (Worker) | Ollama | `/api/generate` | — (синхронно) |

### Поток данных

1. **User Action** → Browser обрабатывает событие
2. **Browser** → HTTP → Client API (создание/обновление сессии)
3. **Client API** → HTTP → A2A Server (`/api/v1/invoke`)
4. **A2A Server** → Вызывает AI Hub для LLM задач
5. **AI Hub** → HTTP → Ollama для генерации ответа
6. **Response** → Обратный поток: Ollama → AI Hub → A2A Server → Client API → Browser

### Асинхронный поток (с Promise)

1. A2A Server возвращает `promiseId` вместо немедленного результата
2. Client API начинает polling A2A Server (`/api/v1/requests/:id/result`) и сохраняет артефакты в `N+1/`.
3. Browser начинает polling Client API (`/api/a2a/sessions/:id/async`)
4. При завершении: AI Hub → A2A Server (status: completed)
5. Polling обнаруживает завершение → возвращает результат
