# ADR-003: State Machine (PhaseMachine) на клиенте

## Дата
2026-02-25

## Авторы
- Команда разработки

## Статус
Принято

## Контекст

PhaseMachine управляет потоком обработки запросов на стороне сервера. Клиент взаимодействует с сервером, отправляя запросы и получая обновления статуса.

### Требования к State Machine

- **Детерминированность:** Переходы между фазами должны быть предсказуемыми
- **Обработка ошибок:** Каждая фаза должна обрабатывать возможные ошибки
- **Логирование:** Все переходы должны логироваться
- **Восстановление:** Возможность восстановления после сбоев

## Решение

### Диаграмма состояний (серверная)

```
                     +---------+
                     |  idle   |
                     +----+----+
                          |
                          | request received
                          v
               +------------------+
               |    discovery     |
               +--------+---------+
                          |
                          | data collected
                          v
               +------------------+
               |   recognition    |
               +--------+---------+
                          |
                          | entities identified
                          v
               +------------------+
               |    analysis       |
               +--------+---------+
                          |
                          | analysis complete
                          v
               +------------------+
               |     action        |
               +--------+---------+
                          |
                          | action executed
                          v
               +------------------+
               |    validation     |
               +--------+---------+
                          |
                          | validation passed
                          v
               +------------------+
               |    completed      |
               +------------------+
                          |
                          | reset
                          v
                     (idle)
```

### Описание фаз (серверная логика)

| Фаза | Описание | Входные данные | Выходные данные |
|------|---------|----------------|-----------------|
| `idle` | Ожидание нового запроса | - | - |
| `discovery` | Сбор данных о задаче | request, context | discovered_data |
| `recognition` | Распознавание сущностей | discovered_data | entities |
| `analysis` | Анализ данных | entities | analysis_result |
| `action` | Выполнение действия | analysis_result | action_result |
| `validation` | Проверка результата | action_result | validation_result |
| `completed` | Задача выполнена | validation_result | final_result |

## Клиентское взаимодействие

### Отправка задачи

```typescript
import { A2AClient } from '@a2a-client/api-client';

const client = new A2AClient({ baseUrl: 'http://localhost:3000' });

// Отправка задачи
const response = await client.sendTask({
  task: {
    id: 'task_001',
    type: 'analysis',
    input: { query: 'analyze codebase' },
  },
  context: {
    graph: { nodes: [], edges: [] },
    history: [],
  },
});

const promiseId = response.result.promiseId;
```

### Опрос статуса

```typescript
// Polling подход
async function waitForCompletion(promiseId: string): Promise<any> {
  while (true) {
    const status = await client.getTaskStatus(promiseId);
    
    if (status.result.status === 'completed') {
      return client.getTaskResult(promiseId);
    }
    
    if (status.result.status === 'failed') {
      throw new Error('Task failed');
    }
    
    await sleep(5000); // 5 секунд
  }
}
```

### WebSocket подписка

```typescript
// Real-time обновления через WebSocket
const ws = new WebSocketClient({
  url: 'ws://localhost:3001',
});

ws.subscribe(promiseId, (update) => {
  console.log('Status:', update.status);
  
  if (update.status === 'completed') {
    console.log('Result:', update.data);
  }
});
```

### Обработка ошибок

```typescript
// Обработка ошибок при взаимодействии с PhaseMachine
try {
  const result = await waitForCompletion(promiseId);
} catch (error) {
  if (error.code === -32002) {
    // Timeout - задача заняла слишком много времени
    console.error('Task timeout');
  } else if (error.code === -32001) {
    // Unauthorized
    console.error('Authentication required');
  } else {
    // Другие ошибки
    console.error('Task error:', error.message);
  }
}
```

### Типы статусов

```typescript
enum TaskStatus {
  PENDING = 'pending',
  PROCESSING = 'processing',
  COMPLETED = 'completed',
  FAILED = 'failed',
  CANCELLED = 'cancelled',
}

interface TaskStatusResponse {
  promiseId: string;
  status: TaskStatus;
  progress?: number;
  currentPhase?: string;
  error?: {
    code: number;
    message: string;
  };
}
```

## FlowManager на клиенте

Клиент имеет собственный FlowManager для управления локальным состоянием:

```typescript
import { FlowManager } from '@a2a-client/agent';

const flowManager = new FlowManager();

// Инициализация потока
await flowManager.initialize(context);

// Обработка ответа от сервера
async function handleServerResponse(response: any) {
  // Сохраняем текущий шаг
  flowManager.addStep({
    stepId: response.id,
    phase: response.phase,
    result: response.result,
  });
  
  // Продолжаем или завершаем
  if (response.status === 'completed') {
    await flowManager.complete(response.result);
  }
}
```

## Последствия

### Положительные

- **Понятный поток:** Чёткая последовательность обработки
- **Отладка:** Легко отследить текущее состояние
- **Тестирование:** Каждую фазу можно тестировать изолированно
- **Real-time:** WebSocket для мгновенных обновлений

### Отрицательные

- **Зависимость от сервера:** Клиент полагается на серверную логику
- **Polling overhead:** HTTP требует периодического опроса

### Риски

- Потеря соединения во время выполнения задачи
- Timeout при длительных операциях
