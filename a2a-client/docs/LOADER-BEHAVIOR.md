## Обзор

Прелоадер (loading indicator) — обязательный элемент UI, показывающий пользователю что система обрабатывает запрос. Прелоадер управляется двумя уровнями:

1. **Клиент (JS)** — включает прелоадер сразу после действия пользователя
2. **Сервер (Client API)** — управляет состоянием прелоадера после получения ответа

> **Ключевой принцип**: Минимальная логика на фронтенде. Сервер сообщает клиенту когда убрать прелоадер.

## Поведение по шагам агента

### Шаг 1: Открытие новой панели сессии

```
Пользователь открывает новую панель (нажимает "+")
        ↓
Появляется поле ввода "тип сессии"
        ↓
Пользователь вводит текст + жмет Enter
        ↓
[КЛИЕНТ] СРАЗУ показывает прелоадер (заменяет поле ввода)
        ↓
[КЛИЕНТ] Отправляет запрос на сервер
        ↓
[СЕРВЕР] Обрабатывает запрос
        ↓
[СЕРВЕР] Возвращает ответ:
  - Если sync (есть execute) → отправляет команду "убрать прелоадер"
  - Если async (есть promiseId) → отправляет команду "продолжать показывать"
        ↓
[КЛИЕНТ] Получает команду от сервера:
  - MINIMUM_LOADER_TIME = 5000ms (выполняется ВСЕГДА)
  - После MINIMUM_LOADER_TIME:
    - Если пришел execute → убрать прелоадер
    - Если есть promiseId → продолжать показывать до resolved
```

**Требования**:
- При нажатии Enter поле ввода **немедленно** заменяется на прелоадер
- Минимальное время показа прелоадера: **5 секунд** (даже если сервер ответил быстро)
- Если сервер вернул `execute` (не `promiseId`) — убрать прелоадер после истечения 5 секунд

---

### Шаг 2: Choice форма (роутинг)

```
Пользователь видит форму с вариантами выбора (choices)
        ↓
Выбирает вариант + нажимает Enter (или клик)
        ↓
[КЛИЕНТ] СРАЗУ показывает прелоадер с выбранным вариантом
        ↓
[КЛИЕНТ] Отправляет { choice: "variant_id" }
        ↓
[СЕРВЕР] Обрабатывает выбор
        ↓
[СЕРВЕР] Возвращает execute для следующего шага
        ↓
[КЛИЕНТ] MINIMUM_LOADER_TIME = 5000ms → убрать прелоадер
```

**Требования**:
- При выборе варианта — показать прелоадер с текстом выбранного варианта
- После ответа сервера — подождать 5 секунд минимум, затем убрать

---

### Шаг 3: Отправка сообщения (LLM обработка)

```
Пользователь вводит сообщение в чате
        ↓
Нажимает Enter для отправки
        ↓
[КЛИЕНТ] СРАЗУ показывает прелоадер (сообщение уходит на long-running LLM)
        ↓
[КЛИЕНТ] Отправляет { message: "..." }
        ↓
[СЕРВЕР] Возвращает promiseId (асинхронная обработка)
        ↓
[КЛИЕНТ] Начинает polling за promiseId
        ↓
[ПОЛИНГ] Пока promise не resolved:
  - Продолжать показывать прелоадер
        ↓
[ПОЛИНГ] Promise resolved
        ↓
[КЛИЕНТ] Получает execute → убрать прелоадер
```

**Требования**:
- При отправке сообщения — **обязательно** показать прелоадер
- Если есть `promiseId` — показывать прелоадер до завершения промиса
- **Перезагрузка страницы**: если промис еще не завершен, показать прелоадер при загрузке

## Архитектура управления

### Диаграмма потока

```
┌─────────────────────────────────────────────────────────────────┐
│                         FRONTEND (JS)                           │
├─────────────────────────────────────────────────────────────────┤
│  1. Пользовательское действие (Enter / Click)                   │
│         ↓                                                        │
│  2. showLoader() — немедленно показать прелоадер               │
│         ↓                                                        │
│  3. sendToServer() — отправить запрос                           │
│         ↓                                                        │
│  4. [Ожидание ответа]                                           │
│         ↓                                                        │
│  5. MINIMUM_LOADER_TIME = 5000ms (таймер запущен)              │
│         ↓                                                        │
│  6. receiveServerResponse():                                   │
│     - Если execute → hideLoader()                               │
│     - Если promiseId → ждать resolve → hideLoader()             │
└────────────────────────────┬────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                     BACKEND (Client API / Vite Plugin)          │
├─────────────────────────────────────────────────────────────────┤
│  1. Получить запрос от клиента                                  │
│         ↓                                                        │
│  2. Обработать (роутинг / AI / etc)                             │
│         ↓                                                        │
│  3. Вернуть ответ:                                              │
│     - sync: { execute, context }                               │
│     - async: { promiseId, ... }                                 │
└─────────────────────────────────────────────────────────────────┘
```

## Минимальное время показа прелоадера

### Требование: MINIMUM_LOADER_TIME = 5000ms

```javascript
// Константа должна быть определена на клиенте
const MINIMUM_LOADER_TIME = 5000; // миллисекунд
const LOADER_MIN_END_KEY = 'loaderMinTimeEnd'; // ключ в state
```

### Логика работы

```
Таймер запускается при показе прелоадера:
    startLoader() {
        this.loaderShownAt = Date.now();
        this.loaderMinEnd = this.loaderShownAt + MINIMUM_LOADER_TIME;
    }

При получении ответа сервера:
    onServerResponse(response) {
        const now = Date.now();
        
        if (now >= this.loaderMinEnd) {
            // Минимальное время уже прошло
            // Убираем прелоадер сразу если есть execute
            if (response.execute) {
                hideLoader();
            }
        } else {
            // Минимальное время НЕ прошло
            // Планируем убрать прелоадер в нужное время
            const remaining = this.loaderMinEnd - now;
            setTimeout(() => {
                if (response.execute) {
                    hideLoader();
                }
            }, remaining);
        }
    }
```

### Исключения

- **Шаг 3 (LLM)**: Если есть `promiseId` — прелоадер показывается до resolved, независимо от 5 секунд
- **Перезагрузка страницы**: При загрузке проверить состояние promise — если pending, показать прелоадер

## Восстановление после перезагрузки страницы

### Сценарий

1. Пользователь отправил сообщение (Шаг 3)
2. `promiseId` получен, идет polling
3. Пользователь перезагружает страницу
4. При загрузке: проверить есть ли активный promise

### Реализация

```javascript
// При инициализации сессии после загрузки
async function restoreSession(sessionId) {
    // 1. Загрузить состояние сессии
    const session = await loadSession(sessionId);
    
    // 2. Проверить есть ли pending promise
    if (session.pendingPromiseId) {
        // 3. Показать прелоадер
        showLoader();
        
        // 4. Продолжить polling
        continuePolling(session.pendingPromiseId, (result) => {
            hideLoader();
            renderExecute(result.execute);
        });
    } else {
        // 5. Нет активного promise — показать обычное состояние
        renderExecute(session.execute);
    }
}
```

### API для проверки состояния

```
GET /api/a2a/sessions/{sessionId}/promise/{promiseId}

Response:
{
    "status": "processing" | "completed" | "failed",
    "execute": { ... } // если completed
}
```

## Спецификация API

### Ответ сервера должен содержать

```typescript
interface ServerResponse {
    // Существующие поля
    execute?: Execute;
    context?: Context;
    promiseId?: string;
    
    // Новые поля для управления прелоадером
    loader?: {
        // Управление прелоадером
        show: boolean;        // Показывать ли прелоадер
        message?: string;    // Опциональное сообщение
        minTime?: number;    // Минимальное время в мс (по умолчанию 5000)
    };
}
```

### Примеры ответов

**Sync ответ (Шаг 1):**
```json
{
    "execute": {
        "form": {
            "choices": [
                { "id": "code-review", "label": "Code Review" },
                { "id": "refactor", "label": "Refactoring" }
            ]
        }
    },
    "loader": {
        "show": true,
        "minTime": 5000
    }
}
```

**Async ответ (Шаг 3):**
```json
{
    "promiseId": "prom_abc123...",
    "loader": {
        "show": true
    }
}
```

**Завершение промиса:**
```json
{
    "execute": { ... },
    "loader": {
        "show": false
    }
}
```

## `execute.wait` (runtime extension)

`execute.wait` is a **runtime-only** Client API / UI hint: it is **not** part of sync golden `response.json` files (goldens model immediate `execute` or `promiseId`, not client-side delay semantics). The loader may stay visible while a `wait` step is active; see `simulations/SCHEMA.md` scope. Do not add `execute.wait` to simulation step `response.json` unless a dedicated contract test requires it.
