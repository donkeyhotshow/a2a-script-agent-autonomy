## Улучшенная формулировка
Реализовать систему управления фоновыми процессами для MCP Terminal Server, включающую:
- Чтение начального вывода при запуске в фоне с задержкой
- Новый MCP tool `background_process` для управления запущенными процессами
- Чтение логов процессов в реальном времени
- Управление процессами (остановка, завершение)

**Требования:**
- [ ] Добавить опцию `readInitialOutput` и `initialOutputDelay` в `terminal` tool
- [ ] Создать новый MCP tool `background_process` с действиями: list, status, read_log, stop, kill, cleanup
- [ ] Реализовать отслеживание фоновых процессов (метаданные, PID, статус)
- [ ] Реализовать чтение логов процессов (tail, весь лог, фильтрация)
- [ ] Реализовать управление процессами (graceful stop, kill)
- [ ] Интегрировать с существующим фоновым режимом

**Ожидаемый результат:**
Полноценная система управления фоновыми процессами с возможностью отслеживания, чтения логов и управления их жизненным циклом.

## Контекст
При запуске команд в фоновом режиме (`is_background: true`) пользователь не может получить начальный вывод процесса и управлять им после запуска. Необходимо реализовать систему управления фоновыми процессами.

## Требования

### 1. Чтение начального вывода при запуске в фоне
- [ ] Добавить опцию `readInitialOutput: true` в параметры `terminal` tool
- [ ] Добавить опцию `initialOutputDelay` (по умолчанию 2 секунды, диапазон 0.5-10 секунд)
- [ ] При запуске в фоне с `readInitialOutput: true`:
  - [ ] Ждать указанное время
  - [ ] Прочитать первый вывод процесса
  - [ ] Вернуть начальный вывод вместе с `processId`
  - [ ] Продолжить выполнение процесса в фоне

### 2. Новый MCP Tool: `background_process`
- [ ] Создать handler `handlers/background-process-handler.cjs`
- [ ] Зарегистрировать tool в `mcp-server.cjs`
- [ ] Реализовать действия:
  - [ ] `list` - получить список процессов (с фильтрацией по статусу, сессии)
  - [ ] `status` - получить статус процесса
  - [ ] `read_log` - прочитать лог процесса (tail, весь лог, фильтрация)
  - [ ] `stop` - остановить процесс gracefully (SIGTERM)
  - [ ] `kill` - принудительно завершить процесс (SIGKILL)
  - [ ] `cleanup` - очистить завершенные процессы

### 3. Отслеживание фоновых процессов
- [ ] Хранить метаданные процессов в `data/background-processes/{processId}.json`:
  - [ ] `processId` - уникальный идентификатор
  - [ ] `command` - исходная команда
  - [ ] `cwd` - рабочая директория
  - [ ] `startTime` - время запуска (ISO 8601)
  - [ ] `status` - статус (running, stopped, terminated, error)
  - [ ] `logFile` - путь к файлу лога
  - [ ] `sessionId` - идентификатор сессии MCP
  - [ ] `pid` - PID процесса
  - [ ] `timeout` - таймаут выполнения
  - [ ] `initialOutput` - начальный вывод (если был прочитан)
- [ ] Автоматически регистрировать процесс при запуске с `is_background: true`
- [ ] Создавать файл лога в `logs/background-processes/{processId}.log`

### 4. Интеграция с существующим фоновым режимом
- [ ] Обновить `CommandExecutorWrapper` для сохранения PID и создания лог-файла
- [ ] Обновить `terminal-handler.cjs` для регистрации процессов
- [ ] Возвращать `processId` в ответе при запуске в фоне

### 5. Безопасность
- [ ] Изоляция процессов по сессиям (пользователь может управлять только своими процессами)
- [ ] Валидация `processId` перед выполнением действий
- [ ] Ограничение максимального количества одновременных процессов на сессию (по умолчанию 10)
- [ ] Ограничение максимального размера лог-файла (по умолчанию 10MB)

## Технические ограничения
- Использование только Node.js API (`child_process`)
- Поддержка Windows, Linux, macOS
- Совместимость с существующей архитектурой MCP Terminal Server
