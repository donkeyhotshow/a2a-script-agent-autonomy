# 🚀 Модульный MCP Сервер

## 📋 Обзор

Модульный MCP сервер представляет собой унифицированную архитектуру, объединяющую все функциональности проекта в единую
модульную систему. Каждый модуль отвечает за определенную область функциональности и может быть независимо разработан,
протестирован и развернут.

## 🏗️ Архитектура

```
mcp/server/
├── core/
│   └── ModuleBase.cjs      # Базовый класс для модулей
├── modules/
│   ├── Terminal.cjs        # Терминальные операции
│   ├── FileOperations.cjs  # Файловые операции
│   ├── Search.cjs          # Поиск и правки
│   ├── Archive.cjs         # Архивирование
│   ├── Atomic.cjs          # Атомарные операции
│   ├── PowerShell.cjs      # PowerShell команды
│   ├── Interceptor.cjs     # Перехватчики команд
│   └── Test.cjs            # Тестирование
├── utils/                  # Утилиты
│   └── encoding-utils.cjs  # Утилиты кодирования
├── Validation.cjs          # Валидация путей и параметров
└── README.md               # Этот файл

Примечание: CoreServer.cjs отсутствует - используется mcp-server.cjs (в корне проекта) напрямую.
```

## 🔧 Модули

### 1. **Terminal** - Терминальные операции

- Выполнение команд терминала
- Управление рабочими директориями
- История команд
- Автоматическое определение ОС

### 2. **FileOperations** - Файловые операции

- Чтение, запись, копирование файлов
- Создание и удаление директорий
- Валидация путей
- Обработка ошибок

### 3. **Search** - Поиск и правки

- Поиск по файлам
- Замена текста
- Grep-подобный поиск
- Рекурсивный обход

### 4. **Archive** - Архивирование

- Создание архивов (ZIP, TAR)
- Извлечение архивов
- Просмотр содержимого
- Поиск в архивах

### 5. **Atomic** - Атомарные операции

- Предопределенные наборы операций
- Пользовательские операции
- Dry-run режим
- Откат изменений

### 6. **PowerShell** - PowerShell команды

- Выполнение PS команд
- Автоматическое исправление ошибок
- Предложения по улучшению
- Обработка кодировок

### 7. **Interceptor** - Перехватчики команд

- Автоматический перехват команд
- Оптимизация для Windows
- Проверка безопасности
- Метрики производительности

### 8. **Test** - Тестирование

- Запуск unit/integration тестов
- Покрытие кода
- Валидация модулей
- Очистка тестовых данных

## 🚀 Запуск

### Базовый запуск

```bash
node mcp-server.cjs
```

**Примечание:** Файл `mcp/server/CoreServer.cjs` не существует - используется `mcp-server.cjs` напрямую.

### С переменными окружения

```bash
LOG_LEVEL=debug node mcp-server.cjs
```

## 🔌 Создание новых модулей

### 1. Создайте файл модуля

```javascript
const { ModuleBase } = require('../core/ModuleBase.cjs');

class MyModule extends ModuleBase {
  constructor(server) {
    super(server, {
      name: 'MyModule',
      version: '1.0.0',
      description: 'Описание модуля'
    });
  }

  async processRequest(id, args) {
    // Логика обработки запросов
  }

  getTools() {
    return [{
      name: 'mytool',
      description: 'Описание инструмента',
      inputSchema: {
        type: 'object',
        properties: {
          // Схема параметров
        }
      }
    }];
  }
}

module.exports = { MyModule };
```

### 2. Зарегистрируйте модуль в CoreServer

```javascript
const { MyModule } = require('./modules/MyModule.cjs');

// В конструкторе CoreServer
this.registerModule('mymodule', new MyModule(this));
```

## 📝 Логирование

Логи сохраняются в `logs/core-server.log` с настраиваемым уровнем:

- `debug` - Детальная отладочная информация
- `info` - Общая информация о работе
- `warn` - Предупреждения
- `error` - Ошибки

## 🚨 Обработка ошибок

Все модули используют единообразную обработку ошибок:

- Автоматическое логирование
- Детальная информация об ошибке
- Контекст выполнения
- Предложения по исправлению
