# Service Management Library - Testing Documentation

## Обзор тестирования

Библиотека управления сервисами включает комплексную систему тестирования, разработанную согласно принципам когнитивной дисциплины:

### Приоритеты тестирования:
1. **Стабильность** - проверка корректной работы в разных условиях
2. **Предсказуемость** - тестирование edge cases и граничных условий  
3. **Работоспособность** - проверка основных сценариев использования
4. **Контроль** - тестирование управления жизненным циклом сервисов

## Структура тестов

```
tests/
├── setup.js                    # Настройка тестового окружения
├── basic.test.js              # Базовые тесты без внешних зависимостей
├── service-management.test.js  # Основные тесты ServiceManagementUtils
├── service-process-manager.test.js # Тесты ServiceProcessManager
├── service-config-manager.test.js  # Тесты ServiceConfigManager
├── service-logger.test.js      # Тесты ServiceLogger
├── service-status-utils.test.js # Тесты утилит статуса сервисов
├── service-cli.test.js         # Тесты CLI интерфейса
└── integration.test.js         # Интеграционные тесты
```

## Запуск тестов

### Все тесты
```bash
npm test
```

### Базовые тесты (рекомендуется для начала)
```bash
npx jest tests/basic.test.js
```

### Конкретный файл тестов
```bash
npx jest tests/service-logger.test.js
```

### Тесты с покрытием
```bash
npm run test:coverage
```

### Тесты в режиме наблюдения
```bash
npm run test:watch
```

### CI тесты
```bash
npm run test:ci
```

## Типы тестов

### 1. Базовые тесты (basic.test.js)
- **Цель**: Проверка базовой функциональности без внешних зависимостей
- **Покрытие**: ServiceLogger, ServiceConfigManager, ServiceStatusUtils
- **Особенности**: Стабильные моки, предсказуемое поведение

### 2. Unit тесты
- **ServiceLogger**: Логирование событий, ошибок, предупреждений
- **ServiceConfigManager**: Управление конфигурацией, загрузка/сохранение
- **ServiceProcessManager**: Управление процессами сервисов
- **ServiceStatusUtils**: Утилиты проверки статуса сервисов

### 3. Интеграционные тесты
- **CLI интерфейс**: Командная строка управления сервисами
- **Жизненный цикл сервисов**: Полный цикл от создания до удаления
- **Конфигурация**: Изменения конфигурации в реальном времени

## Покрытие тестами

### Основные сценарии:
- ✅ Создание и инициализация компонентов
- ✅ Управление жизненным циклом сервисов
- ✅ Обработка ошибок и исключений
- ✅ Граничные условия и edge cases
- ✅ Производительность с большим количеством сервисов
- ✅ Интеграция между компонентами

### Edge Cases:
- ✅ Очень длинные имена сервисов (1000+ символов)
- ✅ Специальные символы в идентификаторах
- ✅ Null/undefined значения
- ✅ Пустые конфигурации
- ✅ Циклические ссылки в данных
- ✅ Ошибки файловой системы
- ✅ Ошибки выполнения процессов

## Моки и заглушки

### Создание моков
```javascript
const createMockLogger = () => ({
    info: jest.fn(),
    error: jest.fn(),
    warn: jest.fn(),
    debug: jest.fn()
});
```

### Использование моков
```javascript
beforeEach(() => {
    jest.clearAllMocks();
    mockLogger = createMockLogger();
    // ... другие моки
});
```

## Рекомендации

1. **Начните с базовых тестов** - они не требуют внешних зависимостей
2. **Запускайте тесты перед коммитом** - используйте `npm run test:ci`
3. **Добавляйте тесты для новых функций** - следуйте принципам когнитивной дисциплины
4. **Тестируйте edge cases** - особенно null/undefined значения
5. **Используйте моки** - для изоляции компонентов

## Устранение неполадок

### Ошибка "Cannot find module"
- Проверьте, что все зависимости установлены
- Убедитесь, что пути к модулям корректны

### Тесты падают с таймаутами
- Увеличьте `testTimeout` в конфигурации Jest
- Проверьте, что все асинхронные операции завершаются

### Проблемы с моками
- Убедитесь, что моки создаются в `beforeEach`
- Проверьте, что `jest.clearAllMocks()` вызывается
