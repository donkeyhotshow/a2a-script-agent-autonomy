### **4. ПОЛИТИКА ЗАПУСКА НОВОГО ПРОЦЕССА**

**ПРИЧИНА:** При запуске нового процесса с тем же демоном старый процесс остается активным.

**СЛЕДСТВИЕ:**
- ✅ Kill старого процесса при запуске нового
- ✅ PowerShell Jobs для автоматического завершения дочерних процессов
- ✅ Логирование замены процессов
- ✅ Проверка PID на активность

**АЛГОРИТМ:**
1. Проверяем существующий процесс
2. Сравниваем конфигурацию
3. Если данные изменились → kill старого
4. Если данные не изменились → ставим в очередь
5. Логируем замену процесса

### **5. СИСТЕМА ОЧЕРЕДЕЙ**

**ПРИЧИНА:** Несколько копий демона пытаются запуститься одновременно.

**СЛЕДСТВИЕ:**
- ✅ Очередь ожидания при занятости демона
- ✅ Проверка позиции в очереди
- ✅ Автоматическая обработка очереди
- ✅ Логирование ожидания

**ЛОГИКА ОЧЕРЕДИ:**
```javascript
// Если демон занят
if (existingProcess && !shouldRestart) {
  return await this.queueTicket(ticket, existingProcess);
}

// Если достигнут лимит
if (runningProcesses >= maxConcurrent) {
  return await this.queueTicket(ticket);
}
```

### **6. POWERSHELL JOBS ДЛЯ АВТОМАТИЧЕСКОГО ЗАВЕРШЕНИЯ**

**ПРИЧИНА:** Дочерние процессы не завершаются при остановке демона.

**СЛЕДСТВИЕ:**
- ✅ Все процессы завершаются вместе с демоном
- ✅ Автоматическая очистка ресурсов
- ✅ Предотвращение "зомби" процессов

**РЕАЛИЗАЦИЯ:**
```powershell

# Завершение через PowerShell Job
```

## 🏗️ **АРХИТЕКТУРА СИСТЕМЫ**

### **1. TicketExecutor - Полная логика выполнения**

**КРИТИЧЕСКИЕ ФУНКЦИИ:**

#### **execute(ticket) - Основной алгоритм:**
1. **findExistingDaemonProcess()** - Поиск существующего процесса
2. **shouldRestartDaemon()** - Проверка необходимости перезапуска
3. **killExistingProcess()** - Завершение старого процесса
4. **queueTicket()** - Постановка в очередь
5. **startProcess()** - Запуск нового процесса
6. **setupProcessHandlers()** - Настройка обработчиков

#### **killExistingProcess() - Детальная логика:**
```javascript
// 1. PowerShell Jobs kill
const killCommand = `Get-Job -Name "daemon-${daemonName}" | Stop-Job -PassThru | Remove-Job`;

// 2. Проверка активности
if (await this.isProcessAlive(pid)) {
  // 3. Принудительное завершение
  const forceKill = spawn('taskkill', ['/PID', pid.toString(), '/F']);
}

// 4. Обновление PID файла
await this.updatePidFile(daemonName, { status: 'killed' });
```

#### **queueTicket() - Логика очереди:**
```javascript
const queueInfo = {
  ticket,
  addedAt: new Date(),
  reason: existingProcess ? 'daemon_busy' : 'limit_reached',
  existingProcess
};

// Логирование замены
await this.logProcessReplacement(ticket, existingProcess);
```

### **2. PidFileManager - Управление PID файлами**

**КРИТИЧЕСКИЕ ФУНКЦИИ:**

#### **initialize() - Инициализация:**
1. Создание директории
2. Создание начального файла
3. Загрузка и валидация данных
4. Проверка активности процессов

#### **validateRunningProcesses() - Валидация:**
```javascript
for (const [daemonName, daemonInfo] of Object.entries(daemons)) {
  if (daemonInfo.status === 'running' && daemonInfo.pid) {
    const isAlive = await this.isProcessAlive(daemonInfo.pid);
    
    if (!isAlive) {
      // Обновляем статус на failed
      updatedDaemons[daemonName] = {
        ...daemonInfo,
        status: 'failed',
        failedAt: new Date().toISOString(),
        reason: 'process_died'
      };
    }
  }
}
```

#### **writePidData() - Атомарная запись:**
```javascript
// Очередь записи для предотвращения конфликтов
async writePidData(data) {
  return new Promise((resolve, reject) => {
    this.writeQueue.push({ data, resolve, reject });
    this.processWriteQueue();
  });
}
```

## 🔄 **ПРИЧИННО-СЛЕДСТВЕННЫЕ ЦЕПОЧКИ**

### **Цепочка 1: Запуск нового демона**

```
1. Пользователь запускает демон
   ↓
2. TicketExecutor.execute(ticket)
   ↓
3. findExistingDaemonProcess() - Поиск существующего
   ↓
4. shouldRestartDaemon() - Проверка конфигурации
   ↓
5. Если данные изменились:
   ↓
6. killExistingProcess() - Завершение старого
   ↓
7. startProcess() - Запуск нового
   ↓
8. updatePidFile() - Обновление PID файла
   ↓
9. Логирование замены процесса
```

### **Цепочка 2: Обработка очереди**

```
1. Демон занят или достигнут лимит
   ↓
2. queueTicket() - Постановка в очередь
   ↓
3. addToQueue() - Добавление в PID файл
   ↓
4. Логирование ожидания
   ↓
5. Периодическая проверка processQueue()
   ↓
6. getNextFromQueue() - Получение следующего
   ↓
7. execute() - Запуск тикета
   ↓
8. removeFromQueue() - Удаление из очереди
```

### **Цепочка 3: Мониторинг процессов**

```
1. Периодическая проверка checkProcesses()
   ↓
2. isProcessAlive() - Проверка активности
   ↓
3. Если процесс не отвечает:
   ↓
4. updateTicketResults() - Обновление результатов
   ↓
5. Удаление из runningProcesses
   ↓
6. processQueue() - Обработка очереди
   ↓
7. Обновление статистики
```
