# Обертки для MCP сервера - Полное руководство

## Обзор

Этот документ объединяет информацию об обертках для MCP сервера: упрощенная обертка, план отказоустойчивости и архитектурное решение.

## Упрощенная обертка

### Проблема

Полнофункциональная обертка (`server-wrapper.cjs`) может быть излишне сложной и вызывать проблемы:
- Heartbeat timeout убивает сервер при отсутствии активности
- Слишком много проверок и фильтраций
- Circuit breaker может блокировать работу

### Решение

Создана упрощенная обертка `server-wrapper-simple.cjs`, которая:
- ✅ Просто проксирует stdin/stdout
- ✅ Фильтрует только JSON-RPC из stdout
- ✅ Не убивает сервер при отсутствии активности
- ✅ Минимум логики - максимум надежности

### Использование

Обновлен `.cursor/mcp.json` для использования упрощенной обертки:

```json
{
  "mcpServers": {
    "node-terminal": {
      "command": "node",
      "args": ["./server-wrapper-simple.cjs"]
    }
  }
}
```

### Преимущества

1. **Простота** - меньше кода, меньше точек отказа
2. **Надежность** - нет лишних проверок, которые могут сломать работу
3. **Совместимость** - работает с любым MCP сервером через stdio

### Что делает обертка

1. Запускает `mcp-server.cjs`
2. Проксирует stdin → child.stdin
3. Фильтрует stdout → отправляет только валидный JSON-RPC
4. Игнорирует stderr (не мешает Cursor)

## План повышения отказоустойчивости

### Цель и KPI

- **Цель:** обеспечить 100% аптайм MCP сервера node-terminal на локальных Windows машинах
- **SLO:** сервер должен восстанавливаться после сбоя ≤5 сек, watchdog фиксирует статус каждые 5 сек
- **Область:** локальный запуск в Cursor/PowerShell, без внешних интеграций

### Текущие проблемы

| ID | Симптом | Риск |
|----|---------|------|
| P1 | `Terminal tool error: safeExecute undefined` | Полная блокировка команд |
| P2 | Грязный stdout (debug после JSON) | Клиент теряет соединение |
| P3 | Зависание фоновых задач/heartbeat | Сервер «жив», но не отвечает |
| P4 | Таймаут JSON-RPC (`no result from tool`) | Пользователь получает ошибки |
| P5 | Пустые логи при старте | Сложно диагностировать сбой |

### Требования к обертке

- Watchdog внутри wrapper: ping MCP процесса каждые 5 сек
- Реакция на сбой ≤10 сек, перезапуск с экспоненциальной задержкой (1 s → 4 s → 9 s)
- Lazy-loading модулей: три фазы (core, security/handlers, расширения)
- Фильтрация stdout: wrapper принимает stdout, отделяет JSON и диагностический шум
- Логирование: `logs/wrapper-startup.log` (rolling 10 MB), события `START`, `READY`, `RETRY`, `CRASH`, `DEGRADED`

### Архитектура supervising-wrapper

#### Компоненты

1. **Launcher**: PowerShell или `npm script`, запускает wrapper
2. **Wrapper Core** (`scripts/wrapper/server-wrapper.cjs`):
   - создает child-process (`node mcp/mcp-server-entry.cjs`)
   - подписывается на stdout/stderr, фильтрует вывод
   - управляет фазами lazy-loading, публикует состояние
3. **Health Monitor**:
   - heartbeat от MCP (`process.send('heartbeat')` или спец. лог)
   - таймеры запуска, watchdog
4. **Error Controller**:
   - классификация ошибок (fatal/recoverable/degraded)
   - стратегия ретраев и circuit breaker
5. **Status CLI**:
   - `npm run mcp:status` → читает IPC/файл состояния

## Архитектурное решение (ADR)

### Вариант A: Наблюдающая обертка

**Решение:** Создать supervising wrapper, который:
- Запускает MCP сервер как child process
- Мониторит его состояние через heartbeat
- Автоматически перезапускает при сбоях
- Фильтрует stdout для чистого JSON-RPC

**Преимущества:**
- Изоляция от сбоев MCP сервера
- Автоматическое восстановление
- Чистый JSON-RPC вывод
- Гибкая конфигурация

**Недостатки:**
- Дополнительный слой абстракции
- Потенциальные проблемы с производительностью
