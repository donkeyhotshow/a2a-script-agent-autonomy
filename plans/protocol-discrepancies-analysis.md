## Изменения протокола (упрощение)

### Удалены поля:
- `version` — не нужен
- `session_id` — не нужен (сервер не хранит состояние)
- `architectural_features` — не нужен
- `continue` — не нужен (итеративный обмен)
- `confirm` — не нужен (итеративный обмен)

### Новый принцип протокола:
1. Клиент ВСЕГДА отправляет context + codeBlocks
2. Сервер обрабатывает, наполняет context, даёт указания
3. Сервер НЕ хранит ничего — context пуляет клиент при каждом запросе
4. Итеративный обмен пока сервер не вернёт `outcome: "completed"`

## Текущая структура context

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `new_task` | CONDITIONAL | Новая задача (для первого запроса) |
| `graph` | OPTIONAL | Граф знаний от предыдущей итерации |
| `request_files` | OPTIONAL | Запрошенные файлы (в ответе сервера) |

---

## Жизненный цикл сессии

```
1. Клиент: POST /requests
   → context: { new_task: [...] }
   → codeBlocks: [package.json, composer.json]
   
2. Сервер: Определяет фреймворки
   → Активирует нейроны по триггерам
   → Генерирует questions
   → Возвращает outcome: "graph_incomplete"

3. Клиент: Получает questions
   → Использует RAG.search() для поиска файлов
   → Читает найденные файлы

4. Клиент: POST /requests
   → context: { graph: {...} }
   → codeBlocks: [найденные файлы]

5. Сервер: Распознаёт сущности
   → Обновляет граф
   → Возвращает outcome: "completed" или новые questions

6. Повторять пока outcome: "completed"
```
