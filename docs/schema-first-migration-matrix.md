# Schema-First Migration Matrix

Inventory of the runtime logic that currently lives in processors/scripts and where it should land once the schema-first pipeline is the single source of truth. Each entry tags the block as “must stay” (transport/runtime only), “move to transform” (business logic belongs in the prompt transforms), or “delete after migration” (scripts that can be retired once transforms cover the behavior).

| Source | Key logic | Target transform / schema | Tag | Notes |
| --- | --- | --- | --- | --- |
| `a2a-client/vite-plugin-a2a/routes/stepRoutes.js` and `routes/handlers/step-handlers.js` | Choice vs. message normalization, result validation (`result.message` / `result.choice`), dialog history merging, context/task injection, and dialog-specific branching before calling `/api/v1/invoke`. | `prompts/transforms/dialog-request.json` (and eventual `form-choice-request.json`) | move to transform | These transformations still occur in the router before hitting the server. Once dialog/form transforms emit the same shape, the client route only needs to proxy transport metadata. |
| `a2a-client/vite-plugin-a2a/routes/utils/builders.js` (`mergeDialogHistoryForInvoke`, `mergeResponseContext`, `pickInvokeContextPatch`) | One-off helpers that massage history/context from the last step and keep `context.task` + `context.execution` in sync. | `dialog-request.json` + `dialog-response.json` (context normalization rules) | move to transform | The same logic belongs in canonical transforms so neither the Vite plugin nor future processors need to reinterpret history bits. |
| `a2a-client/vite-plugin-a2a/routes/utils/web-execute-dto.js` | Sanitizes `execute` into UI-friendly `message`/`attachments`, injects fallback copy when no form/message is present (reads/writes/commands), culls client-only action keys. | `prompts/transforms/dialog-response.json` / `form-choice-response.json` (enforce single execute key, guardrail messaging) | move to transform | Response transforms should decorate `execute.message`/`attachments` consistently instead of relying on DTO logic in the client. |
| `a2a-client/vite-plugin-a2a/routes/utils/agent-rag-chain.js` | Client-side loop that runs tool `execute` keys (rag-search, read/write-file, run-script, etc.), persists intermediate step files, and re-invokes `/api/v1/invoke`. | `prompts/transforms/agent-request.json` + `prompts/transforms/agent-response.json` (tool chains declared declaratively) | move to transform | Schema-first responses should emit “run this tool” actions explicitly; the processor should only honor that single-key contract, not hard-code rerun loops. |
| `a2a-server/src/actions/**` (`action-processor`, `action-service`, DSL definitions) | Action-scripted dialog flows with hand-written routing, step sequencing and client-script execution. | `prompts/transforms/*.json` (dialog/form/agent flows defined declaratively) | delete after migration | As soon as the transforms carry the dialog/form business rules, the old action scripts become dead weight and can be removed. |
| `a2a-server/scripts/sim-validate.ts` | Zod/AJV-heavy validation-plus-normalization that enforces golden shape rules (execute/result/context) and strips transport ids. | `docs/new-request-flow/json-schemas/*.json` + new schema-based CLI validation that runs as `npm run sim:lint`/`sim:validate` | move to transform/schema | Move the structure checks into JSON Schema assertions; keep `sim-validate.ts` as a lightweight runner that wires those schemas into `npm run sim:validate --all`. |
