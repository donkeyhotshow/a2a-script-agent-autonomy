# Закон: пути и нейроны

**Индекс:** [docs/README.md](README.md)

---

## 1. Путь к файлам не участвует в контексте

**Закон:** Путь к проектным файлам никак не участвует в контекстной обработке и зависимостях. Папка проекта — не важна. Главное — **что внутри** (содержимое).

**Следствия:**
- `project_path`, структура папок — не триггеры для нейронов
- Триггеры — по **содержимому** (FormRequest, extends Model, Inertia, .vue)
- Путь может быть `foo/bar/User.php` или `app/Models/User.php` — неважно, если внутри `extends Model`

**Текущее расхождение:** Нейроны сейчас используют path-триггеры (`app/Models/`, `app/Http/Requests/`). По закону — триггеры должны быть content-based.

---

## 2. Нейроны: только задача расшевеливает

**Принцип:** Только входящая задача может расшевелить нейроны. Нейроны управляют контекстом. Нейроны **всегда что-то делают** — не пассивны.

**Цепочка:**
1. Задача (new_task) + содержимое файлов (codeBlocks) → вход
2. Нейроны активируются по триггерам (содержимое, не пути)
3. Активированные нейроны → **действие**: inject context, request_files, подсказки
4. Нейрон без действия — мёртвый нейрон

**Нейрон обязан:**
- Иметь триггеры (по содержимому)
- При активации — делать что-то (inject, request, hint)
- Не «просто знать» — действовать

---

## 3. Парсинг → семантика → вопросы → индекс

**Поток:**
1. Парсим документ (задача + файлы)
2. Отбираем семантику (комментарии, docblocks, идентификаторы; обходим несемантику)
3. Строим вопросы — **много**
4. Вопросы → в codebase индекс (поиск ответов)

**Реализация:** `semantic-extractor.ts`, `question-builder.ts`, `index-query.ts`. Индекс — placeholder до реализации search.service.

---

## 4. Сводка

| Что | Правило |
|-----|---------|
| Пути | Не участвуют в контексте. Важно содержимое. |
| Нейроны | Активируются только задачей + содержимым. Управляют контекстом. Всегда действуют. |
| Триггеры | По содержимому (код, ключевые слова), не по путям. |
| Семантика | Парсинг → отбор семантики → много вопросов → индекс codebase |
