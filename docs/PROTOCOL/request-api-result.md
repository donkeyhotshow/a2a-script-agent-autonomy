# RequestApiResult

The RequestApiResult is the full result structure returned by the Request API, containing the outcome of processing a client request along with all necessary context for the next iteration.

## Fields

### outcome
- **Type**: `'completed' | 'graph_incomplete' | 'failed'`
- **Description**: The outcome status of the request processing
- **Values**:
  - `'completed'`: Request processing finished successfully
  - `'graph_incomplete'`: Graph analysis incomplete, more information needed from client
  - `'failed'`: Request processing failed with errors
- **Usage**: Client uses this to determine next action (continue, ask questions, handle error)
- **Service Responsibility**: Set by request processor based on processing results

### message
- **Type**: `string` (optional)
- **Description**: Human-readable message describing the outcome or providing instructions
- **Usage**: Displayed to user or used for logging/debugging
- **Service Responsibility**: Generated by request processor or error handlers

### context
- **Type**: `RequestContextBlock` (optional)
- **Description**: Context block containing all data needed for next iteration
- **Usage**: Client uses this context for subsequent requests
- **Service Responsibility**: Assembled by request processor from various services

### questions
- **Type**: `string[]` (optional)
- **Description**: Questions for client when graph_incomplete
- **Usage**: Client should ask user these questions to gather more information
- **Service Responsibility**: Generated by graph analysis services when missing data detected

### missing
- **Type**: `string[]` (optional)
- **Description**: Missing elements identified during processing
- **Usage**: Client may use this to inform user about required information
- **Service Responsibility**: Identified by validation and analysis services

### graph_stats
- **Type**: `object` (optional)
- **Description**: Graph statistics for monitoring and debugging
- **Properties**:
  - **entityCount**: `number` - Total number of entities in graph
  - **relationCount**: `number` - Total number of relations in graph
  - **entityTypes**: `Record<string, number>` - Count of entities by type
- **Usage**: Performance monitoring and graph health assessment
- **Service Responsibility**: Calculated by graph services

### activated_neuron_ids
- **Type**: `string[]` (optional)
- **Description**: IDs of neurons that were activated during processing
- **Usage**: Tracking which AI components contributed to the result
- **Service Responsibility**: Collected by neuron activation system

### injected_content
- **Type**: `string[]` (optional)
- **Description**: Content injected by activated neurons
- **Usage**: Provides additional context or instructions from AI components
- **Service Responsibility**: Generated by neuron system

### error
- **Type**: `object` (optional)
- **Description**: Error details when outcome is 'failed'
- **Properties**:
  - **code**: `string` - Error code identifier
  - **message**: `string` - Human-readable error message
- **Usage**: Client error handling and user feedback
- **Service Responsibility**: Set by error handling services

## Usage Patterns

### Successful Completion
```typescript
{
  outcome: 'completed',
  message: 'Task completed successfully',
  context: {
    tasks: [],
    architectural_features: ['typescript', 'react']
  }
}
```

### Graph Incomplete - Need More Info
```typescript
{
  outcome: 'graph_incomplete',
  message: 'Additional information required',
  questions: [
    'What is the main purpose of this application?',
    'Are there any external APIs to integrate with?'
  ],
  context: {
    request_files: ['requirements.txt', 'api-spec.yaml']
  }
}
```

### Processing Failed
```typescript
{
  outcome: 'failed',
  message: 'Unable to process request',
  error: {
    code: 'VALIDATION_ERROR',
    message: 'Invalid file format provided'
  }
}
```

## Service Responsibilities

- **Request Processor**: Sets `outcome`, `message`, assembles `context`
- **Graph Services**: Provides `graph_stats`, detects incompleteness, generates `questions`
- **Neuron System**: Supplies `activated_neuron_ids`, `injected_content`
- **Validation Services**: Identifies `missing` elements
- **Error Handlers**: Populates `error` when failures occur

## Client Response Logic

Based on `outcome`, client should:

1. **`'completed'`**: Process final results, may start new tasks
2. **`'graph_incomplete'`**: Ask user the `questions`, gather `request_files`, send new request
3. **`'failed'`**: Handle error, possibly retry or inform user

## State Management

- Context is preserved across iterations via `RequestContextBlock`
- Graph state evolves incrementally
- Error state is terminal (client must handle or retry differently)
