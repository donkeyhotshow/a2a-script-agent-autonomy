# RequestContextBlock

The RequestContextBlock is a specialized context block returned in Request API responses, containing all data needed by the client for the next iteration in the request/response cycle.

## Fields

### tasks
- **Type**: `Task[]` (optional)
- **Description**: Tasks to be performed, derived from new_task and neuron activation
- **Usage**: Client processes these tasks in subsequent requests
- **Service Responsibility**: Generated by request processor service

### request_files
- **Type**: `string[]` (optional)
- **Description**: List of file paths that the client should provide in the next request
- **Usage**: Client reads and sends these files in next ClientMessage.files
- **Service Responsibility**: Determined by request processor based on task requirements

### architectural_features
- **Type**: `string[]` (optional)
- **Description**: Architectural features detected in the project during analysis
- **Usage**: Client uses this information for context-aware operations
- **Service Responsibility**: Generated by architectural analysis services

### graph
- **Type**: `object` (optional)
- **Description**: Current graph state containing entities and relations
- **Properties**:
  - **entities**: `unknown[]` - Graph entities (nodes)
  - **relations**: `unknown[]` - Graph relationships (edges)
- **Usage**: Used for graph-based reasoning and knowledge representation
- **Service Responsibility**: Managed by graph processing services

### frameworks
- **Type**: `Record<string, unknown>` (optional)
- **Description**: Frameworks detected in the project with flexible structure
- **Usage**: Framework-specific processing and code generation
- **Service Responsibility**: Detected by framework analysis services

### new_task
- **Type**: `string[]` (optional)
- **Description**: Original task from client (preserved for reference)
- **Usage**: Maintains task context across iterations
- **Service Responsibility**: Copied from ClientMessage.context.new_task

### projectId
- **Type**: `string` (optional)
- **Description**: Project ID from client for multi-project support
- **Usage**: Scopes operations to specific project context
- **Service Responsibility**: Set by client, validated by server

### sessionId
- **Type**: `string` (optional)
- **Description**: Client session ID for tracking user sessions
- **Usage**: Session management and user-specific state
- **Service Responsibility**: Generated by client, may be sanitized by server

## Usage

RequestContextBlock is returned in RequestApiResult.context and provides the client with:

1. **Task Instructions**: What work needs to be done next
2. **Data Requirements**: Which files to provide
3. **Project Context**: Architectural features and framework information
4. **Graph State**: Current knowledge representation
5. **Session Continuity**: Maintained state across request cycles

## Client-Server Data Separation

- **Client Data**: `sessionId`, `projectId` (client-controlled identifiers)
- **Server Data**: `tasks`, `architectural_features`, `graph`, `frameworks` (server-generated)
- **Shared Data**: `request_files`, `new_task` (coordinated between client and server)

## Example

```typescript
{
  tasks: [
    {
      id: "analyze-codebase",
      type: "analyze",
      status: "pending",
      target: "src/"
    }
  ],
  request_files: ["src/main.ts", "package.json"],
  architectural_features: ["typescript", "react", "node"],
  graph: {
    entities: [{ id: "user", type: "actor" }],
    relations: [{ from: "user", to: "system", type: "uses" }]
  },
  frameworks: {
    "react": { version: "18.0.0" },
    "typescript": { version: "5.0.0" }
  },
  new_task: ["Implement user authentication"],
  projectId: "project-123",
  sessionId: "session-456"
}
```
