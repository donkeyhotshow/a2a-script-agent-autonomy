# Search Types

The search types define the structure for search queries, filters, options, and results used in the RAG (Retrieval-Augmented Generation) and code search functionality.

## SearchQuery

The main search query interface that defines what to search for and how.

### Fields

#### query
- **Type**: `string`
- **Description**: The search query string (natural language or keywords)
- **Examples**: "user authentication logic", "React component patterns", "function.*error.*handle"
- **Usage**: Primary search input from user or system
- **Service Responsibility**: Provided by client or generated by search services

#### filters
- **Type**: `SearchFilters` (optional)
- **Description**: Filters to narrow down search scope
- **Usage**: Restrict search to specific file types, directories, or frameworks
- **Service Responsibility**: Set by client based on context or user preferences

#### options
- **Type**: `SearchOptions` (optional)
- **Description**: Search execution options and parameters
- **Usage**: Control search behavior, limits, and output format
- **Service Responsibility**: Set by client or default configuration

## SearchFilters

Filters that restrict the search scope to specific criteria.

### Fields

#### file_types
- **Type**: `string[]` (optional)
- **Description**: File extensions to include in search
- **Examples**: `[".ts", ".tsx", ".js"]`, `[".md", ".txt"]`
- **Usage**: Limit search to specific file types
- **Service Responsibility**: Set by client based on project structure

#### directories
- **Type**: `string[]` (optional)
- **Description**: Directory paths to search within
- **Examples**: `["src/components", "src/services"]`, `["docs"]`
- **Usage**: Restrict search to specific directories
- **Service Responsibility**: Set by client based on project scope

#### framework
- **Type**: `string` (optional)
- **Description**: Framework-specific search context
- **Examples**: "react", "express", "vue", "angular"
- **Usage**: Apply framework-specific search patterns and filters
- **Service Responsibility**: Detected from architectural features or set by client

#### exclude
- **Type**: `string[]` (optional)
- **Description**: Patterns or paths to exclude from search
- **Examples**: `["node_modules", "*.test.*", "dist/"]`
- **Usage**: Exclude irrelevant or generated files
- **Service Responsibility**: Set by client or default exclusions

## SearchOptions

Options that control how the search is executed and what results are returned.

### Fields

#### limit
- **Type**: `number` (optional)
- **Description**: Maximum number of results to return
- **Default**: Implementation-dependent
- **Usage**: Prevent overwhelming result sets
- **Service Responsibility**: Set by client or system defaults

#### min_score
- **Type**: `number` (optional)
- **Description**: Minimum relevance score threshold (0-1)
- **Usage**: Filter out low-relevance results
- **Service Responsibility**: Set by client for quality control

#### include_context
- **Type**: `boolean` (optional)
- **Description**: Whether to include surrounding context in results
- **Default**: `false`
- **Usage**: Provide more context around matches
- **Service Responsibility**: Set by client based on detail needs

#### highlight_matches
- **Type**: `boolean` (optional)
- **Description**: Whether to highlight matching text in results
- **Default**: `false`
- **Usage**: Improve result readability
- **Service Responsibility**: Set by client for presentation preferences

## SearchResult

The result structure returned after executing a search.

### Fields

#### results
- **Type**: `SearchMatch[]`
- **Description**: Array of individual search matches
- **Usage**: Contains all matching results with metadata
- **Service Responsibility**: Generated by search engine

#### total
- **Type**: `number`
- **Description**: Total number of matches found (may exceed returned results)
- **Usage**: Pagination and result count display
- **Service Responsibility**: Calculated by search engine

#### query_time_ms
- **Type**: `number`
- **Description**: Time taken to execute the search in milliseconds
- **Usage**: Performance monitoring and optimization
- **Service Responsibility**: Measured by search service

#### algorithm_used
- **Type**: `string`
- **Description**: Identifier of the search algorithm or engine used
- **Examples**: "semantic-search", "grep", "vector-similarity", "hybrid"
- **Usage**: Debugging and algorithm selection feedback
- **Service Responsibility**: Set by search implementation

## SearchMatch

Individual search result containing match details and metadata.

### Fields

#### file
- **Type**: `string`
- **Description**: Path to the file containing the match
- **Usage**: Locate the source of the match
- **Service Responsibility**: Determined by file system analysis

#### score
- **Type**: `number`
- **Description**: Relevance score (typically 0-1, higher is better)
- **Usage**: Rank and filter results by relevance
- **Service Responsibility**: Calculated by search algorithm

#### matches
- **Type**: `MatchDetail[]`
- **Description**: Array of specific match locations and content
- **Usage**: Detailed match information with context
- **Service Responsibility**: Generated by search engine

#### metadata
- **Type**: `FileMetadata`
- **Description**: Metadata about the matched file
- **Usage**: Additional context and filtering information
- **Service Responsibility**: Extracted from file analysis

## MatchDetail

Detailed information about a specific match within a file.

### Fields

#### line_start
- **Type**: `number`
- **Description**: Starting line number of the match (1-indexed)
- **Usage**: Locate match position in file
- **Service Responsibility**: Determined by text analysis

#### line_end
- **Type**: `number`
- **Description**: Ending line number of the match (1-indexed, inclusive)
- **Usage**: Handle multi-line matches
- **Service Responsibility**: Determined by text analysis

#### content
- **Type**: `string`
- **Description**: The actual matching text content
- **Usage**: Display the matched text
- **Service Responsibility**: Extracted from file content

#### highlight
- **Type**: `string`
- **Description**: Content with matches highlighted/formatted
- **Usage**: Enhanced display with visual emphasis
- **Service Responsibility**: Generated by search engine

#### context_score
- **Type**: `number`
- **Description**: Contextual relevance score for this specific match
- **Usage**: Fine-grained ranking within a file
- **Service Responsibility**: Calculated by context analysis

## FileMetadata

Metadata associated with a file containing search matches.

### Fields

#### framework
- **Type**: `string`
- **Description**: Framework detected in the file
- **Examples**: "react", "express", "typescript", "node"
- **Usage**: Framework-specific processing and filtering
- **Service Responsibility**: Detected by framework analysis

#### type
- **Type**: `string`
- **Description**: File type classification
- **Examples**: "component", "service", "config", "documentation", "test"
- **Usage**: Categorize files for filtering and analysis
- **Service Responsibility**: Determined by file analysis

#### last_modified
- **Type**: `string`
- **Description**: ISO timestamp of last file modification
- **Usage**: Recency-based filtering and relevance
- **Service Responsibility**: Retrieved from file system

## Usage Examples

### Basic Code Search
```typescript
{
  query: "handle user authentication",
  filters: {
    file_types: [".ts", ".tsx"],
    directories: ["src/auth", "src/components"]
  },
  options: {
    limit: 10,
    include_context: true
  }
}
```

### Documentation Search
```typescript
{
  query: "API endpoints",
  filters: {
    file_types: [".md"],
    directories: ["docs"]
  },
  options: {
    min_score: 0.7,
    highlight_matches: true
  }
}
```

### Framework-Specific Search
```typescript
{
  query: "state management",
  filters: {
    framework: "react",
    exclude: ["*.test.*"]
  },
  options: {
    limit: 5,
    include_context: false
  }
}
```

## Service Responsibilities

- **Search Engine**: Executes queries, calculates scores, generates results
- **Index Manager**: Maintains search indexes for performance
- **Filter Processor**: Applies filters to narrow search scope
- **Result Formatter**: Structures and highlights results
- **Metadata Extractor**: Gathers file and framework information
- **Performance Monitor**: Tracks query execution times and optimization opportunities
