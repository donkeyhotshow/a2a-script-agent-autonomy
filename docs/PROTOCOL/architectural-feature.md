# ArchitecturalFeature

The ArchitecturalFeature interface represents architectural patterns, conventions, and framework characteristics detected in a project codebase.

## Fields

### name
- **Type**: `string`
- **Description**: Unique identifier/name for the architectural feature
- **Examples**: "typescript", "react-hooks", "express-middleware", "directory-structure-mvc"
- **Usage**: Used for feature detection, code generation, and analysis
- **Service Responsibility**: Generated by architectural analysis services

### category
- **Type**: `'directory_structure' | 'naming_convention' | 'custom_pattern' | 'framework'`
- **Description**: Category classifying the type of architectural feature
- **Values**:
  - `'directory_structure'`: Project organization patterns (MVC, feature-based, etc.)
  - `'naming_convention'`: Naming patterns (camelCase, PascalCase, kebab-case, etc.)
  - `'custom_pattern'`: Project-specific patterns or conventions
  - `'framework'`: Framework or library usage patterns
- **Usage**: Categorization for different types of architectural analysis
- **Service Responsibility**: Set by feature detection algorithms

### description
- **Type**: `string` (optional)
- **Description**: Human-readable description of the architectural feature
- **Examples**: "Uses TypeScript with strict mode enabled", "Follows MVC directory structure"
- **Usage**: Documentation and user interface display
- **Service Responsibility**: Generated by analysis services or human-defined

### path
- **Type**: `string` (optional)
- **Description**: File or directory path where this feature is detected/applied
- **Examples**: "src/components/", "tsconfig.json", "src/"
- **Usage**: Location-specific feature application
- **Service Responsibility**: Determined by file system analysis

### metadata
- **Type**: `Record<string, unknown>` (optional)
- **Description**: Additional metadata specific to the architectural feature
- **Examples**: Version information, configuration details, pattern specifics
- **Usage**: Extended feature information storage and processing
- **Service Responsibility**: Set by specialized analysis services

## Usage

ArchitecturalFeature objects are used throughout the system for:

1. **Code Generation**: Framework-specific code templates and patterns
2. **Analysis**: Understanding project structure and conventions
3. **Validation**: Ensuring code follows established patterns
4. **Recommendations**: Suggesting architectural improvements

## Service Responsibilities

### Detection Services
- **Framework Detection**: Identifies framework usage (React, Express, etc.)
- **Structure Analysis**: Detects directory organization patterns
- **Convention Analysis**: Identifies naming and coding conventions
- **Pattern Recognition**: Finds custom project-specific patterns

### Usage Services
- **Code Generators**: Use features for template selection
- **Validators**: Check code against detected patterns
- **Documentation**: Generate architecture documentation
- **Migration Tools**: Suggest refactoring based on features

## Examples

### Framework Feature
```typescript
{
  name: "react",
  category: "framework",
  description: "React framework with hooks",
  path: "src/components/",
  metadata: {
    version: "18.2.0",
    features: ["hooks", "concurrent"],
    config: { strictMode: true }
  }
}
```

### Directory Structure Feature
```typescript
{
  name: "feature-based-structure",
  category: "directory_structure",
  description: "Feature-based directory organization",
  path: "src/features/",
  metadata: {
    pattern: "features/{feature}/{type}/",
    features: ["auth", "dashboard", "settings"],
    types: ["components", "hooks", "services"]
  }
}
```

### Naming Convention Feature
```typescript
{
  name: "camelCase-components",
  category: "naming_convention",
  description: "Component files use camelCase naming",
  path: "src/components/",
  metadata: {
    pattern: "^[a-z][a-zA-Z0-9]*\\.tsx?$",
    examples: ["userProfile.tsx", "loginForm.tsx"]
  }
}
```

### Custom Pattern Feature
```typescript
{
  name: "error-boundary-wrapper",
  category: "custom_pattern",
  description: "All components wrapped with error boundaries",
  path: "src/components/",
  metadata: {
    wrapper: "ErrorBoundary",
    fallback: "ErrorFallbackComponent"
  }
}
```

## Detection and Processing

Features are detected through:

1. **Static Analysis**: Code parsing and AST analysis
2. **File System Scanning**: Directory structure and file naming patterns
3. **Configuration Files**: package.json, tsconfig.json, etc.
4. **Import Analysis**: Dependency and module usage patterns
5. **Convention Recognition**: Heuristic-based pattern detection

Features are processed by:

1. **Feature Registry**: Centralized storage and lookup
2. **Code Generators**: Template selection based on features
3. **Validators**: Pattern enforcement and checking
4. **Documentation Generators**: Architecture documentation
5. **Migration Assistants**: Refactoring suggestions

## Metadata Schema Guidelines

While metadata is flexible (`Record<string, unknown>`), common patterns include:

- **Version Info**: `{ version: "1.2.3" }`
- **Configuration**: `{ config: { strict: true } }`
- **Patterns**: `{ pattern: "^[a-z]+$", examples: ["user", "admin"] }`
- **Dependencies**: `{ requires: ["typescript", "react"] }`
- **Statistics**: `{ usageCount: 15, coverage: 0.85 }`
