# ADR-0101: Engineering the Next Generation of Autonomous Agent Orchestration: Strategic Transition to A2A 3.0 Architectures

**Статус:** Утверждено  
**Контекст:** Эволюция оркестрации автономных агентов A2A требует перехода от простых циклов (single-server, статический Gray Room, 10 итераций) к сложным, многоуровневым системам. Текущая архитектура страдает от переполнения контекста, единых точек отказа и статических наборов инструментов. Необходим переход к распределенным сессиям через P2P, адаптивному управлению контекстом (AgentSwing) и безопасному механизму самостоятельной эволюции.

## 1. Децентрализованная инфраструктура и P2P управление сессиями
Переход от централизованной модели `/api/a2a/sessions` к децентрализованной mesh-сети — самое значительное изменение в A2A 3.0.
*   **Использование libp2p**: Обеспечивает транспортные уровни (TCP, QUIC, WebSocket, WebTransport) и NAT-обход (hole punching, AutoNAT, STUN/TURN). Агенты находят друг друга через Kademlia DHT напрямую, без центрального координатора.
*   **GossipSub**: Используется для мгновенного вещания состояний агентов и обновлений задач в реальном времени.
*   **Loro CRDT**: Заменяет базу данных для обеспечения конвергентного синхронизированного состояния (Conflict-free Replicated Data Types) между пирами без блокировок.

## 2. Распределенное обучение и совместная работа
Использование алгоритмов вроде DiLoCo (Distributed Low-Communication) для коллаборативного обучения моделей на "островах" плохо связанных устройств. Внутренние оптимизации происходят локально, а синхронизация параметров (outer gradients, Nesterov momentum optimizer) происходит каждые H шагов (например, 500+).

## 3. Адаптивное управление контекстом (AgentSwing)
Замена статических стратегий на фреймворк AgentSwing, который управляет ограниченной емкостью контекста через параллельное ветвление.
*   **Эффективность (η) и Точность (ρ)**: AgentSwing анализирует эти две метрики для долгосрочных агентов.
*   **Механизм маршрутизации (Lookahead)**: При приближении к лимиту контекста AgentSwing параллельно разворачивает несколько ветвей (например, "Keep-Last-N", "Селективное резюме", "Discard-All-Except-Gold") и выбирает наиболее перспективное продолжение. Позволяет сократить число шагов навигации до 3 раз.

## 4. Ограниченная безопасностью самоэволюция и песочницы (SkillLite L3)
Внедрение надежной песочницы для ограничения агентов при модификации собственного кода, уточнении промптов и создании навыков.
*   **SkillLite Architecture**: Петля "Feedback → Reflect → Evolve → Verify" объединена с многоуровневой системой безопасности.
*   **Level 3 (L3) Security Scanning**: OS-нативная изоляция (Seatbelt для macOS, bubblewrap/seccomp для Linux) для изоляции файловой системы, сети и IPC. Применение ограничений по ресурсам (rlimits) для предотвращения неограниченного потребления CPU. 

## 5. Высококонкурентная оркестрация и Git-изоляция
По мере роста команд до 136+ агентов оркестратор должен адаптировать плагинную архитектуру для параллельной работы флотов.
*   **Git Worktree Parallelism**: Каждый агент работает в изолированном git worktree, что позволяет читать код, писать тесты и создавать PR без конфликтов.
*   **CLI-First Entry / Supervision**: Смещение точки входа к дашбордам, динамическое делегирование (CEO агент назначает навыки и рабочие процессы). CLI инструменты (npx/binary) для бесшовной интеграции разработчиков.

## 6. Model Context Protocol (MCP) как универсальный мост
Замена статического Registry v2 на MCP, стандартизирующего интеграцию агентов с внешними системами.
*   **JSON-RPC и Discovery**: Доступ к тысячам MCP-серверов без кастомного middleware (git, финансы, поиск). Унификация инструментов, ресурсов и промптов.
*   **MCP Gateway Pattern**: Унифицированная инфраструктура поиска, защиты и выполнения (через STDIO и HTTP). Выступает в роли OAuth 2.1 прокси для сложной аутентификации агентов.

## 7. Продвинутая верификация и протоколы "Truly Done"
Ввод строгого протокола поведенческих проверок, чтобы избежать ложных завершений задач с "грязным" кодом или несуществующими данными.
*   **sdd-verify Behavioral Quality Gate**: Решение считается "COMPLIANT" только при условии успешного выполнения тестов (настоящее доказательство работы, Spec Compliance Matrix). 
*   **MAS-ProVe**: Проверка промежуточных шагов агентов с использованием "LLM-as-a-Judge" для отбраковки неверных траекторий на ранних этапах.

## 8. Надежность Multi-LLM и Fallback Shim
Внедрение стратегий запасных провайдеров (gateway pattern) для защиты от 429 или 503 ошибок API.
*   **Hierarchical Failover**: Маршрутизация от OpenAI (основная) до Anthropic, Gemini или DeepSeek. Использование быстрых/дешевых моделей (Gemini Flash, DeepSeek) для легких задач (что экономит до 90% стоимости) и "heavy-duty" (GPT-5/o3) для высокоответственного планирования.
*   **Нормализация ответов**: Унификация форматов ответов и ошибок для оркестратора + circuit breakers.

## Последствия (Consequences)
Эти стратегические шаги (P2P mesh, AgentSwing, L3 Sandboxing, MCP Gateway, Behavioral Verification) трансформируют оркестратор A2A из простого "скрипта" в передовую, отказоустойчивую мультиагентную систему, обладающую безопасной само-эволюцией и высокой масштабируемостью (parallel clusters).
