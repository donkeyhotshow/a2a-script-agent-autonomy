# ADR-0060: Sight-Driven Verification (Visual QA)

- **Status:** Accepted
- **Date:** 2026-04-03
- **Author:** Alex Ribchinskiy
- **Impact:** High | **Complexity:** Medium | **Risk:** Low
- **Estimated Effort:** 3 days | **Priority:** P1
- **Deciders:** Autonomy team

---

## Context

The autonomous system generates frontend components and applications effectively,
relying on AST parsing, unit tests, and the `LoopDetector` for safety.
Visual regressions — misaligned buttons, poor text contrast, clipped text — cannot
be detected through code analysis alone.  The existing `mcp-call` action handler
gives the server a Playwright integration capable of navigating pages and capturing
screenshots.  A Vision-capable LLM at the AI Hub endpoint (`11434`) can already be
invoked via the same proxy used by `LLMJudge`.

## Decision

Implement the **Sight-Driven Verification** pattern as `VisionTester`:

1. **New service** — `a2a-server/src/services/evaluation/vision-tester.ts`.
2. **Flow**
   - Caller provides a `url` (running dev-server), the original `uiRequirement`, and
     an optional `sessionId` + `turn` counter.
   - `VisionTester` invokes the `playwright` MCP server via the existing `mcp-call`
     action handler to capture a base64 screenshot of the page.
   - The screenshot and requirement are passed to a Vision-capable LLM via the AI Hub
     `/api/generate` endpoint.
   - The LLM response is parsed into a `VisualQaResult`, which is stored as a
     `VISION_QA_RESULT` artifact.
   - When `approved === false`, the result's `critique` field can be handed back to the
     Coder agent via `ActionProcessor` for a self-correction cycle.
3. **New `ArtifactType`** — `VISION_QA_RESULT` with a 14-day TTL.
4. **Graceful degradation** — if the `playwright` MCP server is unavailable or the
   Vision LLM returns an unstructured response, `VisionTester` falls back to a
   rule-based heuristic (screenshot size check + keyword scan of page title).

## Consequences

### Pros
- Replaces 90 % of manual UX testing for components generated by the Coder agent.
- Lets the agent autonomously fix CSS/layout bugs that unit tests miss.
- Reuses existing `mcp-call` infrastructure and AI Hub proxy; no new runtime
  dependencies required.

### Cons
- Requires a Vision LLM to be registered in AI Hub (higher latency / cost per cycle).
- Orchestrating a background dev-server inside the sandbox adds operational overhead.
- `PLAYWRIGHT_MCP_SERVER` env variable must be configured for screenshot capture to
  work in production; the service degrades gracefully when it is absent.

## Implementation Notes

| Concern | Decision |
|---------|----------|
| Single-writer rule | `vision-tester` is the sole writer for `VISION_QA_RESULT` |
| AI Hub endpoint | `VISION_AI_HUB_URL` env (default: same as `AI_HUB_URL`) |
| Vision model | `VISION_MODEL` env (default: `llava`) |
| Playwright MCP | `PLAYWRIGHT_MCP_SERVER` env — JSON command array; absent ⟹ fallback |
| Approve threshold | `overall_score >= 0.70` AND no blocking issues |
