# Planning Workflow — reasoning через агента

## Концепція

Планування відбувається як діалог з агентом: агент задає уточнюючі питання блоками, отримує відповіді, потім фіксує рішення в issues. Це не waterfall — план живий і оновлюється.

## Процес

```
1. Визначити проблему або область
2. Агент задає питання блоками (по одному блоку за раз)
3. Відповіді фіксуються як рішення в issues/
4. Якщо рішення змінює інші issues — оновити їх теж
5. Після серії питань — оновити PRIORITIES.md
```

## Правила

- Одне питання = один блок (не кілька одразу)
- Якщо відповідь змінює попереднє рішення — явно зафіксувати що змінилось і чому
- Issues не видаляються — тільки оновлюється статус
- Симуляція = golden standard (ADR-0001, ADR-0020): спочатку симуляція, потім код

## Статуси issues

| Статус | Значення |
|--------|----------|
| `потребує перевірки` | Є гіпотеза, треба перевірити в коді |
| `потребує аудиту` | Треба прочитати і порівняти |
| `заплановано` | Рішення є, реалізація не почата |
| `стратегія визначена` | Підхід узгоджений, треба зробити в симуляціях |
| `потребує переробки` | Є старий варіант, треба переробити під нову стратегію |
| `в роботі` | Активна розробка |
| `КРИТИЧНО` | Блокує інші задачі, виконати першим |
| `завершено` | Реалізовано і перевірено на симуляції |

## Порядок роботи з симуляцією

```
1. Прочитати симуляцію (всі кроки)
2. Визначити які transforms потрібні
3. Перевірити чи transforms існують в prompts/transforms/
4. Написати/виправити код
5. Запустити: node a2a-server/scripts/run-simulation.ts <name>
6. Порівняти output з response.json кожного кроку
```
