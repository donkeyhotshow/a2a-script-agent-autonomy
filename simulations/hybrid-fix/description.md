# Симуляция: hybrid-fix

## Описание
Гибридное исправление - комбинация анализа ошибки, генерации патча, анализа графа зависимостей и обновления зависимостей в package.json.

## Тип экшена
`action_proposal`

## Входные данные
- action: `task_request`
- task: "исправить ошибку в модуле Order и обновить зависимости"
- options:
  - targetModule: "Order"
  - fixType: "error_and_deps"
  - includeTests: true
  - updatePackageJson: true

## Ожидаемое поведение
Сервер должен предложить гибридный экшен, который комбинирует:
1. Анализ (analyze-*) - анализ ошибки в коде
2. Генерация (generate-*) - генерация патча для исправления
3. Граф (graph-*) - анализ зависимостей и обновление связей
4. Действия по обновлению зависимостей

## Sub-actions (гибридный подход)
1. **analyze-order-error** - анализ ошибки в модуле Order
2. **graph-order-dependencies** - анализ графа зависимостей модуля
3. **check-outdated-packages** - проверка устаревших пакетов
4. **generate-order-patch** - генерация патча для исправления
5. **update-dependencies** - обновление зависимостей в package.json
6. **graph-update-links** - обновление связей в зависимых файлах
7. **verify-fix** - верификация исправления

## Особенности гибридного экшена
- Комбинирует аналитику + генерацию + граф операции
- subActions включают действия из разных категорий (analyze, generate, graph)
- Обеспечивает полный цикл: найти проблему → исправить → обновить связи → проверить
