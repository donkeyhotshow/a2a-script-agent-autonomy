# Coder Smart Simulation

## Опис

Покращений кодер: **єдиний фронт через LLM** без прив’язки до steps. Створює на клієнті MD-файл спеціального формату — повний опис задачі. Далі усі ітерації йдуть через LLM з цим документом як контекстом.

## Формат MD-файлу задачі

Файл у проекті (наприклад `.a2a/task.md` або `docs/task-context.md`):

```markdown
# 1. Запит користувача

<оригінальний текст задачі>

# 2. Уточнена формулювання

<покращене формулювання від LLM>

# 3. План аналізу

<пункти плану аналізу коду/контексту>

# 4. Чеклист на виконання

- [ ] Пункт 1
- [ ] Пункт 2
- [ ] ...
```

Після виконання пункту: `- [ ]` замінюється на `- [x]`.

## Потік

### Фаза 1: Збір даних і створення документа

1. Користувач надсилає задачу.
2. Сервер повертає action `coder-smart` (без steps — один LLM-flow).
3. Клієнт обирає `coder-smart`.
4. Сервер викликає LLM: на основі запиту згенерувати блоки 1–4 (п.1 = як є, п.2–4 = згенеровані). Відповідь LLM — вміст MD.
5. Сервер повертає `execute.write-file`: шлях у проекті + content (MD). Клієнт записує файл.

### Фаза 2: Цикл виконання чеклиста

6. Сервер повертає `execute.form` (поле message = контент документу). Клієнт підставляє в форму контент з `.a2a/task.md` і надсилає його як `result.message`.
7. Сервер надсилає в LLM: request.md з **context** (task, execution, **history**: один елемент `{ role: "user", message: "<контент task.md>" }`) та **message** = той самий контент (як у coder-dialog).
8. LLM повертає JSON: `result` (опис виконаного) та `updatedTaskDoc` (MD з позначкою `[x]`).
9. Сервер повертає клієнту: **context** (з history) + **execute.write-file** (оновлений MD). Клієнт записує файл.
10. **Повтор:** клієнт надсилає result.written; сервер знову повертає execute.form; клієнт надсилає result.message = оновлений контент task.md; LLM виконує наступний пункт. Так до завершення чеклиста.

## Правила

- Симуляції з AI **відв’язані від steps**: один action, весь сценарій керується через LLM і контекст (MD).
- Клієнт зберігає MD у файлах проекту і при кожній ітерації передає його контент як перше повідомлення після очищення history.
- Системний промпт: асистент виконує поточний пункт чеклиста, повертає результат і оновлений MD (з позначкою виконаного пункту).

## Структура файлів симуляції

```
simulations/coder-smart/
├── description.md
├── analysis.md
├── 1/ request.json, response.json
├── 2/ request.json, response.json
├── 3/ request.json, request.md, response.json, response.md   # LLM: створення task doc
├── 4/ request.json, response.json                            # клієнт підтверджує запис
├── 5/ request.json, request.md, response.json, response.md   # LLM: виконання п.1 чеклиста
├── 6/ request.json, response.json                            # оновлений MD записано, наступна ітерація
└── ...
```
