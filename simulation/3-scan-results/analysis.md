# Анализ: Результаты сканирования

## Что произошло

Клиент просканировал проект и нашёл:
- 2 файла с нарушениями PSR-4
- 2 файла без нарушений

## Нарушения

| Файл | Текущий namespace | Ожидаемый namespace |
|------|-------------------|---------------------|
| src/Domain/Services/UserService.php | App\Services | Domain\Services |
| src/Domain/Repositories/UserRepository.php | App\Repositories | Domain\Repositories |

## Проблема

Файлы в `src/Domain/` имеют namespace `App\*`, но по PSR-4 должны иметь `Domain\*`.

Но wait! В composer.json указано только `App\` → `app/`. Нет правила для `src/`!

## Вопрос

Откуда сервер узнает правильный namespace для `src/Domain/`?

## Ответ сервера

Сервер обнаружил проблему: файлы в `src/Domain/` не подпадают под известные правила PSR-4.

### Что сервер не знает

1. Есть ли правило для `src/` в composer.json (клиент мог не прислать полный composer.json)
2. Какой namespace хочет использовать разработчик для `src/Domain/`

### Варианты

1. **Domain\\** — если в composer.json есть `"Domain\\": "src/Domain/"`
2. **App\\Domain\\** — если разработчик хочет держать всё в App\
3. **Свое правило** — разработчик определяет сам

### Ключевой вывод

Даже для механических задач серверу может не хватить контекста. Нужен механизм уточнения.
