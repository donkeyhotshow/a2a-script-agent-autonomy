# Анализ: Первый запрос

## Запрос от клиента

Клиент отправляет:
- `context.new_task`: "Добавить валидацию email при регистрации"
- `codeBlocks`: package.json, composer.json

## Что система ДОЛЖНА делать (моё видение)

### Клиент:

1. **Читает манифесты** — package.json, composer.json из проекта
2. **Формирует запрос** — context + codeBlocks
3. **Отправляет на сервер**

### Сервер:

1. **Извлекает фреймворки** — из package.json/composer.json
2. **Анализирует задачу** — понимает, что речь о валидации при регистрации
3. **Определяет, какие файлы нужны** — на основе задачи и фреймворков
4. **Возвращает context с questions/request_files**

## Проблемы текущей реализации

### Проблема 1: Как сервер понимает задачу?

Текущая реализация: сервер просто парсит текст задачи, но НЕ понимает семантику.

**Что нужно:** NLP/LLM для извлечения:
- Сущность: "валидация" → нужен FormRequest или Validation rules
- Контекст: "регистрация" → Auth/RegisterController, User model
- Действие: "добавить" → модификация существующего кода

### Проблема 2: Откуда сервер знает какие файлы запрашивать?

Текущая реализация: сервер НЕ знает структуру проекта. Он может только:
- Угадывать по конвенции (Laravel → app/Http/Controllers)
- Использовать захардкоженные пути

**Что нужно:** 
- Либо клиент передаёт структуру проекта
- Либо сервер имеет доступ к файловой системе
- Либо итеративный поиск через RAG

### Проблема 3: Что делает клиент с questions?

Текущая реализация: клиент получает questions и должен найти файлы.

**Но:** клиент НЕ знает:
- Какой файл отвечает за регистрацию
- Где находится валидация
- Какие модели связаны

**Что нужно:** RAG-поиск по кодовой базе на стороне клиента.

## Вопросы для уточнения

1. Должен ли сервер иметь доступ к файловой системе проекта?
2. Или клиент должен передавать структуру проекта?
3. Как клиент находит файлы по questions?
4. Нужен ли LLM на сервере для понимания задачи?
