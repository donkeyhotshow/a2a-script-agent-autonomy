# Симуляция протокола A2A

## Цель

Понять, как должен работать протокол для механической задачи "исправить импорты".

## Структура симуляции

```
simulation/
├── 1-first-request/      # Начальный запрос + ответ сервера
├── 2-client-response/    # Клиент ищет файлы → сервер просит сканировать
├── 3-scan-results/       # Результаты сканирования → сервер задаёт вопрос
├── 4-clarification/      # Ответ на вопрос → инструкции для исправления
├── 5-completed/          # Применение исправлений → завершение
├── mechanical-tasks.md   # Описание механических задач
└── use-cases/            # Use cases системы
```

## Ключевые выводы

### 1. Разделение ответственности

| Компонент | Обязанности |
|-----------|-------------|
| **Сервер** | Анализ контекста, определение нарушений, формирование инструкций |
| **Клиент** | Сбор контекста, сканирование файлов, применение исправлений |

Сервер НИКОГДА не исправляет файлы напрямую.

### 2. Итеративность протокола

Задача не решается за один запрос:

```
Итерация 1: new_task + package.json → сервер запрашивает файлы
Итерация 2: файлы не найдены → сервер просит сканировать проект
Итерация 3: scan_results → сервер задаёт уточняющий вопрос
Итерация 4: ответ на вопрос → сервер формирует инструкции
Итерация 5: applied_fixes → completed
```

### 3. Контекст для механических задач

Даже для "исправить импорты" нужно:
- PSR-4 правила из composer.json
- Список всех PHP файлов с их namespace
- Ответы на уточняющие вопросы (если правила неполные)

### 4. Типы outcome в ответах сервера

| Outcome | Значение |
|---------|----------|
| `need_files` | Серверу нужны файлы для анализа |
| `need_project_scan` | Серверу нужно просканировать проект |
| `need_clarification` | Серверу нужно уточнение от пользователя |
| `ready_to_fix` | Сервер готов дать инструкции |
| `completed` | Задача завершена |

### 5. Вопросы сервера

Сервер может задавать вопросы:
- Выбор из вариантов (choice)
- Ввод текста (text)
- Подтверждение (confirm)

## Проблемы, выявленные в симуляции

### Проблема 1: Неполные PSR-4 правила

В composer.json было только `App\` → `app/`, но файлы были в `src/Domain/`.

**Решение:** Сервер спрашивает у пользователя, какое правило применить.

### Проблема 2: Use-инструкции в других файлах

После изменения namespace нужно обновить все use-инструкции.

**Решение:** Клиент сообщает affected_files, сервер формирует инструкции.
