# Вариант 3: Построение графа знаний

## Описание варианта

Система извлекает сущности из кода (классы, функции, модели, контроллеры) и строит связи между ними, создавая навигируемый граф знаний. Это позволяет понимать архитектуру проекта, находить зависимости и влияния изменений.

## Роль клиента

Клиентская часть отвечает за:

1. **Парсинг кода** — извлечение синтаксических структур
2. **Отправка сущностей** — передача найденных элементов на сервер
3. **Визуализация графа** — отображение связей в UI
4. **Навигация** — переход от узла графа к коду

### Пример workflow клиента

```
Пользователь: Открыть проект
    ↓
Клиент: Сканирование структуры проекта
    ↓
Клиент: Извлечение сущностей (классы, методы, переменные)
    ↓
Клиент: Отправка на сервер для построения связей
    ↓
Сервер: Создание/обновление графа знаний
    ↓
Клиент: Визуализация интерактивного графа
```

## Роль сервера

Сервер управляет графом знаний:

1. **Хранение графа** — персистентное хранение в БД
2. **Построение связей** — анализ зависимостей между сущностями
3. **Поиск по графу** — запросы к структуре проекта
4. **Анализ влияния** — что изменится при модификации узла
5. **Вопросы по коду** — генерация вопросов для заполнения пробелов

### Типы сущностей

```typescript
enum EntityType {
  // Структурные
  PROJECT = 'project',
  NAMESPACE = 'namespace',
  FILE = 'file',
  
  // Кодовые
  CLASS = 'class',
  TRAIT = 'trait',
  INTERFACE = 'interface',
  METHOD = 'method',
  FUNCTION = 'function',
  PROPERTY = 'property',
  
  // Данные
  MODEL = 'model',
  MIGRATION = 'migration',
  
  // Web
  CONTROLLER = 'controller',
  ROUTE = 'route',
  MIDDLEWARE = 'middleware',
  
  // Frontend
  COMPONENT = 'component',
  PAGE = 'page',
}
```

### Типы связей

```typescript
enum RelationType {
  // Структурные
  CONTAINS = 'contains',        // A содержит B
  IMPORTS = 'imports',          // A импортирует B
  EXTENDS = 'extends',          // A наследует B
  IMPLEMENTS = 'implements',    // A реализует B
  
  // Использование
  USES = 'uses',                // A использует B
  CALLS = 'calls',              // A вызывает B
  REFERENCES = 'references',    // A ссылается на B
  
  // Данные
  BELONGS_TO = 'belongs_to',    // A принадлежит B (Eloquent)
  HAS_MANY = 'has_many',        // A имеет много B
  HAS_ONE = 'has_one',          // A имеет один B
  
  // Web
  HANDLES = 'handles',          // Controller обрабатывает Route
  RETURNS = 'returns',          // Метод возвращает Model
}
```

## Преимущества

| Преимущество | Описание |
|--------------|----------|
| **Понимание архитектуры** | Визуальное представление структуры |
| **Анализ влияния** | Понимание последствий изменений |
| **Навигация** | Быстрый переход между связанными элементами |
| **Поиск** | Семантический поиск по структуре |
| **Документация** | Автогенерация документации из графа |
| **Onboarding** | Помощь новым разработчикам |

## Недостатки

| Недостаток | Описание |
|------------|----------|
| **Сложность парсинга** | Разные языки требуют разных парсеров |
| **Неполные данные** | Динамические связи сложно извлечь |
| **Шум** | Много тривиальных связей |
| **Актуальность** | Граф устаревает при изменении кода |

### Сложности извлечения связей

| Паттерн | Сложность | Решение |
|---------|-----------|---------|
| Прямой импорт | Низкая | AST парсинг |
| Наследование | Низкая | AST парсинг |
| DI контейнер | Средняя | Анализ конфигурации |
| `app()` / `resolve()` | Средняя | Эвристики |
| Магические методы | Высокая | Runtime анализ |
| Динамические вызовы | Высокая | Статический анализ + hints |

## Пример использования

### API запрос

```bash
POST /api/v1/requests
{
  "project_path": "/path/to/project",
  "action": "build_graph",
  "options": {
    "languages": ["php", "typescript", "vue"],
    "include_tests": false
  }
}
```

### Структура графа

```json
{
  "entities": [
    {
      "id": "user-controller",
      "type": "controller",
      "name": "UserController",
      "file": "app/Http/Controllers/UserController.php",
      "namespace": "App\\Http\\Controllers"
    },
    {
      "id": "user-model",
      "type": "model",
      "name": "User",
      "file": "app/Models/User.php",
      "namespace": "App\\Models"
    }
  ],
  "relations": [
    {
      "from": "user-controller",
      "to": "user-model",
      "type": "uses",
      "weight": 0.9,
      "evidence": ["index method", "show method"]
    }
  ]
}
```

### Запрос к графу

```bash
# Найти все использования модели
GET /api/v1/graph/user-model/usage

# Найти влияние изменения
GET /api/v1/graph/user-model/impact

# Найти путь между сущностями
GET /api/v1/graph/path?from=user-controller&to=order-model
```

### CLI

```bash
# Построить граф
npm run graph build

# Показать связи сущности
npm run graph show User --relations

# Найти влияние изменений
npm run graph impact UserController

# Экспорт в GraphViz
npm run graph export --format dot
```

## Вопросы для заполнения пробелов

Система генерирует вопросы, когда не может автоматически извлечь связь:

```json
{
  "questions": [
    {
      "id": "q1",
      "type": "relation",
      "entity": "OrderService",
      "question": "Как OrderService получает доступ к UserService?",
      "options": [
        "Dependency Injection в конструкторе",
        "Через app() / resolve()",
        "Через фасад UserService",
        "Не использует"
      ]
    }
  ]
}
```

## Метрики успеха

1. **Полнота графа** — процент реальных сущностей извлечён
2. **Точность связей** — процент правильных связей
3. **Покрытие вопросов** — процент пробелов, закрытых ответами
4. **Полезность навигации** — время поиска связанного кода
5. **Актуальность** — скорость обновления при изменениях
