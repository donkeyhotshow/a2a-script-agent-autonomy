# Plan to Fix A2A Server Startup Error

## Problem Analysis
The server log shows an `ERR_MODULE_NOT_FOUND` error when running `npm run dev:no-auth`. The script attempts to run `tsx watch src/index.ts`, but the file `a2a-server/src/index.ts` does not exist.

## Root Cause
The project uses a monorepo structure with workspaces under `packages/`. The actual server entry point is located at `packages/server/src/index.ts`, but the npm scripts in `package.json` reference a non-existent `src/index.ts` at the root level.

## Current Project Structure
- Server code: `a2a-server/packages/server/src/index.ts`
- Workspaces: All packages under `a2a-server/packages/*`
- Build output: `a2a-server/dist/` (compiled from packages)
- Scripts incorrectly reference: `src/index.ts` (missing file)

## Solution
Update the npm scripts in `a2a-server/package.json` to reference the correct entry point path.

### Changes Required
1. Update `dev` script: `"tsx watch src/index.ts"` → `"tsx watch packages/server/src/index.ts"`
2. Update `dev:local` script: `"cross-env NODE_ENV=development tsx watch src/index.ts"` → `"cross-env NODE_ENV=development tsx watch packages/server/src/index.ts"`
3. Update `dev:no-auth` script: `"cross-env SKIP_AUTH=1 tsx watch src/index.ts"` → `"cross-env SKIP_AUTH=1 tsx watch packages/server/src/index.ts"`

### Verification
After changes:
- Run `npm run dev:no-auth` should start the server successfully
- Server should listen on configured port (default 3000)
- Health check endpoint should be accessible
- No module resolution errors

### Risk Assessment
- Low risk: Only updating script paths, no code changes
- The actual server code at `packages/server/src/index.ts` is correct and functional
- Build process remains unchanged
- Alternative approaches (creating symlink or root src/index.ts) are possible but script update is cleaner

### Dependencies
- No additional dependencies required
- Existing tsx, cross-env already installed

## Implementation Steps
1. Edit `a2a-server/package.json` to update the three dev scripts
2. Test the server startup with `npm run dev:no-auth`
3. Verify server functionality and endpoints</content>
