# Plan: Normalize File Tree Structure

## Objective

Reorganize the project directory structure to complete the migration to a consistent packages-based monorepo architecture, as outlined in README.md. This will eliminate duplicate source locations (src/, kernel/src/, features/), standardize package layouts, and follow existing project patterns for maintainability.

## Current Structure Analysis

- **Multiple source roots**: `src/`, `kernel/src/`, `features/*/src/`, `packages/*/src/`
- **Inconsistent package layouts**: Some packages have `src/`, `tests/`, `docs/`, `dist/`, others are missing subdirs
- **Migration in progress**: README.md indicates moving from monolithic `src/` to independent packages
- **Target structure**: All source code in `packages/` with scoped packages (@a2a/server-\*)

## Implementation Steps

### Phase 1: Create Missing Package Directories

1. Create `packages/actions/`
2. Create `packages/core/`
3. Create `packages/daemon/`
4. Create `packages/llm/`
5. Create `packages/p2p/`
6. Create `packages/transform/`
7. Ensure each package has standard subdirs: `src/`, `tests/`, `docs/`, `dist/`

### Phase 2: Migrate Source Code

1. Move `kernel/src/` → `packages/server/src/`
2. Move `features/daemon/` → `packages/daemon/` (including src/, tests/, docs/)
3. Move `features/llm/` → `packages/llm/` (including src/, tests/, docs/)
4. Move `features/transform/` → `packages/transform/` (including src/, tests/, docs/)
5. Move `features/actions/` → `packages/actions/src/`
6. Move `src/core/` → `packages/core/src/`
7. Move `src/services/` → appropriate packages (llm/, p2p/, daemon/, actions/)
8. Move `src/protocol/` → `packages/protocol/src/` (if not already)
9. Move `src/lib/` → `packages/utils/src/`
10. Move `src/actions/` → `packages/actions/src/` and `packages/server/src/`
11. Move `src/routes/` → `packages/server/src/`
12. Move remaining `src/` files (app.ts, index.ts) → `packages/server/src/`

### Phase 3: Consolidate Tests

1. Move package-specific tests from `tests/unit/`, `tests/integration/` to respective `packages/*/tests/`
2. Keep root `tests/` for cross-package integration and e2e tests

### Phase 4: Update Configurations

1. Update `package.json` workspace references
2. Update `tsconfig.json` paths
3. Update import statements in moved files
4. Update build scripts in `scripts/`
5. Update `.gitignore` if needed

### Phase 5: Cleanup

1. Remove empty directories: `src/`, `kernel/`, `features/`
2. Update documentation references
3. Verify build and tests pass

## Risks and Considerations

- **Import path changes**: Extensive updates needed for relative imports
- **Build dependencies**: Ensure package.json dependencies are correct
- **Test coverage**: Verify all tests still run after moves
- **Documentation sync**: Update docs/ to reflect new structure

## Verification

- Run `npm run build` to ensure compilation
- Run `npm run test` to ensure tests pass
- Run `npm run lint` to check code quality
- Manual verification of key endpoints

## Rollback Plan

- Git commits per phase for easy reversion
- Backup of critical files before moves
