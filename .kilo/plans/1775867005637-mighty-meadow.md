# Plan to Fix Server Module Resolution Error

## Goal
Resolve the `ERR_MODULE_NOT_FOUND` error for '@a2a/server-utils' that prevents the A2A server from starting, allowing the server to run successfully.

## Analysis
- The error occurs because some files import from '@a2a/server-utils' without subpaths, requiring a main `index.js` in the package, but it doesn't exist.
- The `@a2a/server-utils` package uses subpath exports (e.g., './logger') in its package.json.
- Some imports are incorrect, referencing functions not in server-utils.
- Workspaces are set up correctly with symlinks in node_modules.

## Steps
1. **Fix incorrect imports in affected files**:
   - `packages/server/src/request-processor/dialog-request-processor.ts`:
     - Change `import { logger } from "@a2a/server-utils";` to `import { logger } from "@a2a/server-utils/logger.js";`
     - Change `import { tryParseJsonFromLlmText } from "@a2a/server-utils";` to `import { tryParseJsonFromLlmText } from "@a2a/server-utils/strip-markdown-json-fence.js";`
     - Change `import { resolveAiHubBaseUrl } from "@a2a/server-utils";` to `import { resolveAiHubBaseUrl } from "../../lib/ai-hub-url.js";`
     - Change `import { isAgentSchemaName, lastAssistantMessageFromContext } from "@a2a/server-utils";` to `import { isAgentSchemaName, lastAssistantMessageFromContext } from "../../lib/agent-utils.js";`
   - `packages/server/src/agent-swing.ts`:

     - Change `import { tryParseJsonFromLlmText } from "@a2a/server-utils";` to `import { tryParseJsonFromLlmText } from "@a2a/server-utils/strip-markdown-json-fence.js";`

2. **Build the server-utils package**:
   - Run `npm run build:deps` to ensure all workspace packages, including @a2a/server-utils, are compiled.

3. **Verify the server starts**:
   - Run `npm run dev` or `npm start` and check that no module resolution errors occur.

## Risks
- Import path changes might break if relative paths are incorrect; verify file locations.
- Building might fail if dependencies are missing; ensure npm install has been run.
- If new imports are added elsewhere, they may need similar fixes.

## Alternatives Considered
- Create an `index.ts` in server-utils to re-export common items, allowing base imports. Rejected because it would hide incorrect imports and complicate the package structure.
- Change all imports across the codebase to subpaths. Implemented selectively for affected files to minimize changes.
