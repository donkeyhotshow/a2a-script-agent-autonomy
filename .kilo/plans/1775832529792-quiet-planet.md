# Plan to Process Import Fix Prompts via Task Monitor

## Objective
Run the Task Monitor to process the 11 pending import fix prompts in `prompts-to-agent-mode/` directory, ensuring the autonomous AI operator workstation processes them through Client API sessions.

## Background
- Self-upgrade process: 1) Execute tasks from `tasks/` + `DEV_STATE`, 2) When empty, run Task Monitor (`npm run monitor`) to process `prompts-to-agent-mode/` via Client API sessions.
- `tasks/` directory is empty, `DEV_STATE.md` shows no pending tasks.
- There are 11 prompts in `prompts-to-agent-mode/` all related to fixing imports in various packages (a2a-client/web, execution, script-runner, rag, fs-utils, api-client, a2a-client, a2a-server-features, a2a-server-utils, a2a-server).

## Identified Prompts
- `fix-imports-web.md`: Fix imports in a2a-client/web
- `fix-imports-execution.md`: Fix imports in execution package
- `fix-imports-script-runner.md`: Fix imports in script-runner package
- `fix-imports-rag.md`: Fix imports in rag package
- `fix-imports-fs-utils.md`: Fix imports in fs-utils package
- `fix-imports-api-client.md`: Fix imports in api-client package
- `fix-imports-a2a-client.md`: Fix imports in a2a-client
- `fix-imports-a2a-server-features.md`: Fix imports in a2a-server features
- `fix-imports-a2a-server-utils.md`: Fix imports in a2a-server utils
- `fix-imports-a2a-server.md`: Fix imports in a2a-server
- Total: 11 prompts

## Prerequisites
- Ensure stack is running: ports 5173 (client), 3000 (server), 11434/11435 (hub) should be healthy.
- Run health checks as documented in `docs/SYSTEM_STARTUP.md`.

## Implementation Steps

1. **Verify Stack Health**
   - Confirm all required services are running and ports are accessible.
   - If not running, execute `start-all.bat` from repo root.

2. **Run Task Monitor**
   - Execute `npm run monitor` to start the Task Monitor daemon.
   - Monitor will process prompts from `prompts-to-agent-mode/` one by one through Client API sessions.
   - Each prompt will be processed asynchronously until completion.

3. **Monitor Progress**
   - Check Task Monitor logs and state in `task-monitor-state.json`.
   - Each successful processing will move the prompt to completed state.

4. **Verify Completion**
   - After all prompts are processed, run `npm run monitor:completed:json` to see completed sessions in `merged`.
   - Update `DEV_STATE.md` with evidence of completion.

## Expected Outcome
- All 11 import fix prompts processed successfully.
- Imports fixed across all specified packages.
- Evidence recorded in `DEV_STATE.md` and monitor logs.

## Risks
- If stack is not running, monitor will fail.
- Individual prompts may timeout or fail, requiring manual intervention.
- Import fixes may introduce new issues requiring follow-up.
