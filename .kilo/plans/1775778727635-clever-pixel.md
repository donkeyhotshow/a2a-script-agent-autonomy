# File Tree Normalization Plan

## Objective
Normalize the file tree structure in the a2a-script-agent repository by eliminating duplicates, standardizing directory organization, and ensuring consistency across sub-projects (a2a-server, a2a-client, etc.).

## Current Issues Identified
- **Duplicate files in a2a-server**: `core/` directory contains files that duplicate `kernel/src/`, with outdated relative imports vs. alias imports in `kernel/src/`.
- **Incomplete migration**: Rename scripts exist (`rename-files.js`, `rename-schema.json`) but have not been executed.
- **Structural inconsistencies**: Divergent directories between a2a-server and a2a-client, multiple config formats, and potential archive cleanup needed.
- **Documentation and shared resources**: Scattered `README.md` files and no centralized shared utilities.

## Proposed Solution
Execute a multi-phase normalization process to reorganize the codebase, remove redundancies, and align with architectural rules.

## Implementation Plan

### Phase 1: Execute Core Migration in a2a-server (High Priority)
1. **Verify rename schema completeness**:
   - Compare `a2a-server/rename-schema.json` against actual files in `a2a-server/core/`
   - Ensure all non-test files and directories are mapped (tests/ should remain separate)
   - Update schema if any files are missing

2. **Execute rename script**:
   - Navigate to `a2a-server/` directory
   - Run `node rename-files.js` to move files from `core/` to `kernel/src/`
   - Verify all files moved successfully (check console output)

3. **Cleanup**:
   - Remove empty `core/` directory after migration
   - Optionally archive or delete `rename-files.js` and `rename-schema.json` if no longer needed
   - Run linting/type checking to ensure no broken imports

### Phase 2: Standardize Directory Structures
4. **Consolidate features in a2a-server**:
   - Audit `features/` (root) vs `packages/features/`
   - If `packages/features/` is for publishing, ensure `features/` content is properly integrated
   - Consider moving shared features to `kernel/src/features/` if applicable

5. **Create shared utilities directory**:
   - Move common root-level scripts/tests to `shared/` at project root if they are reusable across a2a-server and a2a-client
   - Update imports accordingly

6. **Normalize configuration files**:
   - Standardize environment/config files (e.g., use `.env.example` consistently)
   - Audit for conflicting configurations

### Phase 3: Documentation and Cleanup
7. **Consolidate documentation**:
   - Review all `README.md` files for redundancy
   - Merge or link related docs in `docs/` subdirectories
   - Update main `README.md` with normalized structure

8. **Prune archives**:
   - Review `archive/` for obsolete content
   - Delete or move to external storage if confirmed unused

9. **Cross-project alignment**:
   - Ensure `protocol/` packages are identical between a2a-server and a2a-client
   - Audit shared types/utilities for deduplication

### Phase 4: Verification and Testing
10. **Run tests and builds**:
    - Execute test suites for a2a-server and a2a-client
    - Run build processes to ensure no broken references
    - Verify linting and type checking pass

11. **Update dependencies**:
    - Review `package.json` files for consistency
    - Update workspace configurations if shared directories were added

## Risk Assessment
- **Low Risk**: File renames are within the same repository; backups can be made via git
- **Mitigation**: Commit changes incrementally; run tests after each phase
- **Rollback**: Use git to revert if issues arise

## Success Criteria
- No duplicate files in `a2a-server/core/`
- Consistent directory structures across sub-projects
- All tests pass and builds succeed
- Reduced codebase size due to removed redundancies
- Clear, documented file tree organization
