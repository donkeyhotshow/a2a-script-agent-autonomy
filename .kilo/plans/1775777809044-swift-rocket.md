# Plan: File Tree Normalization for Readability and Modularity

## Goal
Normalize the file tree structure across all packages in the a2a-client monorepo to improve readability and modularity. This involves standardizing directory layouts, moving loose files into appropriate subdirectories, and ensuring consistent organization.

## Standard Package Structure
Each package should follow this structure:
- `src/` : All source code files (TypeScript, JavaScript, etc.)
- `tests/` : Test files and test data
- `docs/` : Documentation files (README.md can stay at root)
- `scripts/` : Build or utility scripts (if needed)
- `package.json`, `README.md`, `tsconfig.json`, `vitest.config.ts` : Config files at root
- Asset directories (e.g., `css/`, `templates/`) : Keep as-is if specific to the package's purpose
- No loose source files at root
- No `node_modules/` in individual packages (monorepo should manage dependencies centrally)

## Implementation Steps
1. For each package, create the necessary directories if missing
2. Move files as listed above
3. Update all import statements in moved files and dependent files
4. Update `package.json` exports/imports accordingly
5. Run tests and linting to ensure no broken references
6. Update documentation if needed

## Potential Challenges
- Updating imports across the monorepo may require careful grep and replace
- Some moved files may have relative imports that need adjustment
- Ensure TypeScript paths and module resolution still work

## Benefits
- Consistent navigation and understanding of package contents
- Better separation of concerns (source, tests, docs)
- Easier maintenance and onboarding for new developers
- Improved modularity by clearly defining package boundaries
