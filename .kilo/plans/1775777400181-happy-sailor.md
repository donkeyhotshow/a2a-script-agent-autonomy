# Plan: Normalization of File Tree Structure

## Current State Analysis
The project is organized as a monorepo with multiple components at the root level:
- **a2a-server**: TypeScript backend with features/, kernel/, tests/, docs/, scripts/, etc. (28 entries)
- **a2a-client**: JavaScript client with packages/ (12 workspaces), core/, kernel/, tests/, docs/, scripts/ (21 entries)
- **a2a-ai-hub**: Python AI hub with config/, daemon/, tests/, docs/, scripts/ (40 entries)
- **a2a-orchestrator**: Orchestrator component with actions/, orchestrator/, runbook/, skills/, utils/ (5 entries)
- **Root-level dirs**: tests/ (integration tests), tools/ (runbook scripts), docs/, archive/, .kilo/, .cursor/ (IDE artifacts)

Issues for balance and organization:
- Inconsistent sub-directory structure across components (e.g., a2a-orchestrator lacks docs/, tests/)
- Scattered tests: unit tests in each component, integration tests at root
- Temporary/IDE files (.cursor/, package.json.new) cluttering the structure
- tools/ at root may belong in scripts/ within components
- .git worktrees and .cursor dirs may not be needed in main repo

## Proposed Normalization
To achieve balanced organization:
1. **Standardize component structure**: Ensure each main component (a2a-server, a2a-client, a2a-ai-hub, a2a-orchestrator) has consistent subdirs: src/, tests/, docs/, scripts/, config/
2. **Consolidate tests**: Move root tests/ to tests/integration/, keep unit tests in components
3. **Organize scripts**: Move tools/runbook/ to a top-level scripts/, or distribute to component scripts/
4. **Clean up artifacts**: Remove .cursor/ dirs and temp files like package.json.new
5. **Group components**: Optionally move main components under apps/ for clearer hierarchy (but may break existing scripts)

## Implementation Steps
1. Add missing subdirs to components (e.g., create docs/, tests/ in a2a-orchestrator)
2. Move and rename directories as needed
3. Update any references in scripts/configs to new paths
4. Remove unnecessary files/dirs
5. Test that start scripts still work

## Risks and Considerations
- Moving dirs may break relative imports or scripts expecting current paths
- Ensure git history is preserved for moved files
- Balance depth: avoid too deep nesting if not necessary</content>
