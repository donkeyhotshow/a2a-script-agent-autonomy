# Plan: Debug All Services Sequentially

## Objective
Debug all services in the a2a-script-agent project one by one. Attempt to start each service, check for startup errors, and review logs for any issues. Document findings and stop each service after checking.

## Identified Services
Based on project structure and scripts:
1. **a2a-ai-hub** (AI integration/proxy service, Python)
2. **a2a-server** (Backend server, Node.js/TypeScript)
3. **a2a-client packages** (Client-side packages including SDK and Web UI, JavaScript)
4. **a2a-orchestrator** (Central orchestrator, Node.js)
5. **Task Monitor** (Monitor service for processing tasks, Node.js)

## Prerequisites
- Ensure no services are running (run kill-all.sh or equivalent if needed)
- Verify ports are free: 11434 (ai-hub), 3000 (server), 3001 (client-api), 5173 (web-ui)
- Check environment variables and configs are set (e.g., .env files)

## Debugging Steps

### Step 1: Debug a2a-ai-hub
- Change to `a2a-ai-hub` directory
- Run start command: `python -m proxy` (based on pyproject.toml script)
- Wait 10-15 seconds for startup
- Check if port 11434 is listening
- Check logs in `a2a-ai-hub/proxy_logs/` or console output for errors
- If errors found, document them in findings
- Stop the service (kill process)
- Move to next service

### Step 2: Debug a2a-server
- Change to `a2a-server` directory
- Run `npm run dev` (development mode)
- Wait 10-15 seconds for startup
- Check if port 3000 is listening
- Check logs in `a2a-server/logs/` or console for winston logs
- Perform health check: curl http://localhost:3000/health
- If errors, document
- Stop the service
- Move to next

### Step 3: Debug a2a-client (SDK/API)
- Change to `a2a-client/packages/sdk` directory
- Run `npm run dev`
- Wait 10-15 seconds
- Check if port 3001 is listening
- Check logs in console or any log files
- If errors, document
- Stop the service
- Move to next

### Step 4: Debug a2a-client (Web UI)
- Change to `a2a-client` directory
- Run `npm run dev`
- Wait 10-15 seconds
- Check if port 5173 is listening
- Check logs in console
- If errors, document
- Stop the service
- Move to next

### Step 5: Debug a2a-orchestrator
- From root directory
- Run `npm run central`
- Wait for execution (may run offline validations)
- Check console output for errors
- If errors, document
- (This may not run as a daemon, so check completion)

### Step 6: Debug Task Monitor
- From root directory
- Run `npm run monitor:once` (one-time run to check)
- Check console output and any log files for errors
- If errors, document

## Post-Debugging
- Compile all findings into a summary
- Identify any common issues or dependencies
- Suggest fixes if possible
- Run full stack test if all services start without errors

## Potential Issues to Watch For
- Missing environment variables
- Port conflicts
- Missing dependencies
- Configuration errors
- Network connectivity issues
- Database/storage issues

## Tools Needed
- bash for running commands
- curl for health checks
- Process monitoring (ps, lsof, or similar)
- Log file readers
