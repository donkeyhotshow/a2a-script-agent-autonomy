# File Tree Normalization Plan

## Goal
Normalize the repository's file tree for consistency, maintainability, and adherence to standard project structures. This involves standardizing directory names, relocating misplaced files, consolidating documentation and tests, and removing temporary/unnecessary files.

## Current Structure Analysis
- **a2a-ai-hub**: Python project with `proxy/` (main source), `simulation/`, `scripts/`, `docs/`, `config/`, `tests/`. Root contains test files, logs, .pytest_cache.
- **a2a-client**: Node.js monorepo with `kernel/` (main app), `packages/` (SDKs), `core/`, `scripts/`, `tests/`, `docs/`.
- **a2a-orchestrator**: Minimal structure with `actions/`, `orchestrator/`, `skills/`, `utils/`. No README.
- **a2a-server**: Node.js with `packages/`, `src/`, `config/`, `scripts/`, `tests/`, `docs/`, `features/`, `kernel/`, `shared/`, `storage/`.
- **Root**: Mixed docs, tests, scripts, archive. Has `.kilo/`, `.kilocode/` for tooling.

## Proposed Normalized Structure
Adopt a consistent structure for each component:
- `src/` - Main source code
- `packages/` - Published packages (for monorepos)
- `config/` - Configuration files
- `scripts/` - Utility scripts
- `tests/` - Unit/integration tests
- `docs/` - Component-specific documentation
- Root-level: Global docs in `docs/`, global tests in `tests/`, global scripts in `scripts/`

## Implementation Steps

### 1. Standardize a2a-ai-hub Structure
- Rename `proxy/` to `src/`
- Move `simulation/` into `src/simulation/`
- Move config files to `config/` (already there)
- Move `scripts/` to `src/scripts/` or keep as is if utilities
- Move component docs to `docs/` (already there)
- Remove root-level test files (e.g., `test_*.py`) to `tests/`
- Remove `.pytest_cache/`, `logs/`, `proxy_logs/` (temporary)

### 2. Standardize a2a-client Structure
- Rename `kernel/` to `src/` (main app)
- Keep `packages/` as is (standard monorepo)
- Move `core/` into `packages/core/` if not already
- Ensure `scripts/`, `tests/`, `docs/` are clean

### 3. Standardize a2a-orchestrator Structure
- Create `src/` and move `actions/`, `orchestrator/`, `skills/`, `utils/` into it
- Add README.md describing the component
- Add `config/`, `scripts/`, `tests/`, `docs/` if needed

### 4. Standardize a2a-server Structure
- Complete migration to `packages/` structure
- Move remaining `src/` content to appropriate `packages/`
- Remove old `src/` after migration
- Ensure `config/`, `scripts/`, `tests/`, `docs/` are consistent

### 5. Consolidate Root-Level Items
- Move component-specific docs from `docs/` subdirs to component `docs/`
- Move integration tests from root `tests/` to appropriate component `tests/`
- Clean `archive/` - ensure archived items are properly organized
- Remove any temporary files/logs from root

### 6. Update References
- Search and update import paths in code after renames
- Update documentation links
- Update build scripts/package.json paths
- Update CI/CD configurations

### 7. Clean Up Temporary Files
- Remove `.pytest_cache/`, `node_modules/` (regenerate), `dist/`, logs, test outputs
- Ensure `.gitignore` covers temporary files

### 8. Verify and Test
- Run builds/tests after changes
- Ensure start-all.bat works
- Update AGENTS.md if needed

## Risks and Considerations
- Path changes may break imports - thorough search required
- Build processes may need updates
- Documentation links may break
- Test for each component independently

## Success Criteria
- Consistent directory structure across components
- No misplaced files
- All builds and tests pass
- Documentation remains accessible
- Repository easier to navigate and maintain
