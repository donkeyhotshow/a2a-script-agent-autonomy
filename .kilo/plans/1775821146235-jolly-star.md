# Plan: Fix runbook-cli.js issues - COMPLETED

## Problems Resolved
1. **Import Error**: `node scripts/runbook-cli.js start` fails with module not found error for port-manager.js ✅ FIXED
2. **Console Hanging**: Script doesn't release console control after starting services ✅ FIXED

## Root Cause Analysis
1. **Missing File**: `scripts/port-manager.js` doesn't exist despite being imported and referenced in ADR-0032
2. **Wrong Import Path**: Import uses `'./scripts/port-manager.js'` instead of `'./port-manager.js'`
3. **Synchronous Waiting**: `startCommand` uses `await` on `startService` which waits for health checks, keeping the process alive

## Solution Implemented
1. ✅ Created `scripts/port-manager.js` with port reservation/release functions
2. ✅ Fixed import path in `scripts/runbook-cli.js`
3. ✅ Created `startServiceCli()` function that starts services asynchronously without health check waiting
4. ✅ Modified CLI `start` command to use `startServiceCli()` instead of `startService()`
5. ✅ Ensured background processes are properly spawned with `detached: true` and `child.unref()`
6. ✅ Tested that CLI exits quickly after starting services

## Implementation Details
- **Port Manager**: Uses lock files in `~/.a2a/port-locks/` for port reservation with cleanup of stale locks
- **Async Start**: CLI mode now starts services and exits immediately without waiting for health checks
- **Background Processes**: Services start as detached background processes using `detached: true` and `child.unref()`
- **Console Release**: CLI exits immediately after initiating service starts, as requested
