# Plan to Fix Imports in a2a-client

## Goals
- Resolve all import errors and inconsistencies in the a2a-client codebase
- Ensure all packages use consistent naming conventions
- Fix incorrect relative import paths
- Make the monorepo import structure reliable and maintainable

## Current Issues Identified
1. **Inconsistent Package Naming**: Packages are named `@a2a/shared`, `@a2a/core`, etc., but imports and root dependencies use `@a2a-client/shared`, `@a2a-client/core`, etc.
2. **Incorrect Relative Paths**: Some imports use `../@a2a-client/storage/...` which are invalid paths (treat @a2a-client as directory)
3. **Extension Mismatches**: Some exports use `.ts` but imports use `.js`
4. **Missing Dependencies**: Some packages may depend on renamed packages

## Analysis Performed
- Scanned all import statements (884 total)
- Reviewed package.json files for all packages (shared, core, storage, vite-plugin, execution)
- Identified 45 instances of `@a2a-client/` imports that need verification
- Found relative paths using `@a2a-client` in paths

## Proposed Solution
1. **Rename Package Names**: Change all package names from `@a2a/*` to `@a2a-client/*` to match the root naming convention
2. **Update Dependencies**: Update all inter-package dependencies to use the new names
3. **Fix Relative Paths**: Replace invalid relative paths like `../@a2a-client/storage/...` with proper package imports `@a2a-client/storage/src/...`
4. **Standardize Extensions**: Ensure import paths match export paths (e.g., .ts vs .js)

## Steps to Implement

### Phase 1: Rename Packages
1. Update `packages/shared/package.json` name to `@a2a-client/shared`
2. Update `packages/core/package.json` name to `@a2a-client/core`
3. Update `packages/storage/package.json` name to `@a2a-client/storage`
4. Update `packages/execution/package.json` name to `@a2a-client/execution`
5. Update `packages/vite-plugin/package.json` name to `@a2a-client/vite-plugin`
6. Update any other packages' names to `@a2a-client/*`

### Phase 2: Update Dependencies
1. In `packages/vite-plugin/package.json`, change dependencies:
   - `@a2a/core` → `@a2a-client/core`
   - `@a2a/storage` → `@a2a-client/storage`
   - `@a2a/execution` → `@a2a-client/execution`
2. Update root `package.json` dependency if needed (already `@a2a-client/vite-plugin`)

### Phase 3: Fix Import Statements
1. Replace all `@a2a/shared/...` with `@a2a-client/shared/...`
2. Replace all `@a2a/core/...` with `@a2a-client/core/...`
3. Replace all `@a2a/storage/...` with `@a2a-client/storage/...`
4. Replace all `@a2a/execution/...` with `@a2a-client/execution/...`
5. Fix relative paths:
   - `../@a2a-client/storage/promise-status.js` → `@a2a-client/storage/src/promise-status.ts`
   - `../@a2a-client/storage/newSessions.js` → `@a2a-client/storage/src/newSessions.ts`
   - Similar fixes for other invalid relative paths

### Phase 4: Verify Exports
1. Ensure all exports in package.json match the actual file extensions and paths
2. Update any .ts to .js or vice versa as needed for module resolution

### Phase 5: Testing and Validation
1. Run `npm install` to update lockfile
2. Run linting: `npm run lint`
3. Run type checking: `npm run type-check`
4. Run tests: `npm test`
5. Verify no import errors in build: `npm run build`

## Risks and Considerations
- **Breaking Changes**: Renaming packages may break external dependencies or scripts
- **Build Process**: Ensure TypeScript compilation generates correct .js/.d.ts files
- **Workspaces**: Verify npm workspaces resolve correctly after renames
- **Version Consistency**: All packages should have consistent versioning

## Questions for User
- Is the naming convention `@a2a-client/*` preferred over `@a2a/*`? 
- Are there any external consumers of these packages that would be affected?
- Should we standardize on .js extensions in imports even for .ts files?
