# Plan: Apply Import Fixing Action to Each Folder in Isolation

## Overview
Apply the `fix-imports-generic` action (defined in `a2a-server/packages/features/src/actions/definitions/yaml/actions/fix-imports-generic.yaml`) to each major folder/directory in the project in isolation. This ensures that import fixes are applied independently without cross-folder dependencies affecting the process.

## Identified Folders to Process
Based on project structure analysis, the following directories contain source code that may have import issues and should be processed in isolation:

### Server-side folders:
- `a2a-server/` - Main server code
- `a2a-server/packages/utils/` - Utility packages
- `a2a-server/packages/features/` - Feature modules

### Client-side folders:
- `a2a-client/` - Client root (may have shared configs)
- `a2a-client/packages/api-client/` - API client package
- `a2a-client/packages/fs-utils/` - File system utilities
- `a2a-client/packages/rag/` - RAG functionality
- `a2a-client/packages/script-runner/` - Script execution
- `a2a-client/packages/execution/` - Execution engine
- `a2a-client/web/` - Web UI components

## Action Configuration
For each folder, run `fix-imports-generic` with:
- `rootDir`: Set to the specific folder path
- `dryRun`: false (apply actual fixes)
- Context includes TypeScript/JavaScript/Vue support

## Execution Strategy
1. **Sequential Processing**: Process one folder at a time to avoid conflicts and ensure isolation
2. **Evidence Recording**: Each run must record runtime evidence (test execution, file changes, etc.)
3. **Verification**: After each folder, run lint/typecheck to ensure fixes are correct
4. **Async Processing**: Use the Task Monitor system to process each folder as a separate async task

## Steps

### 1. Prepare Task Prompts
Create individual prompt files in `prompts-to-agent-mode/` for each folder:
- `fix-imports-a2a-server.md`
- `fix-imports-a2a-server-utils.md`
- `fix-imports-a2a-server-features.md`
- `fix-imports-a2a-client.md`
- `fix-imports-api-client.md`
- `fix-imports-fs-utils.md`
- `fix-imports-rag.md`
- `fix-imports-script-runner.md`
- `fix-imports-execution.md`
- `fix-imports-web.md`

Each prompt should specify:
```
task: fix imports in [folder-name]
context:
  rootDir: [absolute-path-to-folder]
  mode: agent
```

### 2. Run Task Monitor
Execute `npm run monitor` to process all prompts sequentially through the Client API.

### 3. Monitor and Verify
- Check DEV_STATE for evidence of each action completion
- Run `npm run lint` or equivalent after each folder processing
- Verify no regressions in other folders

### 4. Handle Failures
If any folder fails:
- Review error logs in session data
- Adjust action parameters or create manual fixes
- Re-run the specific folder's task

## Risk Assessment
- **Cross-folder imports**: Since processing is isolated, relative imports pointing outside the folder may break temporarily
- **Shared dependencies**: npm packages should remain unaffected
- **Build system**: Ensure the project can still build after each folder fix

## Success Criteria
- All folders processed without errors
- Import statements are valid and resolvable
- TypeScript compilation passes
- No new linting errors introduced
- DEV_STATE contains evidence for each folder's processing

## Alternative Approach
If the async Task Monitor approach is complex, create a batch script that:
1. Lists all target directories
2. For each directory, runs the action with appropriate context
3. Collects results and reports

## Dependencies
- `fix-imports-generic` action must be available in the action registry
- Task Monitor (`npm run monitor`) must be functional
- Client API must support the action execution
