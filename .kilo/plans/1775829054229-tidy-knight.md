# Plan to Fix Imports on Server

## Problem
The a2a-server uses TypeScript with NodeNext module resolution ("module": "NodeNext" in tsconfig.json), which requires .js extensions in import statements for local files, even when the source files are .ts. This is because TypeScript compiles .ts to .js, and Node.js ESM requires the .js extension.

Current code has incorrect imports like:
- `import { config } from "../../config/index.ts";` (should be .js)
- Some imports may lack extensions entirely for local files.

External packages (like 'express') and workspace packages (@a2a/server-utils) correctly use their published extensions.

## Analysis
- tsconfig.json confirms NodeNext module resolution
- package.json has "type": "module" for ESM
- Grep search found 770+ import statements in .ts files
- Many imports already correctly use .js for local files
- Some incorrectly use .ts extension
- Few imports lack extensions (need to check if they point to .ts files)

## Steps to Fix
1. **Search for problematic imports**: Use grep to find all import statements in a2a-server .ts files that use .ts extension or lack extension for local paths.

2. **Replace .ts with .js**: For all imports ending with .ts, replace .ts with .js in the import path.

3. **Add .js to extensionless local imports**: For imports without extension that point to local .ts files, append .js.

4. **Verify changes**: Run `npm run build` to ensure TypeScript compilation succeeds and no import errors.

5. **Test**: Run lint and tests to confirm functionality.

## Implementation Approach
- Use global find-and-replace with sed or similar tool to change .ts to .js in import lines
- For extensionless imports, manually review or use a script to resolve paths and add .js if target is .ts
- Focus on relative paths (./ ../) and path aliases (@/) - external imports should remain unchanged

## Risks
- Over-replacement: Ensure only import paths are changed, not other .ts references (e.g., in comments or strings)
- Missing extensions: If an import lacks extension and target is not .ts, it might be external or error
- Path resolution: NodeNext requires correct relative paths with .js

## Expected Outcome
All local imports in a2a-server .ts files will use .js extensions, compatible with NodeNext and ESM.
