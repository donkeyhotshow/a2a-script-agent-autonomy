# Duplicate Code Detection and Remediation Plan

## Goal
Create automated scripts to identify full duplicates (identical files) and assist with manual code duplication detection across the a2a-script-agent codebase.

## Current State Analysis
From the provided analysis documents, there are ~120+ duplicate files by name across the codebase with the following patterns:
- Actions package triple nesting (~20 files)
- Gray-room parallel duplication (~15 files)  
- Utilities lib/ vs root duplication (~15 files)
- Request service triplication (4 files)
- API registry migration duplicates (3 files)
- Memory package nested structure (3 files)
- Type definitions scattered (10+ locations)

## Plan Phases

### Phase 1: Full Duplicate Detection Script
**Goal:** Create automated script to find 100% identical files

**Steps:**
1. **File Hash Comparison Script**
   - Use SHA256/MD5 to generate file hashes
   - Group files by content hash to find identical copies
   - Exclude generated files (dist/, node_modules/, *.d.ts)
   - Output grouped duplicates with file paths and sizes

2. **Duplicate Size Analysis**
   - Calculate total lines of duplicated code
   - Identify largest duplicate files for priority handling
   - Generate consolidation impact report

3. **Script Output Format**
   - JSON format for programmatic processing
   - CSV format for manual review
   - HTML report with clickable file links

### Phase 2: Manual Code Duplication Detection
**Goal:** Identify similar but not identical code patterns

**Steps:**
1. **AST-Based Similarity Analysis**
   - Parse TypeScript files into AST
   - Compare function signatures and structures
   - Identify code clones with configurable similarity threshold

2. **Token-Based Duplication Detection**
   - Use tools like PMD CPD or jscpd for token-based analysis
   - Configure for TypeScript/JavaScript
   - Exclude test files and generated code

3. **Semantic Duplication Patterns**
   - Detect repeated utility functions
   - Find similar error handling patterns
   - Identify duplicated validation logic

### Phase 3: Remediation Assistance Scripts
**Goal:** Automate safe consolidation operations

**Steps:**
1. **Import Path Analysis Script**
   - Map all import statements referencing duplicate files
   - Generate migration suggestions for import paths
   - Detect circular dependencies

2. **Safe Consolidation Script**
   - Backup original files before consolidation
   - Update imports automatically where safe
   - Flag manual review cases (different implementations)

3. **Verification Scripts**
   - Post-consolidation build verification
   - Import resolution checking
   - Test suite integrity validation

## Technical Requirements

### Tools and Dependencies
- Node.js script for file system operations
- TypeScript compiler API for AST analysis
- File hashing libraries (crypto, fs)
- Path resolution utilities
- CSV/JSON output libraries

## Risk Assessment

### High Risk Areas
- Actions package consolidation (affects core functionality)
- Import path updates (could break module resolution)
- Type definition consolidation (affects type safety)

### Mitigation Strategies
- Comprehensive backup before any changes
- Phased rollout with verification at each step
- Ability to rollback changes automatically
- Detailed logging of all operations

## Success Criteria
- 100% identical duplicates identified and catalogued
- Similarity analysis covers all source files
- Automated import migration covers 80%+ of cases
- Verification scripts catch 100% of breaking changes
- Consolidation preserves all functionality
